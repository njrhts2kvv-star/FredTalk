# FredTalk 2.0 · 2026-10-13

FredTalk 2.0 把组件检索、逐段选择、整期编排和渲染连成了一套能实际执行、能核验的制作流程。升级的重点，是让 Codex 找到合适的组件，再把它们按本期内容接成一条完整视频。

## 1. 用平常的说法，也能找到组件

修复了组件查询在语义匹配之前就把候选过滤掉的问题。现在可以直接说“数据增长”“两个工具价格对比”“三个要点列表”“代码终端”，也可以用完整口播句来查。用途、对象、动作和常见同义说法都参与匹配，结果会带上命中理由；制作检索与视觉库使用同一份登记数据。

## 2. 新组件有机会进入候选

相关度相同的候选，按来源批次轮流排；按用途浏览、没有查询词时，也会打散批次顺序。旧批次不会再因为登记得早，就把后面的候选位置全占满。每个批次内部仍保留原顺序，准确编号和历史记录可以继续追溯。

## 3. 每一段都要认真挑，前三名必须讲清楚

先写这一段画面里看得见的对象和动作，再查候选、看准确样片。当前排名前三的组件，无论采用还是不采用，都必须写具体理由。建议门禁会重新计算前三名，漏比较就不能交付；改了查询词，也要按新的结果重新比较。

候选不合适，就换一种说法继续查，或明确指出库里缺什么表达。不能跳过这一步，直接写一个通用大字页。选中的组件还要绑定真实源码、本期调用和实际输出，参考编号本身不算完成复用。

## 4. 整期视频有了完整的编排和自检规则

从真实录音和字幕出发，用口播 cue 触发动作；录屏要推到正在讲的位置，演出点击、输入、复制和结果。段与段之间先定交接表，共享对象的位置、尺寸和末态，让观众正在看的东西连续变化。讲解结构类组件默认全片只出现一次，播放外壳、字幕、角标和同一对象的延续按各自职责处理。

渲染之前用 motion_audit.py 检查定格、慢推、单次运动过长和纯滚动过长。阻止级问题必须改掉，或结合真实内容写明豁免理由；关键帧与实际接缝也要看过。

声音按整期安排：收线、滚动、叮和提示这几种跳跃感明显的音效，每期各只保留 1–2 次，其他调用默认换成更轻的刷、弹出或点击。BGM 从头铺到尾；当观众需要欣赏插入作品的对白、音乐与音效时，在准确区间让位，音乐时钟继续。仅复用固定纯配音作讲解时，BGM 正常持续。

整期渲染也整理进工程骨架：大素材上传断开后保留未完成部分并重试续传；画面分块渲染，单块超时或失败自动重试一次；画面和完整音轨分别处理，最后只混一次。混音加入峰值保护，实际 AAC 编码后复测，超过目标时有限次调整并重测，通过后才交付。

## 还有这些升级

- 固定 component-kit：字体、颜色、阴影、缓动、光标、字幕、角标和音效统一取值，新增 Spotlight 局部聚焦、真实口播 cue 与交接工具。制作流程带 kit 指纹检查、长短文案自查和核心帧检查。
- 场景按本期内容重写：可以拆用已认可组件的动作与对象关系，删掉独立开场和收尾，再组合成一段连续动作。公共组件原版保留，本期适配版负责本期内容；新公共组件仍按实际认可入库。
- 逐段审看继续沿用上一版的判断和制作方向，旧文字、旧图片保留在“往期意见”，当前意见框清空。沿用记录标明来源，不把上一版选择当作对新画面的批准。
- 视觉库的新组件前置并标 NEW；已归档组件放到归档区，退出默认制作候选，保留原素材、源码、编号和历史意见。


本次 GitHub 增加 **106 条组件**：新闻关键词快闪 1 条、首批 16 条、第二轮 42 条与补充 5 条、第三轮 40 条与补充 2 条。网站此前已有新闻关键词快闪，本次新增 **105 条**。新组件置前并标 NEW；114 条已归档组件在页面底部默认折叠，退出默认制作候选。

组件样片、核心帧、实际源码、可编辑参数和依赖一起提供。素材通过 Release 按内容哈希安装，旧版本素材包继续沿用原发布标签。私人背景音乐与机器绑定不随仓库分发，使用者提供自己的音乐。

新增组件的个人录屏、人物独立素材不随源码包提供；需要自备的输入路径见各包 `user-media-inputs.json`。预览保留认可画面，使用自己的素材后仍需检查实际输出。
