# 音频和字幕粗剪

公开版不附带作者的自然人声运行环境与录音。原音流程先配置并验证使用者自己的预处理器，再按本节顺序处理；已有人声音频和字幕可直接使用审片台。API上传与付费只依据当前使用者的授权，不能继承作者过去的授权。

输入是实际录音及可用的本期逐字稿；已有字幕可直接续做。目标是保留Fred实际表达，只删失败重说、口误起句和明确重复，校正识别错误，交付可试听、可调整的完整结果。不是重新写稿或逐字照稿重建录音。

## 原音入口

只有原音频时，严格按 **原音 → 自然人声处理 → 1.1倍速 → 字幕识别 → 粗剪 → +8dB** 执行。按 [references/original-audio-api.md](references/original-audio-api.md) 用 `scripts/qwen_asr.py` 对已自然处理且已加速的音频调用 `qwen-audio-3.1-asr-flash-filetrans`。使用者明确授权当前录音上传与API付费调用后，私人Key仅从本机0700目录/0600文件读取，不写进Skill、项目、日志或同步包。不默认打开剪映、不用Paraformer；任务续查不重复提交。稿件提取热词与短上下文，保留原始ASR和词/子词时间，识别结果仍需后续校正。

自然人声沿用项目本地 `audio-master-natural.mjs --no-deepfilter`。1.1倍速在识别前应用，+8dB在粗剪后应用，均只做一次；ASR、cuts和字幕共享加速后的源坐标，导出使用 `--speed 1 --gain-db 8 --trim-start 0`，片头剪切写入cuts。保护限幅并报告实际响度，不因自然链归一化而省略+8dB。已处理版和字幕单改不重复叠加。详细顺序、边界与API命令见上述参考。

## 声音证据与整条复查

新处理、补录替换和局部返修都按 [音频证据、残留与响度](references/audio-evidence-and-loudness.md) 执行：**识别多字只改字幕；句内短词不能凭ASR重复或波形二峰直接启用剪切**。用户确认声音正常时，检查旧导出是否已误剪并恢复，保留手改字幕。真实重说删后复核字头/尾音和残留起音，词时码不直接当下刀位置。

整条最终音轨检查综合指标和连续局部响度；正文、补录、插入旁白按职责比较，并检查插入内部首句突响。`verify_delivery.py`会生成只读响度轨迹及分段/字幕窗口摘要，阈值只提示候选，不自动剪音、归一化或证明听感。纯配音与含SFX的动画混音先核准确源；响度匹配只调当前不合适区间，不重复已完成的处理。

## 判断边界

- 保留“啊、嗯”、笑声、自然停顿、自行增加的评价和措辞。未要求时不批量删静音、去语气词。
- 先说错后重说：删前面失败部分，保留后面完整版本。检查句内残尾，如“工作场景Pro套 / Pro套餐…”，不能只找重复整句。
- 音频剪切与字幕纠错分开。DevDay→Update、Jev→Harness是本期识别错误，不是删对应音频的理由；专名用稿件、可信材料或Fred明确纠正核对，不猜不确定词。
- SRT通常只有句级时间。句内切点不能冒充逐字精度或已听审；用音频/波形定位，无法听审时说明估算，给接缝试听和微调。不能反复保留用户已经明确指出的重复。
- 跨句断字两边一起修：上一句尾“但”接回“是…”成为“但是”，同时维护字幕边界与音频切点。只改字不算剪掉重复。
- 按实际口播和稿件句意断句，别拆开200/美金、Claude/Code、执行能力和/电脑操作；合并沿用首尾时码，不跨候选切点合并失败段与正确段。
- 长字幕检查覆盖整份最终SRT，不只看用户截图那句。特别长的句子在合适语义位置拆成前后两条、按口播依次显示；不是只在同一条里换行，也不是缩字号。完整句意不要求同屏放完，合并后必须重新检查长度；具体方法见工作流的“长字幕与句内漏检”。
- 口误检查必须细到一句里的几个字：错词后立即重说、短词重复、半截起句、句尾残字和跨cue断字都检查，不只找整句重录。用户指出同类漏检后检查全文同类问题；字幕识别错只改文字，实际失败重说才剪声音，不把临场改词强行改回稿件。
- 用户说“字幕太长”时仅处理分段和时间，不擅自调整音频接缝。字幕单改复用原音频并核对hash，保留既有剪切、语速、音量和旧交付；新字幕、前端与下载必须同版。
- 不覆盖原音、剪映原SRT、用户手动文字/剪切选择和旧交付版。
- 展示字幕按语义分段后去掉普通逗号，尤其“一、第二、第三”后不留逗号；保留原始识别证据、小数、百分比、型号等有意义符号。数字按原稿/用户确认写法，如“3件事情”“10多轮”“两小时”，序号“第一、第二、第三”保留，不机械全局替换汉字数字。
- 用户明确要求按原逐字稿校正时，修复指定范围的错词、单位、专名和重复文字，不把全文临场表达强行改回稿件；声音是否需剪单独判断。比较表区分原始识别与当前校正，已修正文不继续标待核对；语气词漏识别不能凭空补时间。

## 停顿、吞咽声与局部返修

- 检查整段实际音频，不能只看SRT条目之间的空白。句级字幕可能覆盖句内停顿、吞咽、口腔声和重说后的过渡；结合波形与前后句意定位。
- Fred可接受约0.5秒的自然停顿，这是参考尺度，不是逐个压到0.5秒的硬阈值。句内或同一意思之间明显拖长时收紧；长段、章节切换和独立演示可稍长，保留表达节奏。低电平不等于没有语音，不能按单一阈值批量删除。
- 每次删重说后复查接点及其前后：不能只删重复字，留下旁边吞咽声或长空隙。先保住前句尾音和后句起音，再缩短无内容的过渡。
- 用户说“其他都好”时，只改指定问题及其直接关联的字幕/时序；相对上一版核对未修改片段的PCM。全篇同类检查不等于重新清洗全音轨。
- 原音、语速、音量已处理过且本次只要剪辑时使用`--passthrough`：保留PCM采样，不变速、不增益、不限幅、不自动裁片头。需要剪掉的片头写入cuts.json。字幕单改继续复用原WAV并验证hash。

## 本期复查与导出检查

- 普通处理导出同时测采样峰值、真峰值、综合响度和覆盖全片的局部响度变化；超标时有限次调整限幅，仍失败则不发布。公共脚本已加入过采样保护和独立真峰值复测；passthrough保持PCM。具体参数与证据见[工作流](references/workflow.md#真峰值与对比交付)。
- 句内删词可通过`cutId + cutRange + removeInfix`绑定声音与字幕，恢复/撤销剪切时联动恢复字词，导出同一cue只显示一次；手调切点后重核删词范围。配置与适用边界见[句内联动](references/workflow.md#句内剪切与字幕联动)。
- 词级ASR切点仍须核对字头/尾音，不凭新识别里的重复词自动剪音。重处理原音迁移旧剪点前，分布检查新旧时间偏移与漂移，方法见[时间对齐](references/workflow.md#词时间与旧剪点迁移)。
- 新旧对照按同一句切换并提供同响度试听，分别报告文字、分段、时间和声音变化；沿用旧分段时直接说明，保留实际版本身份。

## 执行

找本期唯一目录、最新稿件、录音与SRT，核对时长/格式/字幕覆盖。已有审片台时续做，不重建。公共前端已固定在assets/review-app，后续只换输入；可用主视频Skill的[公共模板启动器](../fred-remotion-output/references/segment-review.md#公共模板默认)同时打开音频/关键帧/视频模块。公开版可用合成测试素材验证联动模块，不分发作者个人录音或历史审片数据。首次创建：

```bash
python3 scripts/init_review.py --episode "/absolute/episode" --audio "/absolute/audio.wav" --subtitles "/absolute/subtitles.srt" --script "/absolute/script.md" --title "本期标题"
```

命令从本仓库的 `skills/audio-subtitle-roughcut/` 执行。阅读 [references/workflow.md](references/workflow.md)，把本期候选、词语、边界、分句写入本期 `03_制作过程/audio-review/` 的配置，模板不携带第107期切点/名词。

```bash
python3 scripts/deliver.py --review "/absolute/episode/03_制作过程/audio-review" --version v1
python3 "/absolute/episode/03_制作过程/audio-review/server.py" --port 8107
```

端口冲突用空闲端口，不杀其他服务。绑定127.0.0.1，HTTP准备好再发URL，持久运行用独立进程。原音API入口仅上传用户交付本任务处理的录音，不上传无关素材；已有字幕不无故重复收费转写。与用户沟通简短直接，不为流程新增审批。

## 审片和交付

灰色删除、待试听、原片段/接缝试听、波形与数字边界、启用/恢复、手动剪切、撤销/重做、本地保存、逐句文字编辑必须可用。每行编辑和剪切旁提供“恢复”：一次恢复所有覆盖该句的启用剪切，跨句剪切只恢复当前句，其他句删除及其cutId字幕联动保留。已完全删除的范围不重复新增剪切；恢复后刷新字幕，保留用户文字覆盖，支持撤销/重做与保存。完整成片页读取真实导出文件：完整播放、大字当前句、全部字幕高亮/跟随、点击跳转、倍速、下载、版本信息。局部PCM返修显示继承的既有处理参数，不把本轮passthrough的gainDb=0当作原音没有增益。未导出的修改不冒充最新成片。

待核对的短词重说须列出准确句子、时间、当前是否保留及不确定点；不能以“技术校验通过”宣称全文口误已清零。能继续用本地对齐/波形核验时先做，不把检查工作直接推回用户。

用户给出方向后继续完整导出；要求“直接给最终音频字幕”时交付本期 `02_最终输出/` WAV/SRT并放前端。未处理项须说明，“完整文件”不等于“所有口误已经清除”。

原音新入口先加速再识别，粗剪后仅加增益：

```bash
python3 scripts/deliver.py --review "/absolute/review" --version v1 --speed 1 --trim-start 0 --gain-db 8
```

此处片头空隙由cuts.json显式删除。以下旧命令仅适用于确认尚未加速的已有音频/SRT路径，不用于已按新入口加速的源；用户当次参数优先：

```bash
python3 scripts/deliver.py --review "/absolute/review" --version v2 --speed 1.1 --trim-start 1 --gain-db 8
```

已处理录音的只剪切导出：

```bash
python3 scripts/deliver.py --review "/absolute/review" --version v2 --passthrough
```

`--speed 1 --gain-db 0`本身仍走常规限幅链，不能当作透明保留原音；只剪切请用`--passthrough`，不与非零增益、变速或额外片头裁切组合。

这些是相对原音粗剪结果的总参数，不在已处理版上重复叠加。默认1.1倍速、+8dB；片头按实际空隙去掉，不机械删1秒。脚本用波形阈值提出片头切点，须试听确认，必要时用--trim-start覆盖；其秒数属于加速后的时间。加速保音高、字幕除倍率；裁片头字幕前移；增益不改时间。测峰值，可能超满幅时保护限幅、补偿延迟并报告实际平均变化，不声称限幅后每个样本仍精确增益。

运行 `scripts/verify_delivery.py --review /absolute/review`，再做实际浏览器的播放/寻址/高亮/编辑保存/撤销/下载和桌面手机检查。技术验证、听审和用户认可分开记录。无法接收音频时不假称听过。
