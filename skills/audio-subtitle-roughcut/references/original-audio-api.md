# 原音频到粗剪：千问 API 入口

Fred 在 2026-10-03 明确授权：后续把原音频交给本 Skill 处理时，默认使用已配置的阿里云千问 API，再按既有流程处理。授权范围是该任务提供的录音，不批量上传无关本地文件。不再默认操作剪映，也不使用 Paraformer；模型不可用时报告，不能静默换模型。

## 本地凭证与调用

- 固定模型 `qwen-audio-3.1-asr-flash-filetrans`。识别输入必须已完成自然人声处理和1.1倍速，返回的句级和词/子词时间属于这个加速后的源，不是最初原音坐标。不要换成没有词级时间的聊天转写接口。
- 私人凭证文件 `~/.config/fredtalk/private/dashscope-api-key`，目录 0700、文件 0600。不放进项目、Skill、Git、分发包、日志或截图；同步 Skill 不复制私人目录。使用者需要自行配置自己的密钥。
- 首次配置或更换密钥：`python3 skills/audio-subtitle-roughcut/scripts/qwen_asr.py configure`。隐藏输入，不把密钥放在命令行参数、shell history、普通配置或文档里。
- 前置依赖：本机 `python3`、`requests`、`ffmpeg`。缺失时报告，不自动改变全局环境。

由助手从本期最新稿件提取专名，生成本期 `asr-context.txt` 与 `asr-terms.json`（字符串数组）。上下文最多 400 字符，明确要求只按实际录音识别、保留语气词、重复、重说和半截起句。稿件用于专名与语义参考，不灌入整篇稿件让模型照抄，不以参考稿抹掉临场表达。示例命令的路径由本期实际目录替换：

```bash
python3 skills/audio-subtitle-roughcut/scripts/qwen_asr.py transcribe \
  --audio "/absolute/episode/03_制作过程/audio-preparation/voice-1.1x.wav" \
  --output "/absolute/episode/03_制作过程/qwen-asr" \
  --context "/absolute/episode/03_制作过程/asr-context.txt" \
  --terms "/absolute/episode/03_制作过程/asr-terms.json"
```

脚本不会替调用者自然处理或加速，须先完成下方准备步骤。脚本测峰值，必要时为整数FLAC转换降低固定增益，不再改变输入速度/时间轴；上传单声道避免重复声道计费。转换仅用于识别，粗剪声音使用同时间轴的voice-1.1x.wav而非上传FLAC。临时存储使用阿里云上传策略，不另建公开网盘。

同一命令、同一输出目录再次执行：已完成时复用结果；有任务 ID 时续查，不重复付费提交。提交超时且未拿到 ID 时保留 `submitting` 记录并停止，先查控制台，不能自动再次提交。网络错误不打印包含临时签名的完整 URL。更换音频或模型须新目录；需要重识别时先说明原因，不把重试当作免费动作。

输出 `raw-asr.json`、`source-asr.srt`、`word-timestamps.json`、`asr-state.json` 和 `asr-validation.json`。这些是原始识别证据，不能当作已经粗剪的最终字幕。API usage、整段时长、耗时和真实账单分开，不凭 token 数猜费用。保留的词记录可能含空格、英文子词，confidence=1 不代表正确率 100%。

## 接续处理顺序

1. 校对原音、最新稿件和原始识别覆盖；记录哈希、时长、声道。已有结果优先续做，别因 Skill 更新重跑旧工程。
2. 严格顺序：**原音 → 自然人声处理 → 1.1倍速 → 字幕识别 → 粗剪 → +8dB**。先用 `node skills/_runtime/remotion/codex-episode-1-xhs/scripts/audio-master-natural.mjs --no-deepfilter --input ... --output ... --report ...` 从原音产生本期自然人声文件，再用 `ffmpeg -i natural-voice.m4a -af atempo=1.1 -ar 48000 -ac 2 -c:a pcm_s16le voice-1.1x.wav` 输出识别与粗剪共用源，已存在文件不覆盖。随后才调用上方ASR命令。记录原音/自然处理/加速源的hash、时长、speedApplied=1.1和gainApplied=0（这里指最终+8dB尚未应用，不代表自然链无增益）。此自然链不含DeepFilterNet，也不是旧的afftdn/adeclick链；核对时长/延迟，不把自然处理夸称为新模型降噪。识别与自然处理不是并行支路。
3. 结合词级时间、波形、前后语义和稿件做完整口误初检：整段/整句重录、句内几个字重说、失败起句、残尾、跨 cue 断字及无关打断都检查；删前留后，保留后一次完整表达。不能只靠重复字符串自动剪。
4. 字幕校正与音频剪切分开。原稿中的明确专名、单位和识别错词可校正；Fred 明确说“按原逐字稿调整”时，以稿件解决该范围的争议文本，但不把全文改写成稿件，不因此再动声音。当前要求和手动修改优先。文本修好不代表声音里的重说已去掉，也不代表已经听过。
5. 全文按语义拆成长短适宜的顺序 cue；特别长的句子拆两条或更多条，利用词级时间核对断点，不拆专名、数字单位和固定词组。不只换行、缩字号；避免为追求短字幕造成碎片/短闪。空格子词、跨句词归属和真实发音仍需检查。
6. 展示字幕默认不保留中文逗号或普通英文逗号，尤其“一、第二、第三”后不加逗号；原始识别记录不改。小数点、百分号、数字千位分隔、型号和英文名称等有意义符号保留，不用全标点删除正则破坏它们。断句与显示去逗号分层，先确定语义边界再规范文字。
7. 数字沿用 Fred 的原稿/确认写法，如“3 件事情”“10 多轮”“两小时”；不把全部数字改成汉字，不把“第一、第二、第三”机械改成阿拉伯数字。按具体词组和稿件校对，禁止无条件全局替换“三”“十”。
8. 检查整条音频，不只看字幕间隔。约 0.5 秒自然停顿可保留，长段/章节转换可以稍长；句内明显拖长才收紧。多档低电平扫描结合上下文，阈值不能判断吞咽声或证明听感；删重说后同时检查旁边长空隙、口腔声和断字。
9. 粗剪后必须+8dB，即使自然链已归一化也不省略。新入口导出明确传 `python3 scripts/deliver.py --review ... --version v1 --speed 1 --trim-start 0 --gain-db 8`，不能沿用deliver默认1.1再次加速。片头按实际空隙写进cuts；ASR、cuts、分段全在voice-1.1x.wav坐标，不再把字幕除以1.1。按[工作流的真峰值检查](workflow.md#真峰值与对比交付)测真峰值、采样峰值和响度，超标有限次修正并补偿限幅延迟，记录最终gainDb=8、预处理speedApplied=1.1与实际测量，限幅后不声称每个采样精确提升8dB。已完成这两个步骤后返修才用passthrough，字幕单改严格复用音频hash。第108期旧试验版先识别原音且未追加+8dB，是历史试验，不是后续默认；规则更新不擅自重导旧版。
10. 输出可手调审片台、实际 WAV/SRT、切点/时间映射/修订记录。比较时保持旧版，另建独立结果和播放入口；比较时长、分段、文本、响度及待听项目，提供同句切换/同响度试听；旧剪点迁移先分布检查偏移与漂移。新ASR复核与显示分段重排分开说明。标点/空格归一化后的文本相似度不称识别准确率。网页播放文字、下载文件与 manifest 必须同版；旧识别差异表保留证据并另列“当前校正结果”，不要把已修字幕仍标待核对。

## 能力边界与验证

脚本自动完成上传、提交、续查、原始 SRT/词时间导出；不是全自动语义剪辑器。助手仍须按工作流生成本期 cuts、文字纠错、明确分段和成片导出。公共审片台的合并配置不自动实现词级拆分；需要本期导出脚本时保留实际分段配置，别写了规则就宣称公共脚本已有该功能。

自然链输出使用 AAC M4A 时，后续 WAV 不是全链路无损；需要无损母版须明确实现并验证，不能仅改扩展名。不要把第108期 41 刀、235 cue、专名或具体时码固化成后续配额。

验证原输入和旧交付未变；全音频解码、字幕时序和覆盖、长字幕/短闪检查、原音与处理版延迟、音量峰值/响度；网页播放、跳句、高亮、编辑保存、下载及版本一致。实际听审、技术通过和用户确认分别记录，无音频听审能力时如实标注。

## 剪辑与响度判定

ASR不是剪切授权或听审。识别多字/句内重复先按 [音频证据、残留与整条响度](audio-evidence-and-loudness.md) 分类，声音正确就只改字幕；已误剪时恢复真实声音，保留用户文字。导出既测整条指标，也查全时段局部响度和外部配音/补录内部变化，不因平均LUFS接近就跳过复查。
