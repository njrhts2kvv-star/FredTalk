# 本地执行与数据合同

只有原音频时先按 [original-audio-api.md](original-audio-api.md) 执行原音→自然人声处理→1.1倍速→千问字幕识别→粗剪→+8dB。识别输入与粗剪源均为已加速音频，cuts与字幕也在该坐标；导出明确`--speed 1 --trim-start 0 --gain-db 8`，不再加速，片头空隙写进cuts。该入口含API授权、私人Key、去逗号、数字写法、按稿校正及版本保护规则。

init_review.py复制独立审片台，不覆盖既有实例。project.json保存本期标题、输入路径和hash；非48kHz双声道PCM16的媒体用本地FFmpeg规范化，原文件不改。

## 配置

- cuts.json：`[{id,start,end,title,reason,enabled,confidence,reviewed,originCutId?}]`，project.json的sourceAudio秒坐标。新入口是自然处理且1.1倍速后的源，不是最初录音坐标；已有工程沿用自己的源。说明删哪段、保留哪遍、判断依据；reviewed不等于enabled。行级恢复分拆跨句剪切时，禁用原记录，其他句仍需删除的区间保存为独立片段，`originCutId`追溯原剪切的字幕绑定。
- subtitle-corrections.json：`[{cue,from,to}]`，精准匹配原文，不匹配停止。
- subtitle-edits.json：用户单句文字覆盖，优先于自动校正。
- subtitle-boundaries.json：`[{cue,start?,end?,removePrefix?,removeSuffix?,prefix?,cutId?,cutRange?,removeInfix?,note}]`。同时维护字词和时间，记录估算/听审。例如上一句删尾“但”、下一句补“但”且起止接于同一时点，不能复制两遍或切掉发音。
- subtitle-sentences.json：相邻源cue ID合并组，不乱序/重叠，不跨任何候选起止，包括禁用候选。
- subtitle-joins.json：后一cue ID到逗号/顿号的映射；不把数字、模型名拆开。
- subtitle-sentence-edits.json：合并句文字覆盖，key是cue ID逗号串；sourceCueIds防止组改变后误写旧句。

保留originalText/originalStart/originalEnd和sourceCueIds。恢复校正版撤回手动文字覆盖；顶部撤销只管理剪切。外部修改原输入或server代码需重启，JSON调整后刷新。本期只有一套事实源。

### 行级恢复与重复剪切

- 字幕行的“恢复”恢复该行原始时间范围内的音频，不是清除手改字幕。一次处理全部重叠启用剪切，包括同句被重复删除的情况；已经完整覆盖的范围再次删除为无操作，不叠加刀或撤销记录。
- 使用originalStart/originalEnd，不能因为cutId绑定修订缩短了当前字幕边界，就漏恢复被删除的字头、字尾或整句。
- 某句cutId绑定剪切的声学字头可能略早于估算cue.start，或字尾稍晚。行级恢复可沿绑定剪切扩到相邻cue之间的空隙；前界不得早于上一cue的originalEnd，后界不得晚于下一cue的originalStart，既清掉该句字头的残刀，也不恢复相邻句内容。恢复范围不改变原字幕显示时码。
- 跨句剪切恢复当前句时保留两侧删除区间；其他句不会跟着恢复。分拆片段用originCutId沿用原绑定，server只在片段仍覆盖对应原始cue时应用其字幕修订。恢复当前句后该句绑定修订撤回，其他句的removePrefix/start等修订保持。
- 恢复、撤销、重做均按一轮操作更新cuts，保存后重新读取实际字幕；用户subtitle-edits和subtitle-sentence-edits不被音频恢复覆盖。恢复字幕手改仍使用编辑窗里的“恢复校正版”。
- 回归测试使用独立合成项目，覆盖重复刀、跨句恢复、绑定修订、HTTP保存/重载与撤销/重做；不得为了验证按钮改动正在制作的cuts、文字覆盖或成片。

## 先区分识别错误、声音错误与响度

所有音频处理和返修先读 [音频证据、残留与整条响度](audio-evidence-and-loudness.md)。句内短词只有ASR重复时先保留声音；用户确认是识别多字时只改字幕并撤回误剪。响度由整条连续窗口和实际角色分段核对，不能只凭全片综合值或某一张截图。

## 全篇停顿检查与返修保护

1. 以当前最终WAV和它的时间映射检查全篇，原音/现有剪切区间同时保留；SRT空白仅作线索，不代表真实静音。
2. 用短窗RMS/波形、多档阈值筛出候选，再逐个读前后字幕判断语义。记录当前成片时间、对应源音区间、可能的低声尾音、保留或缩短的理由。阈值检测不识别吞咽声，也不证明听感通过。
3. 约0.5秒的自然停顿通常可保留；句内明显停得过久需收紧，章节交接/演示可以稍长。不要把某期0.4/0.9秒或固定dB阈值当作全部录音的硬值。试听插入点、长段呼吸和语气词按内容保留。
4. 删除重复后复查接点前后是否残留吞咽、口腔声、半截发音或突兀空隙。微调时保护有效辅音/尾音；波形最低点不等于词边界。无法听审的边界标明估算。
5. 新切点仍记在原音坐标；重算后续字幕，不在已剪版本上重复变速。相对上一版证明只删了指定区间，其余保留PCM一致；有意淡化/交叉渐变时明确记录范围，不能再声称这些样本完全一致。
6. 只有字幕分段变化时复用音频路径及hash；如果需要同时删音频中的真实重说，单独列出新增音频剪切。旧版本、用户的手调覆盖及禁用候选保持。

## 导出

### 已处理音频与补录替换

先锁当前完整master、字幕、采样率与处理状态。用户说已做过加速/增益时按该输入只粗剪，明确speed=1、gainDb=0并使用passthrough；不重复自然链、变速或限幅。新补录是原音时仅对补录执行当前原音链，再与旧master替换邻域比较响度，必要时单独匹配；报告补录的+8dB、限幅及最终匹配衰减，不把匹配当作再次处理整条master。

替换清单写明旧master半开范围、新补录保留源范围、失败take和明确不替换的尾句；按采样边界拼接，保护此前已完成的替换。逐段记录源→成片映射与时长delta，字幕及下游画面/音效重新绑定受影响时间，不能按整段总时长比例挪cue。未替换的前后PCM独立比较；淡化或交叉渐变范围单列，不能声称该范围字节相同。接点需核对字头、尾音和前后语气，技术通过/波形估算不冒充听审。当前公共脚本不自动编排多次补录替换，实际拼接和映射保存在本期。

### 长字幕与句内漏检

导出前分开检查两类问题，不用“字幕时间合法”代替内容审查：

1. 全文检查长字幕，尤其是把多个源cue合并后的条目。按目标字幕区实际宽度、字体及阅读时间判断；中英混排考虑英文占宽，不能只数原始字符。明显过长时优先拆两条，在转折、递进、主从分句或列举项边界断开，避免拆开专名、数字单位和词组。不要为了语法整句而继续拼成长条，也不机械把所有字幕切碎。
2. 优先沿用原SRT中合理的语义时间边界。需要句内拆分时核对音频/波形或已有词级对齐；只能估算时记录估算，不宣称逐字同步。拆分后的串联文字与原条目一致，首尾时间覆盖不变，时序不重叠，无空条或不合理短闪。字幕单改时音频文件hash必须不变，不重新应用加速、增益或限幅。
3. 逐条检查句内短词和相邻cue首尾，结合稿件找错词后重说、局部重复、起句残片、句尾多字和跨句错归属。稿件用于识别语义，不覆盖实际临场表达。明确是识别错字时只校正字幕；实际说错后重说则删前留后，声音、字词与边界一起修。证据不足的词不得猜改，但用户已经明确指出的重复不能继续以“待试听”原样留在导出中。
4. 保存本期分段决定及源cue/时间映射，后续再导出应复用，不能被自动合并还原为长字幕。当前模板的subtitle-sentences.json仅支持合并；需要句内拆分时在本期导出流程保存明确的分段配置/脚本，不伪称公共模板已支持自动语义拆分。
5. 全文复查不得止于拆分前：重新计算合并/拆分后的占宽、阅读时长和邻接关系，字幕条目中不能靠\n或缩字号伪装成先后两条。拆分前后串联字符一致；人工确认的错字校正单独列例外。不把某期字符上限或拆分数量固化为所有字幕的配额。
6. “跟、把、和、就、这些”等连接成分按语义放到对应分句；调整前条末尾、后条开头和时间边界，避免漏字/重字/断开词组。句级时间估算不称词级对齐。若文字修订依赖某条剪切，恢复该剪切时必须连同文字归属恢复；公共模板现支持cutId条件生效：禁用/恢复剪切时同步恢复原字词，前端保存后重新载入文字；具体句内删词配置见下文。
7. 核对实际最终SRT、final-delivery.json和网页播放显示一致，并检查拆分前后两条按时间先后切换。技术校验、听审和用户认可分别记录。

例：将“但是大家如果本身用不了Claude Code用的是Codex或者国内的Agent或者模型”拆为“但是大家如果本身用不了Claude Code”与“用的是Codex或者国内的Agent或者模型”。例子只说明语义断点，不作为未来固定文案或时码。

deliver.py复用审片台合并区间、保留片段与文字逻辑。按Fred最新要求，默认speed=1.1、gain-db=8、片头波形阈值提出空隙裁点（需试听，不固定1秒）；--trim-start手动覆盖。需要保持现有处理结果时用`--passthrough`，从审片台粗剪WAV直接复制PCM；这与仅传`--speed 1 --trim-start 0 --gain-db 0`不同，后者仍会限幅。只剪切模式的片头编辑写进cuts.json，禁止额外变速/增益/自动片头裁切。已存在版本拒绝覆盖。输出WAV/SRT到02_最终输出，decision/验证到制作过程，final-delivery.json指向实际最新成片。

时间公式 `newTime = roughCutTime / speed - trimStart`，不重复对已加速版加速。音量不改时间，限幅补偿延迟。剪掉的字幕不导出，跨句内裁点的文字需校对；export的subtitleReview不为空时不能宣布字幕已经最终正确。

verify_delivery.py核对解码、采样数/时长、SRT连续编号/非负/不越界、字词与时间映射、原输入hash。实际浏览器另查两个播放器不叠播、版本/下载/缓存不读旧文件、1.1倍已应用时播放器默认1×。技术验证不等于接缝听感。

历史粗剪任务曾因音频工具不能接收音频而未听审。当前默认原音识别已按Fred授权改为千问Audio 3.1，不调用Paraformer；音频听审能力按本次工具实际判断，不把历史失败固化成永久限制，也不把词级时间冒充听审。


## 版本与检查结果

- 前端完整播放、字幕、下载链接和版本信息必须指向当前导出；保存审查修改不等于已经更新成片。展示未导出状态，导出后刷新实际文件；只有新版本内容或具体剩余风险需要复检时才扩大检查。
- 术语优先使用Fred本期明确纠正的写法，同步字幕及待核对说明；项目名、模型名、价格只保留本期记录，不硬编码到公共替换词典。
- 保留`technicalPass`、`listeningReviewed`和用户认可各自的真实状态；重说候选/价格文字无法精确定位时列出待处理范围，不伪称全部清除。


## 句内剪切与字幕联动

`subtitle-boundaries.json` 可把文字修订绑定 `cutId`。该剪切启用时应用，禁用或移除时恢复；用户手改文字仍有最高优先级。删句中间的短词使用以下结构，例中的词与时间须替换为本期核实的内容：

```json
{"cue": 1, "cutId": "repeat", "cutRange": [0.4, 0.7], "removeInfix": {"text": "重复短词", "occurrence": 1}, "note": "本期词级记录、波形与听审状态"}
```

- `occurrence` 从1开始，针对该条修订应用前的文字。重复词必须指定删第几次，不能全局替换；多条修订按数组顺序应用。
- `cutRange` 与实际剪切区间须在1个采样内一致，且位于该cue内部。手调切点后必须重新核对并更新范围；范围不匹配时保存/导出报错，避免旧删词决定继续生效。禁止为了消除报错机械复制未经核对的切点。
- 导出对经过明确删词核对的同一cue，把切点两边剩余文字合成一次连续显示，避免重复整句或短闪。遇到未绑定的新剪切仍报`subtitleWarnings`，不能被已核对的另一刀掩盖。
- 恢复这刀、撤销、重做时同时检查字幕恢复。手动文字覆盖不会被撤销剪切自动丢弃，需按当前用户意图核对。
- 行级恢复产生的originCutId片段只对仍覆盖的cue延续绑定。removeInfix仍要求实际启用片段与cutRange在一个采样内一致；恢复后范围若不一致继续报错，不能借分拆绕过词边界复核。已匹配的infixCutIds使用实际片段ID，保持导出中的字幕审查准确。
- 原始cutId仍启用时保持既有条件语义，允许前后相邻cue的字词归属修订及声学边界落在ASR空隙。仅originCutId分拆片段限制到仍删除音频的cue。手调绑定前缀/后缀刀后仍须重核该句文字与start/end；当前精确cutRange校验只覆盖removeInfix，不能将前后缀的旧边界当作已重新对齐。
- 这项功能处理明确的句内删词，不自动完成语义分句或声学逐词定位。完整导出后仍检查长字幕和短闪。

## 词时间与旧剪点迁移

词级ASR提供位置候选。结合发音包络和前后文复核字头/尾音；模型把停顿算进词、把字头放晚或多识别一个重复词时，不能直接照时间切。波形能辅助找低能量接点，不能单独证明说了哪个字。实际重复和识别重复分开记录；无法确定时列准确短段、保留/删除状态与不确定原因，不假称听过。

从原音重新处理但沿用旧剪辑时，在开头、中间、结尾及关键剪点附近比较新旧源的同一内容。记录各位置的偏移及检查方法，区分固定延迟与累积漂移；明显漂移要按内容重新映射，不能只用总时长比例或一个起点平移全部剪点。迁移后检查声音边界、字幕与源→成片映射；旧版不覆盖。本期10ms等数值留在本期，不作为Skill默认。

## 真峰值与对比交付

普通处理导出由`audio_qc.py`测综合响度、真峰值和采样峰值；`verify_delivery.py`另用`loudness_profile.py`生成全片连续响度、角色分段和字幕窗口摘要，具体候选判断/局部匹配见[声音与响度参考](audio-evidence-and-loudness.md#整条响度不能只看一个lufs)。`deliver.py`跳过speed=1的atempo，使用带延迟补偿的过采样限幅；不变速时保持精确采样数。默认真峰值目标-1dBTP、测量容差0.05dB，先预留0.5dB余量，若超标最多本地调整3次。失败不发布新final-delivery；根据实际录音与交付规格改参数并核验，不重复ASR。元数据保留每轮参数与测量；`verify_delivery.py`独立重测目标。`--passthrough`只测量、记录，不限幅或改变PCM。

+8dB是增益设置；报告实测LUFS变化和动态范围，限幅会改变实际增幅。延迟补偿配置不代表听审，变更处理链时用波形/脉冲核对同步；字幕单改继续复用原音频hash。

用户要求新旧比较时，前端按对应语句或源时间映射切换，提供同响度试听（仅衰减较响版本，不改下载文件），并可切回原始响度。明确对比固定的两个版本，或在重新导出时同步更新音频、字幕、指标、映射和下载；不能播放新版却沿用旧指标。

交付分别说明四类变化：文字纠错/删词、显示分段与每屏长度、字幕时间、声音处理。新ASR用于复核而保留旧分段时如实写明；不把词级识别成功说成字幕呈现已升级。A/B页面仍由本期按需要实现，公共模板尚不自动生成对照页。


## 公共审片模板与视频台连接

音频前端固定复用assets/review-app，init_review.py只复制代码和空状态，再绑定当前音频/SRT/稿件。project.json及新导出的最终WAV/SRT索引使用相对review目录路径；既有绝对路径配置继续可读，不改冻结旧期。输入在期外且需要独立携带时显式加--copy-inputs，复制到审片台inputs；这不包含付费API、重处理录音或复制私人配置。新目录/输入先核hash，不能把107/108旧切点、反馈或聊天当默认数据。

主视频Skill的serve_review_app.py可同时启动音频和视频模块，用--audio-review指向这里，两页互相链接；已有单独音频服务继续按原server.py启动。音频完整页显示真实已导出版本、语速/音量处理和接缝听审状态，字幕点击跳转与倍速不改最终文件。未导出的编辑只显示在字幕审查，不冒充完整页已更新。制作中继续保持同一台，不用模板更新覆盖cuts或手改字幕。

局部PCM返修的final-delivery可保留`processingMode: bounded-pcm-revision`及`inheritedProcessing`，记录此前已完成的gainDb等处理。完整页显示实际继承增益及一句局部返修说明；本轮speed=1/gainDb=0/passthrough表示不重复处理整轨，不能显示成原音没有加过速或增益。

公共index.html的app.js/styles.css资源URL带当前内容hash版本，静态HTML/JS/CSS响应使用Cache-Control:no-cache，防止同一审片端口继续显示旧按钮或旧处理说明。版本参数只影响前端代码，音频hash URL及媒体缓存策略保持。同步代码时一并更新index.html，不覆盖本期配置。
