# FredTalk 视频设计语言

用于设计新的解释动画、新做组件，也用于适配现有组件。首次构思整片、设计原创场景或新做组件时读。第 2 节是固定规则（具体数值），其余各节是表达原则；本文不规定每期的布局、切镜次数或组件套餐。

当前依据：2026-09-30 Fred 授权沉淀的字体/对齐、浅紫重点、文件对象及媒体连续性反馈，以及2026-09-23的默认外观；第95期当前源映射/认可记录、第99期8条精选准确源码，以及视觉库当前保留的对象/文字动作。用户最新要求优先；旧参考的局部描边、紫色铺面、连线或章节标题不自动继承。准确复刻及已认可局部返修按当次保护范围执行。

## 1. 要稳定的是什么

可以把这套风格描述为：**黑白实体界面、文字主导、按内容连续变化的动效。**

- 黑白面、清楚的大字、克制的柔和阴影建立分量与层级；紫色指出当前关键点。
- 画面围绕正在讲的对象与关系组织，镜头让观众认清变化。不能仅凭黑白圆角或同一字体就称延续了质感。
- 外观和动作的逻辑保持一致；内容、构图、载体、方向、数量与节奏可以变化。纯大字、真实媒体、复杂流程各有适用时刻。
- 字、材质、物体位置、声音和镜头共同指向此刻的重点。不要让每层都独立抢注意力。

- **代码里的唯一来源**是 [`templates/component-kit/src/kit`](templates/component-kit/src/kit)（`theme.ts` 和 `ui.tsx`），指纹锁在 `kit.lock.json`。
- 数值出处（取自哪个已认可组件的哪一行源码）见[视觉值出处](references/style-kit-sources.md)。
- 改这里的任何值，都需要 Fred 明确同意，同时更新 kit、`kit.lock.json` 和本节。
- 准确复刻、已认可组件的局部返修，仍按当次保护范围保留原值，不强行改成本节的值。

| 图标与线 | 不放装饰性图标；真实产品 Logo、录屏原生图标、文件类型可以用。不默认画连线和箭头 | 拓扑、轨迹确实不可替代时少量使用 |

| 职责 | 字体 | 常用字号（1920 逻辑 px） |
| --- | --- | --- |
| 正文、说明 | MiSans Medium 500（`S.body`） | 窗内正文 52–64 |
| 重点、标题、数字 | MiSans Heavy 900（`S.body`） | 单屏结论 120–154；清单项 96–180 |
| 胶囊大字、快过渡大字 | 锐字真言 400（`S.display`，单字重，不能合成加粗） | 胶囊 116–171；黑窗标题 180 |
| 代码、终端、配置 | Source Code Pro Semibold 600（`S.mono`） | 按最长行自适应，上限 52 |
| 手写、温和语气（少用） | 霞鹜文楷 400（`S.kai`） | — |
| 字幕 | 得意黑，走[字幕模块](references/landscape-subtitles.md)，不进组件 | 47.5 |

同一组用同一字体文件和同职责字重，组内对齐、相关底行共享视觉基线。不同字体名义字重相同仍可能挤字，先看实际字形、字距与行距。所有文字都设 `fontSynthesis: 'none'`，并等字体加载完再出帧（`Fonts` 已处理）。只用 400、500、600、900 这几个有文件的字重，其他字重会被浏览器合成。字距默认 0，行高 1.16。字体文件与哈希见 [typography-registry.json](references/typography-registry.json)。

### 2.4 动效（曲线、时长、相机）

具体怎么写（帧驱动、过冲回落、同一进度、对象连续、裁切擦出、文字三件套、景深、相机）见[动效手法](references/motion-craft.md)。

| 项目 | 固定值 |
| --- | --- |
| 主曲线 | `p()` = bezier(.22, 1, .36, 1) ease-out：进入、落定、文字出现 |
| 对象搬移 | `q()` = smoothstep：缩放、位移、蒙版、换位 |
| 章节擦出 | `wipe()` = bezier(.65, 0, .2, 1) |
| 回弹 | `springAt()` = 1 − e^(−8p)·cos(9p)，0.5–0.8 秒，只在明确需要“落下弹一下”时用。**不用 Remotion `spring()`**，不加无理由的弹跳 |
| 相机 | `quintic()` 配合 `cameraTransform()`：移动约 0.6 秒，停稳阅读 0.85–1.65 秒，交替进行。推近以能读清为准，常见 1.3–1.6 倍，不超过让内容出画 |
| 典型时长 | 胶囊打开 0.8 秒；单项进入 0.38–0.42 秒；汇聚 0.72 秒；新消息 0.32 秒；页面擦除 20 帧 |
| 逐字 | `typed()`：标题约 10 帧/字，正文 5–7 帧/字（60fps） |
| 节奏 | 常规组件 5 秒；快过渡 1–3 秒。主体在 0.3 秒内开始出现；结尾至少 0.6 秒稳定阅读；不用全程慢漂移填时长 |
| 依次出现 | 按口播 cue 排；没有 cue 时，项与项相隔 0.5–1.2 秒，不要机械等距 |
| 口播对齐（kit v2） | 每个组件提供 `cues?: number[]`，用 `cueAt(cues, i, 默认秒数)` 取时间：有真实口播就按口播触发，没有就用默认节奏 |
| 进出场（kit v2） | 用 `Handoff` 包住组件内容，提供 `enter`（cut/fade/rise/grow）和 `exit`（none/recede/fade/cut/slide-left/slide-up）。组件自己的入场动作不变，Handoff 只负责接上一段、交给下一段；角标在 Handoff 外面，不跟着动 |
| 局部聚焦（kit v3） | `Spotlight({ rects, amount })`：整体压暗 0.6，只留强调区原亮度，圆角柔边，可配合推近。指出页面某处、某一行时的默认做法，替代黑框、紫框和白色模糊蒙版 |
| 随机 | 渲染必须确定：不用 `Math.random`，伪随机要用固定种子 |

### 2.5 呈现（一个组件做什么）

- **一个组件只做一个主动作。** 动作来自“观众要看懂的变化”（谁 → 变成什么），不来自“挑一个入场特效”。关系与动作的对应见第 3 节。
- **快过渡（1–3 秒）可以用粗大字或大胶囊**，但必须有黑窗或黑胶囊做容器，字粗、对齐、对比强。没有容器、位置乱跳、灰字对比弱、白底大面积留白，都不合格。
- **真实界面必须推近到能读清**，读完再回全貌或交出去。
- **材料到结论**：材料退后（蒙版 + 失焦 + 轻微缩小），结论在前景读清。旧文字要先退干净，不能在前景下面留残字。毛玻璃表达的是“材料 → 判断”：不能用纯色页换掉背景还声称保留了上下文，也不是每段都要加蒙版。
- **同一动作只换颜色、换素材、换场景，算重复。** 新做前先查库，有同动作的组件就复用，不新做。动作不同的同类组件可以并存，用来轮换。
- 不像 PPT：没有页眉、页码、英文眉题、装饰编号、状态小字。

### 2.6 音效

| 动作 | 音效（kit 短名 → 库编号） | 触发点 |
| --- | --- | --- |
| 胶囊、圆点、条目出现 | `pop` → SFX05 | 主体首次出现 |
| 主次交换、推近、接管 | `woosh` → SFX04 | 运动开始 |
| 短窗口进入、遮罩刷出 | `whoosh-short` → SFX01 | 运动开始 |
| 让位、展开、整组上移 | `slide` → SFX13 | 运动开始 |
| 结果落定 | 默认 `pop` → SFX05；全片最重要的 1–2 次结果才用 `ding` → SFX03 或 `notify` → SFX07（传 `keep`） | 落定 |
| 真实点击 | `click` → SFX09 | 点下瞬间 |
| 实际输入 | `typing` → SFX08，音量 0.4 | 只覆盖打字区间 |
| 新回复进入 | `message` → SFX15 | 出现 |
| 多对象聚拢 | 默认 `woosh` → SFX04；全片最多 1–2 次用 `gather` → SFX16（传 `keep`） | 运动开始 |
| 数字实际滚动 | 全片最多 1–2 次用 `scroll` → SFX19（传 `keep`）；不传 `keep` 时 kit 自动换成 `whoosh-short`，想静音就不写 Sfx | 只覆盖滚动区间 |

- 音量 0.5（打字 0.4），不超过 0.5；
- 一个主动作配一声，同时有多个动作时只给主交接一声，每个组件通常 1–4 声；
- 不按每个字、每帧触发；
- **全片限量（kit v3，Fred 2026-10-13）**：齿轮滚动声（`gather`、`scroll`）和“叮”成功声（`ding`、`notify`）在整期里很跳，每期各只留 1–2 处。kit 的 `Sfx` 默认把它们换成刷（`woosh`/`whoosh-short`）和嘟（`pop`），要保留的那一两处写 `<Sfx name="ding" keep />`。交付前统计全片带 `keep` 的数量；
- kit v3 的替换也作用于在 v3 工程里使用的已入库组件（本期适配副本），这是有意的：全片统一限量。要在某个组件里保留，就在本期副本里给那一处加 `keep`，入库原版不改。
- 绑定细则见[音效](references/sound-effects.md)。

### 2.7 内容

- **默认内容用 Fred 的真实素材**：真实界面截图、作品、头像与 3D 卡通形象、真实 Logo、真实数据。不用 lorem、占位图或编造的界面。
- **所有可变内容都是 props**：文字、数量、素材、强调词、时间点。组件内部不藏旧常量。
- **长短文案都要能放下**：至少测一份更长、一份更短的文案。
- **安全**：
  - 密钥、令牌、密码从第一帧起打码；
  - 不出现手机号、私人聊天、他人隐私；
  - 他人创作的素材（例如 library 的参考帧）不作为默认内容。
- **中文优先**：标签写“第一部分”，不写“PART 01”。产品名、代码、命令保持原样。
- **紫色强调词**由 props 指定（`highlight`），一句话里只强调一处。

## 3. 用关系组织动作

设计时先回答：观众已认清什么，接下来哪种关系发生变化，什么时候需要读完，下一段接走什么。动作不从“随机挑一个入场特效”开始。

| 内容关系 | 可复用的动作逻辑 | 质量锚点与适配要点 |
| --- | --- | --- |
| 当前观点交给下一观点 | 当前对象缩小/侧移保留上下文，下一对象接管阅读区；需要总结时重新归组 | T01、T02；文字、外壳、圆角作为同一对象协调。上下左右都可变，不能只缩外壳、不处理文字 |
| 一个概念展开为若干任务 | 先认清整体，再展开实际子项；处理/选中发生后收束结果 | 99-02、99-20；保留建立→展开→判断→收束，不继承三项/六项配额、固定列数或旧文案 |
| 比较与逐项讲解 | 共同条件保持一致，当前项突出，旧项退后，比较对象身份仍可辨认 | 95 row12、T05；变化发生在主次与证据，不能把比较机械画成上下游流程 |
| 给主体补充解释 | 主体保留身份并让出空间，新信息进入；解释完按需要回中或接走 | 99-09、T02；先测真实内容的空间，不为了配旁注无限缩小主体 |
| 从设备看清内容 | 内容从同一屏幕区域放大成为主体，外壳让位，媒体时钟保持连续 | 99-13、T10；绑定真实屏幕框和播放时间，不突然重播或换一张近似截图 |
| 从材料得出判断 | 材料保持身份，黑白蒙版/失焦让其退后，结论在前景读清；再决定返回或交出 | 95 row04、99-21、T07；背景、蒙版、前景独立，模糊不能作用到重点和品牌 |
| 输入、回答与持续阅读 | 输入过程可逐字；完整判断可刷出；补充词可淡入退下；对话组可上卷为新回复让位 | 95 row30、W01–W05；选择依据是文字职责，字幕仍是独立层，不要求每句换一种效果 |

“建立→变化→阅读→交接”是思考问题的方式，不要求每段完整演一遍；上游已建立就直接承接，结论可停在一句大字，稳定阅读不需持续漂移。

### 动作与镜头的共同约束

- 进入要让对象及时可辨认，移动和缩放要有目的地，落定后给足阅读。退出的任务是清楚交出注意力；入场和退出分别按建立与交接职责选动作，不默认完全镜像；当前指定原版轨迹优先。
- 同一运动组保持速度感和完成顺序协调；强调、载体搬移、文字揭示可用不同缓动。不要为“风格一致”把所有动作换成同一个spring，也不保留无理由弹跳。
- 一次变化有主要阅读焦点。旧项尚未退出、新项进入可以重叠，但两段主文字不能意外争抢同一区域。不能用单张终态图证明没有叠字。同级白字检查每项首个可读帧，不能因默认样式或继承透明度让后一个意外变灰；有职责的逐字显隐仍可使用。
- 相机推近服务可辨内容，横移服务焦点交接，回全貌服务重新理解关系；阅读时停稳。不要用全程慢漂移填时长，也不强制相机永远不动。
- 用口播的实际词组确定触发与阅读窗；快动作不等于快闪，读不完就改分组/时序。已有声音需与动作同步，不能每个小变化都加声。
- 连续对象在相邻场景保留身份、几何与媒体时间；话题真正改变时直接切换也可成立。不要求所有边界都变形或刷屏。

## 4. 模块不是一张固定尺寸的图

同一模块至少拆清三种责任：**内容是什么、怎样承载、怎样随时间变化。**

- 内容：本期文字、真实媒体、对象/项目数量和关系；不能藏在组件内部旧常量里。
- 承载：黑白表面、字阶、间距、可读区域、适用字幕避让；让主题统一决定外观，不在每个场景手写一套近似阴影。
- 动作：进入、阅读、强调、退出及交接的状态与cue；移交新文本/媒体时保持该对象的连续性。

原子组件可组合成关系模块，再由本期场景把关系模块与录音、媒体、品牌、字幕接起来。总结不强制胶囊，流程不强制节点线，媒体不强制设备框。使用成熟完整模块仍是优先选项，不能为了抽象而拆坏其已成立的动作。

**画布利用与局部避让：** 正文的布局起点应给内容足够面积；不要把示意用的安全框当成不能跨越的硬边界，也不因右上角有角标就封掉整条顶部、因一条字幕就永久封掉整个底部。全屏媒体可铺满，关键文字与主体按角标实际占用、字幕当前cue的真实宽高及运动路径局部协调。字幕未出现时可使用相应空间，出现时重新检查。规范站示例里的边距只说明一种构图起点，不成为跨期固定比例；真正需要读的材料宁可展开、分阶段或聚焦，不因过宽预留把内容缩小。

**分辨率适配与内容适配分开：** 在1920逻辑画布上整体缩放到4K，可以保持几何；它不会自动处理更长的中文、多一个节点、竖图变横图、双行字幕。后者需要内容测量、布局重排或分阶段呈现，不能仅把整组缩小。

现有代码能力、真实props、固定条件与未完成项见[组件复用图谱](references/component-reuse-map.md)。文档中的设计分层是调用与后续抽象方向，不表示已经新增了一套统一React组件包。

## 5. 没有现成组件时怎么做

**新做可复用组件**（Fred 当次明确授权时）按[新做组件流程](references/new-component-workflow.md)执行：
1. 从需求数据定场景，写一句“观众要看懂的变化”；
2. 用 `component_kit.py` 建工程，只用 kit；
3. 用真实素材，所有内容做成 props；
4. 规则检查（lint）、逐帧检查图、长短文案测试；
5. 云端渲染后交 Fred 挑选，认可的条目用 `component_kit.py intake` 入库。

**本期单个原创场景**（不入库）：
1. 先用一句话定义观众要看懂的内容变化，按第 3 节的关系选构图与动作，不先画卡片网格。
2. 外观、曲线、字体、音效按第 2 节，直接从 `templates/component-kit/src/kit` 复制使用。选择相关的动作质量锚点。**只借动作关系、代码为本期重写，属于场景级定制（2026-10-13 Fred 同意），按二创记 `adapted`**，字段填法见[组件库交付门禁](references/library-delivery-gate.md#场景级定制怎么登记)；找不到任何来源动作的才记 original，需要 Fred 当次授权。不能给没借到动作的代码挂编号。
3. 在原有 `styleContract` 写本镜具体决定：surface、typography、geometry、motion、camera、mediaBehavior，例如谁退后、谁接管、如何读完。不能每镜都粘贴同一份“黑白简约”。
4. 用本期真实最长文字、素材和字幕做关键帧，覆盖建立、最拥挤的中间态、阅读终态与接缝。Fred 确认后，按既有流程内部看动态。
5. 对照锚点检查有效内容面积、字阶、表面层次、动作关系和阅读节奏。符合色彩不代表达到质量；技术 PASS 也不等于视觉通过。

把当前设计决定留在一份 Manifest 中，不新增一套设计审批或第二份逐段计划。只对真实影响的画面和交接复核；已有保护范围继续保留。

## 6. 看画面时实际检查什么

- 这句新增了什么可见信息或状态，观众能否跟上同一对象？
- 是否有可删除的眉题、小标签、装饰icon、细描边、线条和大面积紫色？
- 在实际观看大小下主文字能否读清；密集材料是否有清楚的阅读顺序，而非缩到“放得下”？
- 表面、文字、阴影与运动是否属于同一对象；中间态是否拉字、叠字、裁切或退场残留？
- 毛玻璃是否保留了有用上下文；重点和角标是否清楚；字幕实际出现窗口是否遮住关键前景？
- 前后段是否连续，稳定阅读是否足够；变化是否来自内容，而非为避免“单调”不断换效果？
- 是否只用了第 2 节的值：颜色、阴影、圆角、字体、字重、曲线、音效音量（新做组件用 `component_kit.py lint` 先查一遍）？
- 换成更长或更短的文案后，是否仍不溢出、不叠字，主文字仍然读得清？
- 和库里已有组件相比，是不是同一个动作只换了颜色或素材？

这些是实际观察问题，不是增加几个布尔值就能证明美观。
