# FredTalk 视频设计语言

用于设计新的解释动画，也用于适配现有组件。首次构思整片或设计原创场景时读；日常只带当前场景摘要与所用动作。本文描述要保住的视觉与表达关系，不规定每期的布局、切镜次数或组件套餐。

## 1. 要稳定的是什么

可以把这套风格描述为：**黑白实体界面、文字主导、按内容连续变化的动效。**

- 黑白面、清楚的大字、克制的柔和阴影建立分量与层级；紫色指出当前关键点。
- 画面围绕正在讲的对象与关系组织，镜头让观众认清变化。不能仅凭黑白圆角或同一字体就称延续了质感。
- 外观和动作的逻辑保持一致；内容、构图、载体、方向、数量与节奏可以变化。纯大字、真实媒体、复杂流程各有适用时刻。
- 字、材质、物体位置、声音和镜头共同指向此刻的重点。不要让每层都独立抢注意力。

## 2. 外观默认值与边界

| 维度 | 新画面默认怎么做 | 容易误用的边界 |
| --- | --- | --- |
| 文字与密度 | 保留这句真正需要读的信息，主次清楚；小模块通常主/辅两档足够。冗余解释、英文眉题、状态小字和装饰编号先删。内容过多先归组、分阶段或聚焦，再考虑字号 | 真实文档和UI本来就有小字，先给全貌与阅读焦点，不删证据；不规定所有场景同一字号，也不把所有内容压成几个关键词 |
| 页面组织 | 让主内容直接成为画面。新解释镜头不默认加左上角标题、章节号、横线及固定“标题＋正文区”骨架 | 左对齐可以成立；真实软件标题栏保留；当前重点本身是一句大字时，它是内容。避免的是每幕都套PPT页眉 |
| 胶囊与卡片 | 实心黑底白字，或白底深字配柔和阴影；以填充、留白、投影区分层次。自制胶囊/软卡默认无黑细线、灰细线描边 | 白色承载面不能因去描边而消失；设备轮廓、真实截图与必要图形笔画不属于装饰描边禁令。长文不硬塞细长胶囊 |
| 总结与提炼 | 已建立的材料后退，以黑/白半透明蒙版和适当失焦降低干扰，清晰前景接走结论；按需要恢复原材料 | 毛玻璃是“材料→判断”的关系，不能用纯色页替换背景后声称保留上下文，也不要求每段都加蒙版 |
| 色彩 | 黑白为主体，灰用于退后层；紫色集中在当前关键文字、选中状态或有信息职责的局部模块。一次选定本片accent及主题参数后复用 | 不把紫色铺成整片氛围、整块大背景、所有卡片、整段文字或发光染色。历史keep不代表其所有色值都是新片默认 |
| 图标 | 默认不放装饰性icon。用户已确认：真实产品Logo可表达身份，实操录屏的原生图标保留 | 不给每张卡都配一个象征性小图标。PDF/文档/音频文件和波形可表达真实输入对象及文件类型，配准确名称；它们不属于装饰icon。实际公式或判断符号有含义时可保留，不能替代需要解释的过程或真实文件内容 |
| 线与箭头 | 流程/胶囊关系优先用先后出现、空间归组、同一对象移动、选中/退后和内容接力表达 | 不默认画连线或箭头。确需表达不可替代的拓扑、轨迹或数据关系时少量用，并检查是否真帮助理解；不按固定线条配额设计 |

规范站与示例界面同样使用白底、黑白实体模块和柔和阴影，不以灰色大底、灰色面板或灰色卡片建立层次；少量次级文字、真实素材及黑白半透明遮罩按各自职责使用。规范、可操作组件、完整视觉库、准确源码与取舍操作统一在同一站内，日常使用不需要跳回旧视觉库前端。

## 3. 用关系组织动作

设计时先回答：观众已认清什么，接下来哪种关系发生变化，什么时候需要读完，下一段接走什么。动作不从“随机挑一个入场特效”开始。

| 内容关系 | 可复用的动作逻辑 | 质量锚点与适配要点 |
| --- | --- | --- |
| 当前观点交给下一观点 | 当前对象缩小/侧移保留上下文，下一对象接管阅读区；需要总结时重新归组 | T01、T02；文字、外壳、圆角作为同一对象协调。上下左右都可变，不能只缩外壳、不处理文字 |
| 一个概念展开为若干任务 | 先认清整体，再展开实际子项；处理/选中发生后收束结果 | 99-02、99-20；保留建立→展开→判断→收束，不继承三项/六项配额、固定列数或旧文案 |
| 比较与逐项讲解 | 共同条件保持一致，当前项突出，旧项退后，比较对象身份仍可辨认 | 95 row12、T05；变化发生在主次与证据，不能把比较机械画成上下游流程 |
| 给主体补充解释 | 主体保留身份并让出空间，新信息进入；解释完按需要回中或接走 | 99-09、T02；先测真实内容的空间，不为了配旁注无限缩小主体 |
| 从设备看清内容 | 内容从同一屏幕区域放大成为主体，外壳让位，媒体时钟保持连续 | 99-13、T10；绑定真实屏幕框和播放时间，不突然重播或换一张近似截图 |
| 从材料得出判断 | 材料保持身份，黑白蒙版/失焦让其退后，结论在前景读清；再决定返回或交出 | 95 row04、99-21、T07；背景、蒙版、前景独立，模糊不能作用到重点和品牌 |
| 输入、回答与持续阅读 | 输入过程可逐字；完整判断可刷出；补充词可淡入退下；对话组可上卷为新回复让位 | 95 row30、W01–W05；选择依据是文字职责，字幕仍是独立层，不要求每句换一种效果 |

“建立→变化→阅读→交接”是思考问题的方式，不要求每段完整演一遍；上游已建立就直接承接，结论可停在一句大字，稳定阅读不需持续漂移。

### 动作与镜头的共同约束

- 进入要让对象及时可辨认，移动和缩放要有目的地，落定后给足阅读。退出的任务是清楚交出注意力；入场和退出分别按建立与交接职责选动作，不默认完全镜像；当前指定原版轨迹优先。
- 同一运动组保持速度感和完成顺序协调；强调、载体搬移、文字揭示可用不同缓动。不要为“风格一致”把所有动作换成同一个spring，也不保留无理由弹跳。
- 一次变化有主要阅读焦点。旧项尚未退出、新项进入可以重叠，但两段主文字不能意外争抢同一区域。不能用单张终态图证明没有叠字。同级白字检查每项首个可读帧，不能因默认样式或继承透明度让后一个意外变灰；有职责的逐字显隐仍可使用。
- 相机推近服务可辨内容，横移服务焦点交接，回全貌服务重新理解关系；阅读时停稳。不要用全程慢漂移填时长，也不强制相机永远不动。
- 用口播的实际词组确定触发与阅读窗；快动作不等于快闪，读不完就改分组/时序。已有声音需与动作同步，不能每个小变化都加声。
- 连续对象在相邻场景保留身份、几何与媒体时间；话题真正改变时直接切换也可成立。不要求所有边界都变形或刷屏。

## 4. 模块不是一张固定尺寸的图

同一模块至少拆清三种责任：**内容是什么、怎样承载、怎样随时间变化。**

- 内容：本期文字、真实媒体、对象/项目数量和关系；不能藏在组件内部旧常量里。
- 承载：黑白表面、字阶、间距、可读区域、适用字幕避让；让主题统一决定外观，不在每个场景手写一套近似阴影。
- 动作：进入、阅读、强调、退出及交接的状态与cue；移交新文本/媒体时保持该对象的连续性。

原子组件可组合成关系模块，再由本期场景把关系模块与录音、媒体、品牌、字幕接起来。总结不强制胶囊，流程不强制节点线，媒体不强制设备框。使用成熟完整模块仍是优先选项，不能为了抽象而拆坏其已成立的动作。

**画布利用与局部避让：** 正文的布局起点应给内容足够面积；不要把示意用的安全框当成不能跨越的硬边界，也不因右上角有角标就封掉整条顶部、因一条字幕就永久封掉整个底部。全屏媒体可铺满，关键文字与主体按角标实际占用、字幕当前cue的真实宽高及运动路径局部协调。字幕未出现时可使用相应空间，出现时重新检查。规范站示例里的边距只说明一种构图起点，不成为跨期固定比例；真正需要读的材料宁可展开、分阶段或聚焦，不因过宽预留把内容缩小。

**分辨率适配与内容适配分开：** 在1920逻辑画布上整体缩放到4K，可以保持几何；它不会自动处理更长的中文、多一个节点、竖图变横图、双行字幕。后者需要内容测量、布局重排或分阶段呈现，不能仅把整组缩小。

现有代码能力、真实props、固定条件与未完成项见[组件复用图谱](references/component-reuse-map.md)。文档中的设计分层是调用与后续抽象方向，不表示已经新增了一套统一React组件包。

## 5. 没有现成组件时怎么做

1. 先用一句话定义观众要看懂的内容变化，按上面的关系选构图与动作，不先画卡片网格。
2. 选择相关的表面/文字/动作质量锚点；可只借动作关系，外观按本规范。没有借代码就记original和anchors，不能冒称复用了原组件。
3. 在原有`styleContract`写本镜具体决定：surface、typography、geometry、motion、camera、mediaBehavior；例如谁退后、谁接管、如何读完。不能每镜粘贴同一份“黑白简约”。
4. 用本期真实最长文字、素材和字幕做关键帧，覆盖建立、最拥挤中间态、阅读终态与接缝；Fred确认后按既有流程内部看动态。
5. 对照锚点检查有效内容面积、字阶、表面层次、动作关系和阅读节奏。符合色彩不代表达到质量；技术PASS也不等于视觉通过。

把当前设计决定留在一份Manifest中，不新增一套设计审批或第二份逐段计划。只对真实影响的画面和交接复核；已有保护范围继续保留。

## 6. 看画面时实际检查什么

- 这句新增了什么可见信息或状态，观众能否跟上同一对象？
- 是否有可删除的眉题、小标签、装饰icon、细描边、线条和大面积紫色？
- 在实际观看大小下主文字能否读清；密集材料是否有清楚的阅读顺序，而非缩到“放得下”？
- 表面、文字、阴影与运动是否属于同一对象；中间态是否拉字、叠字、裁切或退场残留？
- 毛玻璃是否保留了有用上下文；重点和角标是否清楚；字幕实际出现窗口是否遮住关键前景？
- 前后段是否连续，稳定阅读是否足够；变化是否来自内容，而非为避免“单调”不断换效果？

这些是实际观察问题，不是增加几个布尔值就能证明美观。
