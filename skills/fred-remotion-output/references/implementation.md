# Remotion实现与依赖

首次建立本期实现环境时读本文件；制作某个场景时读该场景小抄。已有环境未变化不重复读取。具体画面问题仍不清楚时才查 [画面诊断](visual-quality.md) 对应小节。需要 Remotion API 时读项目 Remotion Skill，项目文档缺失才查全局文档。

- 代码从 Manifest 派生镜头顺序和 cue；所有动作由确定的帧时钟驱动，不使用真实时间、未固定随机数或 CSS 自行动画。多场景必须遵守 Manifest 的 `clockContract.mode=scene-local`，在组件内使用 `localFrame = frame - scene.startFrame` 或等价的场景起点序列；未经说明不能用全片 `frame / FPS` 驱动段内动画，也不能让所有 `Sequence` 从 `0` 开始。
- 先明确 `full-remotion / hybrid-repair / image-driven`。播放保留视频是有效媒体复用，但不冒称全代码重建。
- 精确组件从依赖清单定位，复制到本期独立适配；冻结原版与硬链接依赖不原地修改。保存引用 ID、hash、参考片段范围、真正挂载的源码符号和修改范围。
- 原文、图片、录屏与字号均来自本期；示例文案、旧期时间点和整套布局不作为默认内容。图片/录屏使用实际来源，构图参考不能冒充操作证明。
- 字体加载完成再测量和渲染；优先保持当前认可工程的实际字体文件与字重，同组统一。新工程可从MiSans Medium/Semibold起步；指定参考字体或用户另选字体时按准确来源实现，不因默认字体拒绝。字体改变后重新测量换行，不用拉伸字符适配宽度。
- 原版 30fps 与本期 60fps 按秒/帧重新换算；代码中固定 FPS 也要处理。设计到输出只做一次整体尺寸换算，不能两次放大字号/坐标。
- 默认独立横版为 16:9，预览 1080p，正式 4K60；用户规格和当前已认可工程优先。关键前景避开合同中实际字幕、角标与播放器安全区；底部约六分之一只作为需要该字幕带时的起点，无烧录字幕时不机械保留同样空带。全屏遮罩覆盖整个画布；FredTalk横版讲解默认用`brand-corner`沿用已认可品牌规范，其他范围按production-defaults.md处理；不自动套 Deck 标题、装饰条、翻页或紫色竖版模板。

新制作默认先完成覆盖实际风险的少量代表镜头，审看按本轮约定；有限返修只检查目标及受影响接缝，不重做未改代表镜头。代表镜头按本期实际存在的内容选择，例如：最长原文与跨行高亮、最大特写、设备接管、分支初态及复杂交接。检查并修好这些问题，再扩展完整视频；不把每种库效果都做一遍。
- 实现模式可用 `reference`、`adapted`、`original`、`preserved-media` 或 `talk-only`；原创场景必须遵守 styleContract，并作为代表镜头风险覆盖项，不得以“库里没有”作为无记录的自由发挥理由。
