# 反馈、方案与组件持续维护

制作路线与选图流程维护在[路线与选型](route-and-storyboard-review.md)。用户授权保存本轮候选不等于批准每张图或动画；方法、候选、助手预选、用户选择分别归因。单期比喻导致的3D偏航用于路线检查，不升级成禁止某类场景的规则。

只有用户要求沉淀偏好、整理组件或本轮确需更新公共方法时才读本文件。日常制作读当前场景小抄；单期反馈记入本期即可，不每次重新审计整套规则。

## 每次接手与每轮反馈

现有跨期判断见 [历史偏好与防错规则](feedback-rules.md)；结构化源为 `feedback-rules.json`。每条保留触发场景、喜欢的关系、要避免的症状、不要泛化的边界、检查方法和原话出处。规则修改后验证 `scripts/verify_feedback.py`，运行 `scripts/build_reading_guide.py` 重建规则阅读版与完整说明，再同步全局轻量文件。证据验证不代替视觉审看。

本期保留一份当前 Manifest 与交付索引，反馈写现有修订清单或 `feedback.jsonl`。每条记录应能定位：用户原话及消息来源、所指文件/hash、时间范围、问题对象、保护内容、本轮调整、实现版本、检查证据、结果与仍待确认内容。 同时读取按钮判断与文字意见；keep/approved与明确待改内容并存时，不能直接登记整段认可。方向选择、真实关键帧确认、内部动态检查和最终视频认可分别绑定实际产物。

没有用户消息精确时间时记 `recorded-at`，不把执行时刻伪装成发言时间。不要覆盖旧反馈或把反复修改压缩成“用户喜欢此风格”，导致不知道最后取舍了什么。

新认可按当次明确范围记录；旧批评保留日期与版本，不继续冒充当前状态，也不倒改所有历史版本的认可。

历史复核新定位到准确原话时，在本次审计保存原始路径/物理行/实际时间和摘录，不倒改旧认可事件。按当前要求、最新准确选择、同一对象后续取舍判断；助手诊断单独标记。不同版本、阶段或用途的意见不能互相无条件覆盖：例如反复毛玻璃与适量重点蒙版、早期解释动画与后期真实产品截图、同轮统一与跨组变化。

用户要求整期复盘时，从当前场景清单串联早期关键帧、各轮真实意见、最终实际画面和实现调用，包含无备注的保留段及明确删段，不能只总结最后一轮投诉。旧目录缺失时保留归档原话与执行回执，标出无法重读的图片/源码范围；不按目录名推断版本。逐段抽帧对照属于静态抽样复盘，连续动态、声音听审和技术验证各自记录。经验优先补已有规则的触发、检查与边界，单期参数、选图和失败过程留在本期证据索引。用户明确要求跨期固定复用时保存对应公共组件、准确参数与授权范围；108 v9主播放外壳的当前默认见[全屏主视频组件](fullscreen-video-window.md)，不继续将这项明确偏好限制为单期参数。

评价“返修少／这次更好”时，区分用户主要创意返修、同轮局部补充、助手内部修复与上游组件研发；版本桶数不直接等于返修轮数。结合实际修改范围、素材准备程度、成熟模块承担的内容和新设计难度判断原因，不能仅凭轮数归因于流程改善。沉淀可复用的决定与检查，不设“每期两次”的目标，也不把本期现成媒体比例、场景数或组合固化；既有成片与批准状态不因复盘改写。

## 状态分开保存

| 状态 | 可以依据什么写入 |
| --- | --- |
| generated / rendered / downloaded | 实际任务返回、产物与本地校验 |
| internal-reviewed | 助手实际检查范围、方法和证据 |
| user-accepted | Fred 的明确认可原话及准确对象/范围 |
| source-preserved | 源文件、依赖和 hash 已核验 |
| parameterized / build-passed | 新 API、不同参数与构建检查 |
| reusable-visual-reviewed | 新内容短样的实际视觉检查；单独记录是否获用户认可 |
| sent | 实际发送目标、文件身份和回执 |

整个组件、某个局部动作、首帧与完整视频的认可范围不同。默认继续尊重选片台的 keep/optional/drop；本期“可以用”不自动覆盖已有公共排除项。

## 何时沉淀新公共能力

Fred 已授权持续沉淀，允许把通用修复和可复用方法保存成候选；用户喜欢的范围与是否跨期使用仍需真实依据。把当前源片路径/hash、起止帧、实际调用函数、依赖、可变参数、保留关系、已知限制与验证证据一并登记。

优先提取多次实际使用且重复返工的能力：跨行原文聚焦、ROI 多处特写、屏幕接管、关系线初态、同槽替换。参数接口随实际需求形成，不为每个旧片段创建一个名字相近但无实质复用价值的组件。

新适配用不同长度/换行的文字、不同图片比例、不同 cue 检查；参考帧复现只能证明该样例。修复线帽残点时留下进度零与第一可见帧的检查，修复跨行焦点时用跨行/重复词/长短词，而不是只增加一句禁止项。

新版本独立保存；旧项目锁旧源码和依赖。通过检查后更新轻量索引的“可用性”，用户实际认可后更新“偏好”；两者不互相代替。凡选择 revision 改变，先保存旧快照再更新 registry，不能直接改旧记录抹掉来源。

## Skill 维护边界

日常新视频不重写整份 Skill。单期素材与记录在本期，跨期候选在项目依赖目录，稳定通用判断进入本 Skill 的对应 reference；无需把完整聊天、视频文案或所有失败尝试塞进主文件。

用户要求沉淀 ChatGPT Pro 生图与复刻方法时，维护[ChatGPT Pro 分镜探索与 Remotion 复刻](chatgpt-pro-storyboard-replication.md)。沉淀触发条件、提示词、来源与认可边界，以及从多状态取舍、口播动作编排、连续对象、阅读窗口、真实媒体保护到局部返修和完整交付的方法；规划辅助使用[多状态动作模板](../templates/pro-storyboard-motion-plan.md)，写回现有Manifest。具体场景的原话、prompt、会话、图片hash、用户选择、实现文件、单期参数和失败过程留本期。聊天中提出过生图请求不等于图片已生成、用户已认可或已进入成片，必须以本期生成清单和实现证据分别确认。

复盘反复返工时，先检查已有规则是否实际到达执行者、当前动作是否混入旧版本、检查是否只覆盖字段而未对照真实要求；不要默认继续增加负面提示词。工具漏传字段或允许不可能配置时，以失败回归修工具；审美与语义问题用准确参考和真实输出对照。规则级修复不会追认旧画面，也不自动改写冻结成片 Manifest。当前要求传递与代表段做法维护在 `production-defaults.md`，不另起同义质量体系。

用户认可的完整模块与局部能力都可按实际用途沉淀和直接复用，保留准确来源与认可范围；不强制拆成局部，也不把整期搭配固化为所有新片的默认方案。按storyboard.md判断当前内容职责、动画推进和同等质感，不建立近期使用禁用表、冷却期或固定创新比例。

全局注册镜像主文件、references、脚本、模板；大资产和 node_modules 只保留项目实体。修改流程时同步项目 AGENTS/PROJECT 的入口，核对相关全局文件 hash。已停用的 Deck/H3 默认路线不因为一次调用专项工具就自动恢复。

本流程不自动改写 `~/.codex/memories/`；这里只维护用户要求的生产 Skill 与本期/组件记录。

## 按表达关系整理新参考

先将用户截图/编号绑定准确成片hash，再记录排除；同一条的多张截图只算一个选择。原片受到保留、复刻受到保留、新内容通用API通过检查三个状态分开。

在同一 `preferred-motion/catalog.json` 中登记新条目，选择来源保存在不可变 `selectionSources` 证据快照；依赖 registry 只锁路径/hash，不另建可独立改写的批准台账。旧 selectionRevision 继续指其原 picker，新用户事件用独立来源ID与catalogRevision表明，不伪装成旧选片台的新点击。

去重比较用途、主动作顺序、对象关系和现有参数；配色、圆角、胶囊只是表面。明确重复只保留一个默认代表，旧编号记录canonicalId；有差异却只是同名时保留不同能力。跨旧库合并要读实际视频和实际挂载源码，不只比名字。未实现的变体参数应标待适配。

加入新参考后补齐sceneTypes/useWhen/tags/sourceCode/依赖/限制，验证scene-type过滤、旧编号别名、drop排除、来源哈希变化拒绝、孤立源码构建、实体视频与素材哈希。同步项目和全局轻量Skill；大资产只在项目实体。最后生成可浏览文件架，不能只交付一份说明文档。

不同Remotion锁定版本要在独立进程中构建，不能把旧库4.0.519和V2/本批4.0.473加载到同一Node进程。`verify_source_bundles.cjs`按bundle启动进程；`verify_dependencies.py`另查完整素材库存、合法场景类型、合并目标和实际注册编号。沿用原库的选择计数单独核验，新集合使用当前聚合计数，不覆写旧选片事实。

## 局部过渡学习

对象缩放、让位和交接作为局部动作记录到transition-patterns.json，绑定原片内部起止帧、准确hash、源码位置、可迁移关系与已知限制；方向变化按变体处理。状态仍由同一catalog决定，排除和合并记录不借局部索引回流。新源片hash变化要重新检查。更新学习页与轻量查询后同步项目和全局Skill，不把示例时间硬编码为新期节奏，也不把未实现的参数称为公共API。

文字呈现维护在text-patterns.json：区分字符数变化、clipPath揭示、文字流translate、opacity淡化与数字插值。新形式补源片区间、源码机制及实际边界，不把文字载体移动误记成字形动画；正文组件入口同步链接这一份索引，避免复制批准状态或另起相同资产库。

## 完整组件与局部取舍分离

前端复看全部完成后，保存review revision、fingerprint、完整取舍与当时前端引用快照，核对后更新同一catalog的selectionSources/catalogRevision；保留旧picker revision和旧批准历史。整期选段以status记录排除并保留准确源范围，默认查询与前端只显示keep。局部明确保留可在源完整组件被排除时继续使用，但必须由对应文字/过渡条目的selection绑定用户快照、decisionKey和hash；只批准准确局部，不恢复完整组件。同步源注册、文件架、索引及依赖hash，归档已应用取舍，前端换到新库。

## 避免重复与历史规则膨胀

- `production-defaults.md`负责选型默认值；`storyboard.md`负责原文/时钟/分镜结构；`scene-routing.json`只映射类型与附加项；`feedback-rules.json`保存有证据且有范围的偏好；`content-to-component.md`负责源码归因与质量评估；`render-and-delivery.md`连接交付状态。专项实现细节只在其所属Skill维护。
- 主入口与阶段文档可做短摘要和链接，不复制另一套参数或硬门禁。`feedback-rules.md`和完整说明是自动生成视图，只改源文件后重建，不分别手改。
- 新规则先分清用户明确固定项、可覆盖的默认值、场景条件与历史症状。单次“不加某词”“五秒播完”“只改为白色”留在该期；只有跨内容仍成立的方法才入公共规则。旧批评保留版本与日期，不把历史例子的对象数、时长或布局变成全局禁令。
- 每次沉淀同时保留有效的相反取舍：过程需要变化，结论可纯文字；操作需要推进，阅读可停稳。新经验优先补已有规则的触发、检查和边界，不凭一次抱怨新增全局配额或审批。审美观察留在内部审看，只有可客观验证的问题进入代码校验器。
- 前端意见以`user-feedback`单独归因，保存原快照/hash、JSON位置、stableId、判断和所评版本；未知发言时间保持空值，以`recordedAt`表示取证时间。原话及单期证据留在该期，通过项目`00_每期项目`入口检索；不复制成公共批准案例。
- 文档说允许而脚本拒绝时，用最小案例定位执行范围；修正后同时保留允许案例和真实风险拒绝案例，不只删提示文字。代码门禁只陈述它实际验证的边界。

## 已授权静态参考包

Fred明确授权的imagegen新闻快闪组件[NMC01](news-keyword-match-cut.md)同时保存原始四宫格、裁剪单页、对齐/蒙版参数、准确动态样片、生成提示词模板与声音来源。静态素材是已认可动态组件的依赖，不能只保存一份描述文档；不把换词后的生图或换时序后的混音追认为用户已看过。准确本地集合与同一catalog/registry绑定，新素材仍独立检查。

用户明确要求跨期保存的静态分镜，可按[分镜图工作流](storyboard-image-workflow.md)保存项目实体、准确提示词、hash与认可范围；依赖registry登记定位，包manifest保存唯一认可事件。静态图不强塞进动态组件catalog，不继承动画/API批准；未授权的新单期材料继续留本期。
