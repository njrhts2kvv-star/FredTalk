# 从图文建议到关键帧，再到视频

当前交付遵循[组件库交付门禁](library-delivery-gate.md)：默认认可组件复用/二创，原创须当次场景授权；历史探索说明不覆盖此约束。

这是新一期默认协作方式。Fred提供稿件和已有素材，助手先构思并给出可看的建议；已有明确选择、局部返修及当前直出授权优先。全部状态沿用一份当前Manifest和同一前端，不新增平行时间线。

## 1. 接稿与图文建议

读全文，按语义责任拆段，保留完整sourceSpans、stableId和实际cue。没有录音可以估时规划；最终录音到位后更新动作、字幕、音效及受影响接缝。

同时读取用户已给的完整制作要求，按[当前执行包](production-defaults.md#将要求落实到当前执行包)保存仍有效的决定。详细指令已经存在时，不归因于“用户提示词不够丰富”，不再要求用户补一篇总指令；若确有冲突，只定位影响当前选择的具体一项。

第一版页面每段已有：原文/音频、这句要讲清什么、建议制作方式、准备怎样变化、图片或可播放参考，以及推荐理由。助手先形成跨段的整组建议，Fred修改并选择。不得以空白路线表代替构思，也不将默认选项当用户确认。

制作方式用录屏、Remotion动画、AI生成视频、混合；工具与风格分开，卡通/写实不是生成工具分类。已有cartoon记录保留其原意，接手时依具体要求明确使用方式。H3/Seedance等按实际素材与授权走专项分支，不因选中路线自动获得外部上传或付费授权。

## 2. 选方向：先看可实现的真实参考

现有组件能表达时，展示准确参考片段截图/可播放片段，写清保留的动作关系、本期替换内容及适配风险。完整成熟模块适合就复用，不强制拆小，也不以引用一个Pill冒称继承整套动画。

没有准确表达或用户要比较构图时，再按[分镜图工作流](storyboard-image-workflow.md)生少量有意义的候选。候选图负责表达/构图，真实组件负责精确字体、几何和动作。整组比较主次与承接，不设固定方案数、设备数量或同构配额。

在同一页面展示助手建议、候选及用户选择；允许选整套、选局部、重做或直接按对话方向执行。用户选定后才能推进受影响新Remotion段；明确部分可先做。修正生成图的伪数据、无意义小字和样式偏差，但不能偷偷换掉已选的表达关系。

## 真实关键帧

按已选方向实现真实Remotion组件，再由同一工程渲染关键帧。此时先解决画面，不急于完整视频渲染。带入本期真实文案、媒体、字体及适用字幕/角标；不要再次生一张图片冒充代码输出。

按实际语义选建立、重点变化、可读结果、最挤/最长文字、运动危险中间态和相邻交接前后。可密集浏览和逐帧填意见；不固定140张，也不只给每段最后一张定格。展示原文、时间和修改前后对照。

在原口播行的画面素材区呈现对应关键帧和当前版本，旁边直接编辑画面说明/备注；放大时仍能看到本行口播和意见入口。针对某帧或视频时间的意见附帧号/时间/版本。不能只交独立图片墙让用户自己找口播，不能拿旧视频审看新关键帧；当前任务只要求图片时不擅自生成视频。

Fred的关键帧确认仅确认所示画面；不等于动画、音效、口播对齐或全片认可。已有最终录音时在关键帧前锁定真实cue。确认后助手完善动态并内部正常速度检查完整语义短段与受影响接缝，再渲染整片，默认无需再等用户批准动态样片。必须改变已选方向时只说明该冲突；不重复询问已明确决定。

## 4. 完整视频与局部返修

按[渲染与交付](render-and-delivery.md)调用现有共享门禁和已授权渲染方式，完成下载、技术校验及当前交付指针。新版更新同一页面，保留旧反馈；新文件不能继承旧文件的已看状态。

同时理解按钮结论和具体意见。“保留主体但这里要改”不能简化为整段通过，“暂不处理”不抹去已写的修改要求。修改文案、播放、外框、品牌、字幕与音轨时分别确定保护范围；只补受影响段及真实依赖它的接缝。

## 外部视频交接

其他任务生成的H3/Seedance视频或录屏，沿当前mediaContract登记路径/hash、来源用途、有效入出点、帧率和音轨；记录是否自带字幕/角标、允许裁切/设备包装、与口播的映射及首尾对象状态。只有Prompt或首尾图不算已交付视频，生成内容不冒充真实操作证据。

真实素材先承担信息，Remotion只做需要的包装、动画、字幕/品牌和合成。没有合成需求的素材不强迫重建。H3细节按既有h3-handoff读取；通用接收合同适用于用户从其他任务提供的生成视频，不自动执行生成。

## 数据与版本

新一期根设置 `workflow: {profile: "fred-video-v2"}`；当前明确直出或有限返修可设置 `workflow.authorization: {mode: "direct-output"|"bounded-revision", source: "准确用户消息或授权记录"}`。这是当前授权记录，不是助手自授许可。旧工程保持原有合同；不擅自给历史工程补虚假批准。

| 字段 | 作用 |
| --- | --- |
| pages[].productionRoute | suggested、suggestionReason、selected、source；mixed可加subspans。新路线为recording/remotion/generated-video/mixed |
| pages[].storyboardReview | candidates[{id,imagePath,sha256,clipPath?}]、assistantRecommendation、userSelection{candidateId,sha256,scope?}、status、confirmedSource。无图片的已明确方向可用directionNote+confirmedSource |
| pages[].keyframeReview | frames[{id,path,sha256,timeSeconds,label}]、status、confirmedSource、confirmedFrames[{id,sha256}]、sourceFiles[{path,sha256}]、contextSha256；保存真实图与本镜源码、语义、媒体、字幕和品牌上下文 |
| 根subtitles | enabled、sourcePath、sourceSha256、cues[{startSeconds,endSeconds,text}]及现用几何/字体；启用字幕的代表门前须导入真实cue，有SRT路径时校验其hash |
| 根brandCorner | enabled及当前规范引用/深浅安排/几何；不改动认可资产 |
| 根outputSpec | width、height、fps、audio(required/none/optional)，由当前交付规格确定 |
| 当前review/feedback等 | 用户原话、受评文件与版本、保留范围、待改项和处理证据；不以标签代替阅读备注 |

关键帧contextSha256由 `workflow.py --stage signature --manifest <path> --scene-id <id>`生成，绑定本镜文案、方向、媒体、时序和字幕/品牌。sourceFiles列入实际影响本镜的源码/字体/配置；修改这些文件须更新关键帧并核对受影响选择。confirmedFrames保留Fred当时确认的图像身份，不随重新渲染自动刷新。晚到录音或后续动态修改时，重新取受影响的真实关键状态；若所示图像hash与已确认图完全相同，可记录内部复核说明并刷新sourceFiles/contextSha256，保留原确认来源，无需再次询问。图像变化则只将受影响帧标待确认；当前直出授权仍可覆盖等待。不得只改hash冒称重新渲染，无关镜头不重问。

`workflow.py --stage planning`核对方向选择和候选身份；`--stage representative`核对正常新制作的真实关键帧、来源文件与确认记录，生产gate调用同一函数。它校验文件和记录，不能证明用户身份、审美或实际动作；准确原话仍是确认依据。

前端按[审看页](segment-review.md)生成建议/关键帧/视频视图，能保存与导出，但浏览器保存不等于已回写Manifest。Agent读取导出，逐条检查原话及版本后回填；同名文件更新不得继承批准。授权覆盖用户等待时保留未审看状态，内部必要检查照常执行。
