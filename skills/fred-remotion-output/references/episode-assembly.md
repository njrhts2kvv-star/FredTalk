# 整期编排：把组件串成一条视频

组件做得好，不等于整期好看。114 期 v1（2026-10-12）组件本身被 Fred 认可，但 21 段里 19 段要返修，问题几乎都出在组件之间：录屏原样干播、慢推和定格凑时长、同一组件反复出现、紫框/黑框、段与段硬接。v2 按本文件的规则重做并先出关键帧后，第二轮只剩 6 段小改，第三轮只剩 1 段。

本文件管整期层面：做分段工程、给写画面代码的子任务写简报、出关键帧前、渲染前都要读。单个组件的写法看 [DESIGN.md](../DESIGN.md) 和 [动效手法](motion-craft.md)。

**先看 [好坏成对样例](paired-examples.md)**：118 期同一句口播、同一份素材，做对和做错各长什么样（8 组对照图）。下面的规则大多能在那里找到对应画面。

## 0. 113、114 期为什么能做到 90–95 分

114 v2/v3、113 v1 是目前质量最高的两期（Fred 给 114 打 90–95 分；113 是同一套做法，录屏还没补齐，尚未打分）。2026-10-13 对照源码、简报和返修记录复盘，好在这几件事，新一期照做：

1. **先设计“这句话怎么被看懂”，再找代码。** 每段先写“观众要看懂的变化”，把它落实成具体对象的状态变化：谁出现、怎么变、变完留下什么、交给下一段什么。例：113 讲开源和闭源用一本菜谱——“厨房在别人那里”推近后厨，“按份付钱”点菜单出价签，“菜谱拿不到”推近锁住的菜谱；下一段同一本菜谱开锁、盖公开章、变成模型文件下载到自己机器。114 讲 ZIP 和 clone：同一个源头分出两份，ZIP 那根线断开，作者从 v1 更新到 v2，更新只沿 clone 的线传过去。反例是 114 v1：按关键词找“像的”组件，出现一拆多用了多合一、没有赢家却用胜负比较、只标菜单位置没解释 clone 机制（见该期 `qc/组件重选-v2.md`）。
2. **为本期内容先做组件，再做片。** Fred 在 114 点名的 T04e、T05h、T05i、T17c、T09l 都出自第三轮新做组件；其中 T04e、T05h、T05i、T09l 是按 114/113 口播专门做的（`components-wave3-20261012/qc/specs.json` 的 `note` 写着对应哪一段），T17c 是同批的通用文件树。Fred 在视觉库挑过，再进片子。所以进片子时内容、对象和动作已经对得上。做法见[新做组件流程](new-component-workflow.md#本期驱动先为这一期做组件)。
3. **场景为本期重写，复用深入到动作层。** 113 工程拷进了 50 个原版组件，场景一个都没直接 import，而是把需要的动作拆进本期小件；114 实际运行的组件也主要是本期适配版（如 `v2b-T05i-UnboxResult`）。原样串组件，每个组件都有自己的开场和收尾，会不断重置观众正在看的东西。底层（kit、字幕、角标、音效、坐标映射）照用。
4. **时序跟真实口播走。** 用 `cue(段, n)` 取本段第 n 句的真实起点：说到“下载”文件才变，说到“放到自己的机器”机器才进来。先到位（0.4–0.7 秒），再给阅读时间，再响应下一句。
5. **转场写进代码。** 一个对象持续换角色：113 推荐“租机器”的答案卡长成器灵字标再分成四步；114 下载下来的代码卡变成文件夹，再接到结论胶囊。工程上共享上一段的几何常量、绘制函数或末帧取值时间（114 S14 直接取 S13 末态继续变形）。
6. **长段靠一条动作链撑住。** 114 S15 约 31 秒：结论胶囊 → GitHub CLI → 长出钥匙 → 插进 Codex 卡 → 卡长成真实界面 → 验证码交到浏览器 → 已授权按钮变成钥匙头 → 解锁下载、上传、建仓库。为一段写几百行代码是合理的，不用先做成通用接口。
7. **质量是返修收出来的。** 114 v1 21 段 19 段返修；v2 关键帧两轮后剩 1 段；成片后又改了 3 处和全片音效。检查要具体到段号、秒数、证据图和改法。例：113 第三轮复检发现首尾帧吻合，但接缝后 0.1–0.3 秒仍有灰糊和溶解（`ep113-v1/qc/round3/report.md`）——这种只看首尾帧查不出来。
8. **一个人掌握全片，其他人拿具体简报。** 写代码分组并行可以，但主会话定全片交接表、看所有检查报告、做最终判断。单纯加 Agent 数量得不到这个效果。分组时每组只渲到自己的目录（如 `qc/self/A`），推前端的汇总目录只由主会话写；116 期一组清空了公共目录，删掉了别组的关键帧。

工程结构直接用 [整期骨架](../templates/episode-skeleton/README.md)（时间轴、段外壳、交接几何、分块渲染、音频和 BGM、推前端都已写好）。骨架的 `src/components/episode-kit/` 带着 117–121 期沉淀的共享件（`ep.tsx`、`ckit.tsx` 在 119–121 期逐字节相同）（真实比例 `CodexBox`、黑胶囊 `BlackPill`、毛玻璃 `FrostFocus`/`FrostLayer`、章节头与五种章节过渡、大播放窗片段 `ClipWindow`、来源小字 `SourceTag` 等），Fred 挑过的毛病已经在里面修好；直接用，只换每期的常量，不要重画近似版。新一期的 `render/`、`tools/` 脚本**从骨架拷，不从上一期工程整拷**：上一期工程里常是修复前的旧拷贝，会重踩骨架已修好的坑（121 期从 120 拷，又遇到 AAC 拼接错位和 `.bgm.json` 不让覆盖）。场景写法、共享件可以参考上一期；确实拷了旧脚本时，先搜上一期编号（如 `grep -rn "ep117" render tools`）改掉远端目录名（118 期曾同步进 117 的目录并 `--delete`）。


## 1. 整期首版的顺序（不能跳）

1. **先有真实录音和字幕。** 没有最终录音时，只做到关键帧，不出整片。按语速估出来的时长会逼着画面用慢推、定格去补时间（114 v1 的 S17 就是“为了凑估算时长停顿偏长”）。
2. **逐段方向**：按现有流程走建议页和 `library_gate.py`，录屏段也要写清“怎么包装”（第 2 节），不能只写“播放录屏”。
   - **写代码前先填逐句动作表**（[简报模板](../templates/episode-assembly-brief.md)的“逐句动作表”；整期简报范例见 [120 期简报](../templates/examples/brief-ep120.md)，它是逐段写法，逐句表按模板展开）：每句写对象、变化、证据位置、观看焦点、交接对象，并过完表下的五条自查。先定“这一句让观众看见什么变化”，再选组件；不要先选组件再往里填字。
3. **段间交接表**（第 3 节）写进本期简报，写代码前定下来；几何写进骨架的 `src/components/handoff.ts`，两侧 import 同一个常量。
4. **关键帧进前端**：每段至少有首帧、末帧，以及每个交互状态停稳时的帧；带真实字幕条和角标。Fred 10-13 要求关键帧比停稳帧多约 1.5 倍：每个主要动作再补一张中间态（砸下途中、展开一半、交接变形途中），note 写明是哪个动作的中间态；人物动画 B-roll 每段只要 2–3 张。用骨架 `tools/stills.mjs`（`SCALE=1` 出全分辨率）和 `tools/push_keyframes.py`（按 `keyframes/plan/Sxx.json` 的说明推前端）。
5. **Fred 确认关键帧**。要关键帧还是直接出片，按 Fred 当次要求执行，不额外提醒；没有说明时先出关键帧。直接出片时，第 2–9 节的规则和自检照样执行。
6. **动态自检**：渲染预览分段（1080p 即可），跑 `motion_audit.py` 和 `readability_audit.py`（第 8 节），每条结果要么改掉，要么写明豁免理由。
7. 再推 4K60 正式渲染。

## 2. 录屏段怎么包装

录屏是证据，但不能整窗原样播。

- **一进来就能读**：画面里要读的字 ≥ 24px（1080 逻辑画布）。整窗缩进大窗时字只有约 10px，必须推近到正在发生的区域（常见 1.6–2.4 倍）。118 期 S04 就是这样：60 秒以后推近真实录屏的搜索下拉（约 2 倍），结论数字用窗内黑玻璃加大字；46–55 秒原版素材里没有对应画面，才重建示意切换器（见[成对样例](paired-examples.md)第 4、5 组）。第三方录屏原样整窗播放 20 秒是 118 期 Codex 试作最大的失分点。`readability_audit.py` 会把“连续 3 秒以上满屏都是小字”报成阻止项。
- **镜头跟着口播走**：讲到哪里推到哪里。每次移动约 0.6 秒到位，停稳读 0.85–1.65 秒，再走下一处。单次移动超过 1.4 秒就是“慢推”。
- **纯滚动不超过 2 秒**；第一帧就开始动，不先静止再慢慢滚。长页面先跳到要讲的位置，或用长图加镜头定位。
- **每 2–3 秒要有一次可见变化**：点击、输入、结果出现、组件接管、镜头换焦。没有新变化就加组件或剪短，不拉长画面。
- **交互要演出来**：
  - 点击：光标移过去、点击环、按钮状态变化，配 click 声；
  - 输入：对话框弹出，打字机跟口播打出，再点发送，配 typing 声；
  - 复制：地址整行用局部蒙版或阴影抬起指出，光标点右侧复制按钮，图标变勾“已复制”；
  - 等待：用 T09n 快进，或直接跳切，不原速播放等待过程。
- **优先调用已有录屏组件**：CAM01–05（3D 录屏运镜）、T09a（镜头跟光标）、T09d2（发任务后步骤依次完成）、interaction-codex-full（Codex 输入框浮起发送）、T08b（长页滚到重点）、T09l（复制地址交给 AI）、T09i（按条件选中一行）。
- 录屏只截口播讲到的那部分；不要把前一段对话带进来（114 v1 S16 开头误带入了 CLI 授权对话）。
- 平台风险照旧：Codex 输入框左下的“完全访问”用实心块遮住，“群聊/加群”和真实密钥不上屏。
- **画出来的 Codex 输入框照真实截图的比例**（118、119 期 Fred 10-14，原话：“框比较大，这儿也比较大……有点宽，有点扁，就跟正常的不是很像”）：一行字约 860–960 × 140–176，两行再加约 44；圆角约 30、字号 30（不超过 32）；底栏左边“+”，右边模型名、麦克风、黑色发送钮；“完全访问”不画。Codex 标识约 44 号，放在框左上方、和框左边对齐。不要再用 1100×210、1400×270 这种大扁框；超过 3 行时框里只显示最后几行，表现“往上滚”，不把框撑大。参考实现：118 期 `ep118-v1/src/components/ckit.tsx` 的 `CodexBox`。**框里的模型名照 Fred 当前真实截图填**，组件里写死的是旧期的值，不凭记忆填旧型号（Fred 指出过“已经没有 GPT 5.5 了”）。
- **案例挑能看见结果的**（118 期 Fred 嫌“复刻 Windows 计算器”不够吸引人）：优先有可见成品和硬数字的案例（如“4 分钟复刻 Obsidian 快速切换器”，作者自述的数字上屏要能看出出处），去 YouTube、GitHub、抖音找公开演示下载回来，素材授权按现有规则处理。第三方视频在画面左下加“来源：…”小字；没有原版界面录屏的部分画示意图，不冒充真实界面。换案例要连带改稿、只重配那一段（见 fred-voice-tts）。
- **先扫录屏里的凭证，再限定取用区间**（116 期）：Fred 的 Codex 复刻录屏中途有一条消息带 ssh 地址和密码，结尾露出服务器 IP。做法：先 1 秒一格抽帧把整段看一遍，记下凭证出现的区间；场景代码里所有取源时间的地方都经过一个函数（如 `srcAt()`）夹在安全区间内，任何一帧都不会解码到凭证；“完全访问”逐帧实心遮挡；渲染后再对该段所有关键帧和中间态逐张确认。报告和文件里都不抄写凭证本身。
- **商单录屏要看得出是在产品里**（124 期 Fred：“整个视频都看不出来是在豆包里面的无限画布里”“你不用担心左边出现其他项目的名字，这是 OK 的”）：默认保留产品识别——logo、侧栏、功能标题都露出来；只遮凭证和账号隐私（上一条），不为了画面干净去裁侧栏。每次进入产品，先给完整界面停一下，再推近到要讲的地方。产品 logo、功能名在全界面下太小（约 20px）时，第一次出现用 `Spotlight` 只压暗无关区域（产品主区域保持亮），在 logo 和功能标题下挂白色标签（如“豆包电脑版”“无限画布”）。同一种标注全片最多三四处，别每段都来一遍（见第 4 节）。
- **画布、白板、作品墙不要用拉远的全景录屏**（124 期 Fred：“只要展示无限画布的时候都很丑”）：缩到 2%–5% 时每张图只剩几十像素，四周大片空白，录屏又是 1080p，再放大就糊。做法：先在产品里把内容排整齐（同类同尺寸、等间距、接近 16:9），截一张高清截图（4K 视口）；镜头运动在 Remotion 里做，推近到某一区时换成同位置的原图，保证清楚。录屏只留真实操作（拖入、选模型、点按钮、生成）这类近景。
- **用户没录到的操作可以模拟，但要接得上真实录屏**（124 期“把照片丢进去这一段我没有录，你可以模拟”）：用真实录屏的静帧当底，模拟物（照片卡、光标）的落点对准真实界面元素的准确坐标（例如输入框里缩略图的位置），落定后无缝切回真实录屏继续播放。不重画产品界面，不做与真实画面对不上的假操作。
- **录屏取段挑完整、可读的状态**（124 期“不要有点击展开全部的部分”“用我划上去的片段，要不看不完整字体”）：输入框里的文字要能完整读到（选用户把文字滚回开头的那段，或文字全部可见的那一帧）；避开折叠的“展开全部”气泡、加载中、文字被截断的画面。没有现成的好状态时，就定在最好的那一帧推近，再用点击动作切走，不硬播到难看的状态。
- **背景录屏可以一直滚**（Fred 10-13，116 S02）：录屏只当背景、上面压着黑色半透明毛玻璃（约 45% 黑 + 背景模糊）和结论胶囊时，后面的录屏可以整段持续滚动，不受“纯滚动 ≤ 2 秒”限制；动态自检时用 `--allow` 豁免并写明理由。胶囊放画面正中（中心约 960, 470），不贴底。

## 3. 段与段之间：交接表

分段渲染再拼接，接缝最容易露馅。不要用淡入淡出、整屏左右平移、PPT 式划走。

- **上一段末帧 = 下一段首帧**：同一个对象、同一位置、同一尺寸，靠一个连续动作交给下一段。
- 写代码前，在本期简报里列出每个接缝的交接表：

  | 接缝 | 上一段末态 | 下一段首态 | 动作 | 音效 |
  |---|---|---|---|---|
  | S01→S02 | 第三个黑胶囊问题 | 黑幕中央开出圆角窗露出 B-roll | 胶囊放大铺满成黑幕 | woosh |

- 常用交接动作（按内容选，不套固定套餐）：胶囊放大成黑幕再开窗；卡片变形成浏览器窗口；页面压成一条线，再从线上展开；文件行抬起变成卡片；三张卡聚拢变成三个胶囊；前后景深交换（旧窗口后退缩小，新窗口从近处压上来）；输入框对输入框的匹配剪辑。更多见 [对象过渡](object-transitions.md)。
- 跨子任务的接缝（不同人写的两段）必须严格按交接表的状态，写清坐标和尺寸。
- **交接对象连画法一起共享，不只共享坐标**（116 期）：S08 末 / S09 首那张文件白卡，`handoff.ts` 只定了位置，两组各画各的，字号 44 对 36、图标位置也不同，接缝跳了一下。跨组交接的对象要导出一个绘制组件（如 `FileRowCard`），两侧都调用它；类别标签、章节胶囊这类反复出现的对象同理，字号和字体常量也放进 `handoff.ts`。
- 检查：渲染后看拼好的成片接缝前后各 0.5 秒的动态，不只比首尾两张静帧。

## 4. 全片组件去重

- **讲解结构类组件全片只出现一次**：路线图、方法卡、双身份卡、问答回答这类。后面再讲到同一结构时，换一种表达（大字胶囊、关键词卡、对应画面），不要让同一个组件重新入场。114 v1 的路线图出现了 5 次，Fred：“用过一次就换”“不想再看到这个”。
- 同一播放外壳、字幕、角标、连续录屏、同一画布的延续不算重复。
- 出关键帧前，把全片所有段用到的组件列成一张表，查重复。
- **呈现手法也要去重，不只看组件**（124 期 Fred：“1 分 26 和 1 分 39 都是同样的一套组件跟一套内容，看起来挺重复，而且跟最开始也挺重复”）：同一种运镜套路（例如“缩进产品截图 → 标注 logo → 推近某一区”），以及同一个画面状态（例如开头那块铺满的总览板），全片只完整用一次。后面再讲“全在一张画布上”这类同义的话，换一种演法：留在当前画面里拉远补满、在物料上画圈、色卡连线、把总览板拉远成画布上的一张卡、光标点开某一版等。Fred 点名要“回到开头那个画面”时可以回，但回来之后的走法要和开头不同。
- **章节页每期换着用**（124 期 Fred：“章节页记得换几个用，不要每次都用那几个，我组件库里有 20 个呢”）：骨架 `chap.tsx` 自带的五种（T12k/m/q/o/s）不是默认全套。选章节页前先看 [章节动画](fred-chapter-transitions.md) 的“各期已用”表，优先选最近两期没用过的，用完把本期编号补进表里。从库里复制组件时只把 `Frame` 底色改透明、压在段首约 2 秒，组件本身不重画。章节名要清楚可读 ≥ 0.8 秒，章节卡不能盖住字幕（字幕层在章节卡之上）。

## 5. 强调方式

- **不用紫色框，也尽量不用黑框。** 要指出页面上的某处时，优先用：
  - 局部蒙版：用 kit 的 `Spotlight` 把其余部分压暗（0.6），目标保持原亮度。**不用白蒙版加失焦**——114 S08 推荐句用了白色模糊蒙版，Fred：“最后有个蒙蒙模糊的蒙版，这很奇怪”；白蒙版加失焦只留给 DESIGN.md 的“材料 → 结论”让位；
  - 阴影抬起：目标区域浮起、加柔和阴影；
  - 毛刷高亮：从左向右刷过字下。
- **黑描边的节点方块也算黑框**（118 S09 Fred：“黑框这种组件很丑”）：讲“文字变成图”这类内容，不要自己画一排黑描边方块。直接用真实产物图（放在白卡里），用 `Spotlight` 按顺序逐个亮起节点，旁边标出清楚的节点名。
- 紫色只用于少量文字点缀（当前关键词），不做框、不铺底。
- **黑白毛玻璃要用，但别做成同一个套路**（118 期 Fred 原话：“现在全篇其实你比较少用……之前还是蛮喜欢的，但你现在是完全丢失掉了”）：
  - 次数不设上限，但同一个样子不要在相邻几处连用；变化来自这一句的内容：可以是一行字/胶囊，也可以放完整组件（卡片、被划掉的会员卡、浮起的产品卡），黑白交替，或者干脆不加蒙版（119 期 5–6 处连用同一套“毛玻璃 + 一行字”被嫌重复）。与 feedback-rules.md“毛玻璃的适用边界”、production-defaults.md 一致；
  - 白底画面不要压全屏黑玻璃，整屏会发灰（118 S08、S10、S11 第一版，主会话自查发现）。素材在窗口里时，黑玻璃只盖住这个窗口（按窗口位置和圆角裁切），字居中在窗口上；白底上的多张卡用白色磨砂（约 `rgba(255,255,255,0.55)` 加 18px 模糊）配黑字。只有素材铺满全屏时才用全屏黑玻璃；
  - 白磨砂上别叠超大的黑胶囊（118 S07 Fred：“这里大胶囊有点丑”）。需要胶囊就用正常大小，或者直接放大字、重点词用紫色或划线表达；
  - 毛玻璃背后的素材继续播放。参考实现：118 期 `src/components/glass.tsx`，119 期 `ep.tsx` 的 `FrostFocus` / `FrostLayer`。
- 胶囊、卡片和标签放在目标旁边，不挡住正在讲的内容。
- **装饰性、漂浮的小黑胶囊标签默认不用**（115 v1 审看有 4 段明确点名小胶囊“丑、单调”，并定为统一原则；125 期照此执行）：给关键词、卡片、划线配的小胶囊，改成直接在画布上排大字或数字（MiSans Heavy，分主次）、在真实素材上用 `Spotlight` 压暗再提亮、或者用图标。段落结论、引语这类关键句仍可用一枚正常大小的黑胶囊（上面“需要胶囊就用正常大小”、骨架的 `BlackPill`、[成对样例](paired-examples.md)里的结论胶囊照旧有效），这条只收窄装饰性小标签。
- **高亮要停到那句口播说完**（124 期 Fred：“31 秒这里 highlight 只 highlight 得很短，马上就闪过”）：`Spotlight`、毛刷这类强调的退出时间跟着它对应的那句口播，不跟着下一个镜头的入场提前退；至少停稳 1.5 秒。交付前在关键帧里专门抽查强调的中段和退出前一刻。
- **胶囊压在满版、复杂的画面上时先加蒙版**（124 期“一整套品牌设计的时候加个蒙版，现在这个胶囊放在上面不是很明显”）：背景是铺满的作品墙、拼贴、录屏时，关键句胶囊先压一层毛玻璃（`FrostFocus`）或压暗再出，不直接浮在花底上。
- **几项并列信息用一张卡逐行点亮**（124 期 S02 三排“原型 / 风格 / 品类”灰标签 + 黑胶囊被嫌“挺奇怪”）：别拆成几枚漂浮的小胶囊；做成一张白卡，标题一行，下面每行“项目名（小、灰）+ 内容（大字）”，说到哪行点亮哪行，其余行保持淡色。
- 段尾交接不能整页半透明发灰地溶解或失焦淡出：页面要么整张退后、沉出画面，要么由同一对象接走。

## 6. 排版底线（每张关键帧都查）

- 关键内容 y ≤ 900（1080 画布），给字幕条留位；左右至少 80px；避开右上角标区。
- 同组卡片同尺寸、顶对齐、等间距；左右对应的模块按中心对齐。
- 搜索框、输入框按内容宽度，不留大片空白；圆角统一。
- 整体构图居中，不偏一边留空。
- 推近特写后，要讲的内容必须完整显示在画内（114 v1 S15 推近后没显示完）。
- 结论胶囊“不是 A，而是 B”这类关键句：居中，背后加蒙版，不放在画面下方。
- 白色小胶囊并排排列显得单薄（114 S06 Fred：“三个白胶囊有点丑”），优先用黑胶囊或卡片。
- **大字单独停着也要有第二个变化，上下别同时塞两组信息**（119 S02 Fred：“3 秒到 7 秒……就只是两个字儿，下面也没什么变化”“6 秒到 8 秒……上面一个下面一个，比较混乱”）：一句大字停超过约 2 秒，就让它带出下一个对象（卡片展开、数字滚动、对象接走）；两组不同信息不要一上一下同时进场，先后交接。
- **能用真实画面或真实界面动作表达的，不用自绘示意动画代替**：停掉、取消、删除这类动作，用观众真见过的界面操作（订阅面板里点开关，“自动续费”变“已关闭”），不做卡通式的“停掉”（119 期“有一点幼稚”）；某人说话、某件事发生，有真实画面就用真实画面（可以静音），不用声波条之类的模拟动画代表（121 期“这个模拟的音频动画有点丑”）。只有确实找不到画面时才画示意，并标“示意”。
- **重点信息不要缩在角落**（118 S09 Fred：“把一些小的卡片放到一个不显眼的地方，不是很好看”）：问题在位置。结论胶囊别挤在右上角、别压在素材上，放画面正中，或紧贴所指对象的上下沿；字号 ≥48px。
- **卡片一张张加入时，每一步都居中**（118 S07 Fred：“没有对齐”）：每加一张，整组平滑重新居中；或者一开始就按最终张数排好位置。不要出现前两张偏左、右边空着的状态。
- **主体要够大、要居中，不要“上重下空”**（116 期第一版 S07、S09、S12、S17、S18 都犯过）：主体占 y 200–880，整组垂直中心约 470；三张以上缩略卡每张至少约 420×236；正文 ≥ 40px 更稳。关键帧检查时专门看下半屏是否空着。
- **一屏信息太密就改成镜头逐块推近**（116 S12 Fred：“有点太密了，可以通过镜头变化优化”）：一屏超过 4 块信息时，不平铺；所有内容放在同一张大画布上，先全景 0.6 秒，再每次约 0.6 秒推到一块、停稳 1–1.5 秒读完，其余在画外或压暗。
- **内部叫法不上屏**（116 S10 Fred：“不要出现 Library 复刻这种字眼，就是 Fred 组件”）：组件来源批次（Library 复刻、第几轮等）对观众统一叫“Fred 组件”；编号可以保留。

- **推近不截字，卡内留白够**：截图、榜单推近时，要读的那一列左右至少留 24px，宁可少推一点（120 期把“claude”截成“laude”）；卡片里的文字离边框至少 40px、行距留足；装饰元素（图标、皇冠、角标）不压在文字上；气泡和卡片左右内边距相等，装饰收在内边距里（121 期“前面有空格，后面没有”）。
- **大数字按实际字宽留位**：版本号、计数这类会翻动的粗体数字比 DESIGN.md 的拉丁字母估算（0.58em）宽，按最宽的那个值留槽，翻动全程不被容器裁掉（121 期版本号“没显示完”）。
- **一个媒体窗配说明文字（标题、要点胶囊）时，优先上下排，不挂右侧竖列**：窗口居中，标题胶囊在窗口上方居中，要点胶囊沿窗口下沿排一排、逐个加入时整排居中。“窗口 + 右侧一竖列（标题、胶囊、小卡）”Fred 评价“排版太丑”（121 期）。图片不要套在更大的白卡里偏放，直接铺满窗口，或让窗口按图片比例。
- **旁边的视觉对象（计数点、附属小窗等，不是说明文字）后出现时，主体先居中**：主窗口先居中占好画面，旁边的对象出现那一刻再约 0.6 秒让位；不要一开始就偏在一边、另一边空着等（121 期“可以先居中，后面七个的时候再往右挪”）。这是“卡片逐张加入每一步都居中”在“窗口 + 附属对象”上的同一条规则。
- **引语、观点用胶囊表达，不做“白卡一行行字加 ↓”**：几个人的说法、一条链路，用黑胶囊横向流程（A → B → C 逐个砸出）；“以前 / 现在”这类对照，用上一行灰字被划掉、下一行黑胶囊（121 期“有点丑”）。
- **对比卡同尺寸并排**：各自“小标题 → 大图标或画面 → 一行大字”，内边距一致（120 期“这里排版很丑”）。

## 6.1 开头和结尾

- 开头进场要有冲击力（114 S01 Fred：手机进场“并不酷炫”），快速入场，0.5 秒内到位，直接进入真实内容，不先空滚或暂停前摇。**落定不要抖**：119 v2 Fred 嫌“进来之后抖动了一下”，入场改用无过冲的 `settle()`（kit v4 已有，2026-10-14 Fred 同意从 119 期并入），`BlackPill` 去掉了 4% 过冲。（114 期这里曾写“带回弹”，已按 119 意见改掉；motion-craft 第 2 节胶囊过冲 3%–5.5% 的写法同样以此为准。）
- **第一秒就给最有冲击的信息**（118 S01 Fred：“开头不是很吸引人……不一定进来就是这个网页，至少第一秒要调整一下”）：例如口播第一句的大数字，第 0 帧就在毛玻璃上从 0 滚到位，再散开露出网页、落到对应那一行。后面的滚动可以照旧。
- **新模型、新产品开场可以做“发布会式揭示”**（T20g，116 期 Fred 建议）：logo 旋转放射出现、产品名逐字揭开、名字大胶囊砸下落定。官方字标里已经有产品名时，版本号直接接在字标后面、用同一字标风格，不再另放一枚重复名字的胶囊（120 期）。开场大字 ≥ 88px。
- **快报、合集类开场**：画面要丰富、节奏快，优先用本期真实画面；台标不用紫色渐变胶囊（121 期“很丑”，也违反 DESIGN.md 不用渐变底）。参考做法（不是固定模板）：121 期 `ep121-v1/src/scenes/A-S01.tsx`，全屏真实画面快切 + 左上黑胶囊白字小台标 + 中间一句大字。
- **结尾默认优先收成一枚胶囊，停稳**：说“以上就是本期的内容”时，可以让画面上的卡片和胶囊一起往中间收，合成一枚黑胶囊（写本期一句话结论，或“以上就是本期的内容”），停稳到段尾接封底（120、121 期 Fred 都说“可以”这样收）。不加行动号召组件，不加额外内容（114 S21）。

## 7. 角标、字幕、B-roll 和固定插入

- **B-roll 人物动画**：全屏正常速度播放，**加角标，用深色背景版（白字，`<Brand dark />`）**。（例外：125 期 Fred 给的 Roadster 过渡动画整体是浅灰/白底画面，用了浅底版；角标版本按画面实际底色选，固定过渡在 `episode.json` 的 `insert.brand` 里写。）Fred 10-13 在 116 期更正：他说的“浅色角标”指的是放在深色背景上的那一版，116 第一版按字面用了浅底版，被指出“用错了”。人物动画开窗前的黑幕阶段也用深色背景版；画面收回白底（收成卡）时，角标随动作换回浅底版。录屏、网页截图作为主内容全屏播放时仍不加角标。**大播放窗播官方、第三方视频也算主内容**，品牌角标关掉；下一段开头把窗口沉出去的几帧也保持关闭，接缝两侧一致（118 S04 又犯过，Fred：“这种播视频的时候角标可以去掉”）。人物动画除外。
- **口播说“动画”默认指 Fred 人物动画**（116 S07 Fred：“动画应该是 Fred 人物动画哈”），配图用人物动画画面，不用组件缩略图。
- **产品 logo 一律用官方素材，不重画近似图**（116 S01 Fred：“自己去网上搜索一些 logo 用吧”）。常用 logo 放在 `assets/product-logos/`（README 写了来源）；缺的先在本机素材里找，再请 Fred 提供或从官方渠道取，不用代码画近似版。**logo 用透明底，不带白底、白框托着**（119 S01 Fred：“Codex logo 很奇怪，就这个下面这个白框……要不要抠干净”）；`product-logos/x6-logo-codex.png` 已是透明底，直接用。
- **真人上屏的边界**：和本期内容无关的真人不上屏——博主出镜、采访、广告演员、店员、官方演示里的名人演讲（119 期 VideoLingo）；换成产品界面、截取无人区间、裁掉或推近避开。**新闻事件的当事人本人**（例如 121 期在议会用 AI 声音发言的议员）、工具作者演示自己做的工具，都可以上屏，这是在讲他们本人做的事；演示画面里远处、非主体的人也可以。拿不准时列给 Fred 定。
- **第三方测评视频当素材**（120 期）：先筛真人、裁成片段、写 clips.json 卡点，再上屏；缺画面就重建示意并标“示意”。完整做法见 [第三方测评视频](third-party-review-footage.md)。
- 有最终字幕时，全片带得意黑字幕条，关键帧阶段就带上。
- 公开评论区的昵称、头像不用打码（Fred 说明这些本来就公开）；“群聊/加群”字样仍不能上屏。
- 固定过渡插入：见 [固定过渡配音](fixed-skill-library-insert.md)。112、114 期都放在“建议大家先收藏点赞”这句之后。按语义找那句话后的静音点，不按旧时间戳（录音换版后时间会变）。过渡人声是纯人声，BGM 照常不让位（见下一条）。稿子里没有“收藏点赞”时，放在主体讲解开始前的自然停顿（116 期放在“那它帮我做了哪些事情呢”之后、“第一件”之前）。插入段最后一帧是白底大黑卡，下一段首帧从这张黑卡收成本段对象（做法见下一条）。
- **过渡插入段接下一段：末帧图压在最上层，跟着黑卡走、0.3 秒内淡出**：下一段首帧必须和过渡末帧（`media/insert-last.png`：白底大黑卡 + 伸出卡外的 Fred 人物）一模一样。这张图要画在下一段撑开的黑窗**之上**（最高层），约 0.3 秒内淡出（整图原地淡出即可，也可以跟着大黑卡的变换一起缩放移动），由同一张黑卡接成本段对象（这是“同一对象接走”，不是第 3 节禁止的整屏淡入淡出）。把它画在黑窗下面，接缝处会一下变成空黑卡、人物残在卡外——120、121 两期都犯过，单看首尾帧发现不了。参考写法：121 期 `ep121-v1/src/scenes/A-S02.tsx`（整图 zIndex 72 原地 0.04–0.36 秒淡出）；120 期 `ep120-v1/src/scenes/GroupA.tsx` 的 S02 开头（搜“接 INSERT 末帧”，跟着变换）。检查时逐帧看接缝后 0–0.5 秒（每 4 帧一张拼图）。

## 8. 动态自检：motion_audit.py

静帧看不出“慢”。渲染预览分段后先跑：

```bash
python3 skills/fred-remotion-output/scripts/motion_audit.py --dir <分段目录> \
  --allow S02 --allow S11:2-9 --json <本期>/qc/motion-audit.json
```

- **阻止正式渲染的四种**：定格/干等（画面 3 秒以上不变）、缓慢漂移、单次运动过长（一次推近或移动超过 1.4 秒）、纯滚动过长（页面滚动超过 2 秒）。
- **只提醒的两种**：停留偏长（2–3 秒不变）、持续运动不停稳（连续动 3 秒以上没有停下来读）。逐条看一眼，合理就留着。
- 默认裁掉底部字幕区再比较；采样固定 10fps，阈值按这个采样率校准。
- 用 114 v1 校准过：Fred 指出慢的 S01、S02、S03、S04、S07、S09、S12、S13、S15、S16、S19、S21 都会报出来（S04 开头的滚动是提醒级）。也有误报：组件结尾的正常停留（如 S12 第 11–14 秒、S20 各段问答停稳）会报定格，Fred 认可的 S08、S18 会有提醒。所以这是待查清单，阻止级的每条要么改掉，要么写理由豁免。
- 结果是待查清单，不是结论。数字滚动、图表生长、B-roll 这类有意的连续动作可以豁免，但要用 `--allow` 写明段号和区间，并在本期简报里写一句理由。
- 未豁免的问题不为 0，不推 4K 正式渲染。
- 单个组件演示片结尾的停留（2–3 秒）是演示用的，查组件时用 `--max-hold 3.2`。
- **常见误报：多对象接力的组件动作**（116 期 11 处阻止级里 10 处是这类）：目录树逐层展开、缩略图逐张倒出、展示窗抽出、线展开成卡并逐字打出，会被算成“单次运动过长”。逐条看确认不是相机慢推后用 `--allow 段:区间` 豁免，理由写进 `qc/motion-audit-exemptions.md`。结尾“以上就是本期内容”后的停稳也豁免。
- **对整片跑也可以**（125 期直接出 4K，没有分段预览）：先把成片缩成 1080p 再跑。报出来的“单次运动过长”大多是发布会实拍本身在动（烧胎烟雾、0.2 倍慢放喷流、坡道行驶、悬停），逐条按时间换算到段号和口播句、抽帧看过后豁免。要找的是画出来的示意动画该动却没动：125 期“把气球吹满一松手，它是不是嗖一下就飞出去了”，气球几乎原地不动，只有喷流在动——**口播里的动作词（飞出去、松手、倒挂、落地）说到时画面必须当场发生**，否则就是没兑现。

## 8.1 字看不看得清：readability_audit.py

`motion_audit.py` 查的是动不动，查不出“画面一直在动，但字只有几像素”（118 期 Codex 试作 47–68 秒整窗播放第三方录屏，motion_audit 全部通过）。渲染预览后接着跑：

```bash
python3 skills/fred-remotion-output/scripts/readability_audit.py --dir <分段目录> --json <本期>/qc/readability-audit.json
```

用 macOS Vision 按 1 秒一帧识别文字框：一帧里文字框不少于 8 个、而高度 ≥24px 的框面积占全部文字面积不到 45%，算这一帧看不清；连续 3 秒以上为阻止级，2–3 秒为提醒级。注意量的是文字框高度（约为字号的 1.4 倍），所以检查通过不等于满足“要读的字 ≥24px”，那条仍要看图确认。一枚大胶囊压在满屏小字上，面积占比通常仍不够，照样会报。豁免用 `--allow 段:区间` 并写理由。阻止级不为 0，不推 4K。

- **报出来先问：这几秒观众需要读界面里的字吗？** 需要读，就推近或重建（[成对样例](paired-examples.md)第 5 组）。不需要读、画面只表现“有这样一个工具在运行”，而结论已经由足够大的胶囊或卡片给出（例如 118 成片 87–92 秒：大窗播第三方截图工具演示，上面压“拆的是开源截图工具 ShareX”胶囊），可以豁免，理由写进 `qc/readability-exemptions.md`。这种整窗播放全片要少用、尽量短。
- 已知局限：1 秒一帧采样，只出现 1 秒的看不清画面不报；可读面积占比在 0.45–0.6 的半可读终端画面可能漏报；虚化背景里的字也会算成小字。只能在 macOS 上跑（用 Vision 和 swiftc）。

## 9. 出关键帧前的自检清单

按 Fred 历期意见（114 期起陆续补充）逐段查。Sonnet 逐张检查关键帧并列出问题，Opus 判断怎么改：

1. **录屏**：有没有整窗干播、慢推、纯滚动超过 2 秒、定格凑时长？
2. **交互**：讲到点击、输入、复制、下载时，画面里有没有光标、打字、状态变化？
3. **重复**：这个组件前面用过吗？讲解结构类组件是不是第二次出现？
4. **强调**：有没有紫框、黑框（包括黑描边节点方块）？能不能改成局部蒙版、阴影或毛刷？毛玻璃是不是总用同一种“一行字/胶囊”、黑白有没有变化？白底上有没有压全屏黑玻璃？白磨砂上有没有叠超大胶囊？
5. **排版**：对齐、居中、y ≤ 900、有没有出画、推近后内容是否完整（字没被截、翻动的数字没被裁）？重点胶囊和标签是不是缩在角落？卡片逐张加入、窗口旁对象后出现时，每一步是否居中？媒体窗的说明是不是挂成了右侧一竖列？卡片、气泡左右内边距是否相等？画出来的 Codex 输入框是不是真实比例、模型名是不是当前的？
6. **数量上屏**：口播提到数量（“几百万个”“900 多个”），画面就给出真实数字，取自截图原文，用大字或黑胶囊放在数字原位（114 S07 Fred 补的意见：搜 AI 约 700 万、video cutter 983、speech to text 约 9.4 万）。
7. **组件高潮不被截掉**：时间不够时，压缩或加速前面的录屏，保住组件最后的结果动作（114 S18 的文件过滤少了“3 个文件传进去”约 2 秒，Fred 要求完整呈现）。
8. **一次性码也遮**：设备验证码、一次性登录码即使已失效也打码（114 S15 露出过）。
9. **口播对应**：口播里提到的每个名词（工具名、按钮、搜索词、文件名），画面上有没有出现？比如“想录音就搜 speech to text”就要真的搜出来；讲到某个界面元素时，要用蒙版或阴影指出它在哪（例如 114 期讲 Star 时指出位置，再斜杠划掉“只是参考”）。
10. **真实画面优先**：有没有用自绘示意（声波条、卡通动作）代替本来找得到的真实画面或真实界面操作？上屏的真人是不是新闻当事人、演示自己工具的作者或画面远处的非主体，有没有无关的博主、采访、广告演员、店员？

- **六组并行、只出关键帧、直接上云渲 4K**（125 期，正文约 4.8 分钟、9 段加过渡，Fred 要求“多用几个子 agent”“不用 1080p 视频，修好直接推云端”）：

  - 看联系表时注意缩放：关键帧常按 `SCALE=0.5` 出图，联系表又缩一次，字看着小不一定真小。打回前按 1920 画布换算实际 px 再判断（125 期 B 组多数字号其实已达标）。
  - **哪组定稿先渲哪组**：用 `plan.py <还没好的段…>` 跳过未完成的段，`cloud.sh go` 先渲已定稿的；后面的段好了，同步 stage 后用 `cloud.sh chunk <台> <段> <起> <止>` 按块分到各台补渲，已拉回的块会跳过。125 期第一轮 33 块渲完时，最后一组还在改。

  - 返修只重渲受影响的块：旧块挪到 `out/chunks-old/`，`cloud.sh chunk` 补渲；音效变了就先重渲 `out/full-sfx.wav`，再 `REUSE_SFX=1 python3 render/final.py`，最后跑 `loudness.py --fix`（125 期 -10.2 → -9.6 LUFS）。

## 12. 交付前检查

114 v2 第一次交付时漏了 BGM，整片直接叠音频还爆过音（峰值超过满幅）。成片交给 Fred 前逐项查，每项写实际结果：

2. **音频流程**：音效轨（`noVoice`）和口播轨分开渲，混音后过 `alimiter`，再用 `bgm.py` 加 BGM。骨架的 `render/final.py` 已按这个顺序写好。
3. **BGM**：从 0 秒到结尾都有；固定过渡插入段照常有 BGM（纯人声不让位），封底等自带音乐的区间按 `bgm-plan.json` 让位；音乐不够长时的拼接点要人耳试听，没听过就写“接缝待试听”。
4. **响度**：AAC 实测真峰值 ≤ -1 dBTP（114 v3：-9.6 LUFS、-1.3 dBTP）。
5. **音效次数**：`grep -rnE '<Sfx[^>]*name="(gather|scroll|ding|notify)"[^>]*keep' src`，齿轮声和叮各不超过 2 处；再 `grep -rn "sfx/" src` 确认没有绕过 `Sfx` 直接用 `<Audio>` 放音效。
6. **接缝**：每个接缝看前后各 0.5 秒的连续帧，特别是切点后 0.1–0.3 秒有没有灰糊、溶解、残影。
7. **字幕、角标**：字幕和口播同步；角标显隐按第 7 节，接缝两侧一致。
8. **平台安全**：“完全访问”、密钥、一次性码、“群聊/加群”。
9. **前端**：用骨架的 `tools/push_videos.py` 把成片切段推进“逐段视频”页，段落起止和成片一致。

11. **时长也要核对，不只核对帧数**（116 期）：外部片段（封底）和拆小再拼回的块，时间基是 1/60000，云端块是 1/90000，`concat -c copy` 会把它们压成一瞬间——帧数仍然对，画面却在那里“定住”（116 v1 2:58–3:02，Fred 看片时指出）。`final.py` 已统一成 90000 并核对时长；手工拼块时用 `-video_track_timescale 90000`，交付前检查 `时长 = 帧数 / 60`，并抽看被拼接处前后几秒在动。

## 13. 云渲染的实际经验（116 期）

- **重段切小块**：带 4K 视频素材的段（113/114 片段叠版本卡）一块 365 帧会超过 15 分钟超时，两台各试两次都失败。`episode.json` 的 `heavySegments` 权重 ≥ 1.5 的段，`plan.py` 自动按更小块切（约 180 帧）。
- **多台服务器**：`episode.json` 的 `cloud.hosts` 可以写任意多台（键名任意）；`cloud.sh sync <host>` 单独同步一台。第二台中途加入时，让它从各线队尾反向领块，先拉回本地的那块另一台自动跳过。
