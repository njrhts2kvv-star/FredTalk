# 文字怎样出现、流动和退出

Fred 明确要求把滚动、刷出、淡出等文字呈现保存为后续视频参考。原话和准确视频区间绑定在 `text-patterns.json`。这是独立连续视频的文字层方法，入口同时接入“正文组件”Skill；该库原点击式Deck Demo的固定布局和透明度限制不自动套到这里。

## 先分清作用层

- **字词层**：逐字增加、遮罩刷出、颜色强调、淡入淡出、原位换词。
- **文字流层**：已有多行/多条文字整体滚动，为新信息让出阅读位置。
- **载体层**：胶囊、窗口或图卡的移动与缩放，按 [对象过渡](object-transitions.md) 选用。

先决定这句话何时开始可读、何时完整可读、读到什么时候，再选适合的形式。需要表现输入过程用逐字；快速建立一句完整判断可用刷出；补充词读完可淡出；持续对话可上卷。文字不必每次都套胶囊，也不要求每句换一种动效。

## 换成新文案时要保留什么

1. **固定最终排版，再做可见性变化。** 刷出通常先排完整句，用遮罩控制可见区域，不靠反复截短文本改变中心和换行。逐字输出确需改字符数时，预留最终宽高、对齐和行高。
2. **按当前文字测量。** 短词和长段落分开，中文、英文、标点、emoji与组合字符按字素边界处理。W01原代码使用slice，新内容不能默认安全切分所有字符。
3. **区分刷出、滚动和淡化。** `clipPath`改变可见区域；`translate`移动文字或文字流；`opacity`改变透明度。这些可以组合，但不能把源片没有的机制写成已实现API。
4. **按口播决定节奏。** 逐项文字绑定实际词组cue，阅读段停稳，上一条读完再滚出；不要为了好看把尚未读完的字提前淡掉。新句可在旧句退让后建立，涉及整个载体时组合T类动作。
5. **淡化是可选形式。** 用户指定或适合轻量强调时直接采用，不能被旧Deck Demo的“禁止透明度淡入”误挡；也不把所有正文都统一成普通淡入。
6. **结束态清楚。** 淡出需要干净退出时归零/卸载，保留上下文时明确保留比例；旧词和光标不残留。刷出末帧要完整，不切掉标点和字形边缘。

文字显示与载体扩容要共享真实语义 cue，首个可读状态不能只有空胶囊运动。补充句晚于主句时，可先建立含主句的长载体，再同步扩出下一行及文字；空壳先展开适合的场景仍可采用，但不拖成无信息等待。短句能单行完整放下时按实际字宽/边距分组，不仅为了强调色拆成两行；明确单行/白色要求只作用于指定对象，不改其他卡片。

换字或刷出后检查完整阅读窗口，而非只查文字出现时间。要展示的数值、单位和关键短语不能只留在字幕中或末帧一闪而过；当前合同只要求字幕承载时不重复添加画面字。字体按同职责统一，颜色与层级不靠空白换行补救。文字层和载体层分别检查，避免两个独立显隐窗口制造意外闪动。

现有代码、字体、素材和依赖仍从原参考包复制后适配。不要对冻结样片原地改字。当前6类是经过源片和源码核对的参考，不是已验证任意长文字的统一组件；不同缓动helper的参数含义见对象过渡文档。

## 对应分镜与后续沉淀

使用时在当前 `motionEvents` 记录 `textEffectRef`、`referenceId`、参考片段区间、实际文案及cue；`sceneGuide`加 `text-presentation`，把字号/换行、读完时刻、退出方式落实到applications。载体过渡按需要另加 `object-transition`，两者可以组合但不必全用。

检查首个可见帧、半句/换行中段、完整句、退出中段和最终帧；核对文字完整、标点/emoji、裁切、基线、阅读停留与字幕区域。新出现的形式沿同一文字索引补证据、机制和限制；只有动作方向或配色不同则记变体，避免重复组件。
