# 用第三方测评视频当画面素材

120 期（Gemini 4 Argon，2026-10-14）Fred 没有亲测，画面主要来自海外 YouTube / X 测评和少量国内博主视频。Fred 的要求：“只保留测评画面，避免有一些真人露出”“最好用海外内容，国内博主可以用观点，用的话多张画面一起、不停留太久”。下面是这期跑通的做法。

## 1. 先筛真人露出，再选段

1. 每条视频每 3 秒抽一帧（缩到 480 宽），用人脸检测先粗筛（macOS Vision `VNDetectFaceRectanglesRequest` 即可，不用装 OpenCV），算出人脸框占画面比例，区分“整屏主播”“角落小窗/圆头像”“无人”。
2. 检测器会漏检（国内博主的圆头像）也会误报（游戏角色、卡通人物、Spider-Man），所以**每条再出联系表（每 9–10 秒一格）人工看一遍**，以肉眼为准。
3. 输出一份报告（120：`research/reports/broll-usability.md` + `.json`）：每条的真人情况和时间段、烧录字幕/水印、可用纯测评区间（起止 + 画面内容 + 适合讲哪一点）、评级 A 直接可用 / B 裁掉部分可用 / C 基本不可用。烧录字幕或头像贯穿全片的判 C。
4. 交付前主会话自己抽几帧复核，不只转述子任务结论。

## 2. 裁成能直接用的片段

- 裁掉小窗/头像所在区域后**补成 16:9 的 1920×1080**（宁可多裁边，不留黑边、不拉伸），去掉音轨，CRF 18，保持源帧率；作者水印条（如 `@mirochill`）一并裁掉。
- 每段出联系表（每 2 秒一格）并写进 `clips.json`：`{name, file, source, srcStart, srcEnd, crop, content, moments:[{t, what}]}`。**moments 写片段内秒数和此刻画面发生什么**（“按 V 进入第一人称”“顶栏显示 Gemini”），写场景代码的人靠它对口播卡点。
- 同一屏多个模型轮流出现的（Arena 对比），按顶栏模型名逐秒核对，只留本期模型的区间；顶栏被裁掉的，在画面上自己用模型标签标出来。
- 画面里的 AI 生成人物插图不算真人；被剪辑的访谈对象、视频通话里的人算真人，要裁掉或不用。
- **国内博主片源**（头像小窗 + 烧录字幕贯穿全片）：不出视频片段，只截 2–3 张静帧（裁掉头像和字幕区，保留原比例），在场景里快扫或并排，每张停 ≤1.2 秒。
- 片段放 `public/media/clips/`，片源原视频不进 `public/`（太大，也不需要）。

## 3. 上屏规则

- 第三方视频作主内容播放时关掉右上角标，左下加来源小字（`YouTube · 作者名`、`Arena WebDev · 日期`、`抖音 · 作者名`）；**口播里不念博主名**（见 fred-script-generation 的 hooks-and-structure.md“转述别人的实测或观点”）。口播讲到转述来的结果、但这段没用对方画面时（例如只采用国内博主的观点），也在那几秒的画面左下标来源，不能完全不标。
- **素材里没有合适画面时，按原片描述重建示意，并在画面上标“示意”**（120：终端报错、API 代码卡、双摆弹簧代码、DaVinci 剪辑窗、代码审查报告卡、泄露路径卡）。不要把示意画面做得像真实截图，也不要拿别的视频冒充。
- 榜单、跑分优先用官方页面截图（截图时间写进来源小字），再用 kit 重建条形卡突出两三行；数字以截图为准，不用二手报道。
- 录屏包装规则照 [整期编排](episode-assembly.md) 第 2 节：推近到要读的区域、每 2–3 秒一个变化、不整窗干播。

## 4. 分工参考（120 实际）

- Sonnet：真人筛查 + 报告（27 条约 10 分钟）、裁片段 + clips.json（22 段 + 8 静帧）、抓官网/榜单截图与 logo。
- 主会话：定哪些点要画面、复核抽帧、决定缺画面时重建什么。
