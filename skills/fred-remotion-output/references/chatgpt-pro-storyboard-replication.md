# ChatGPT Pro 分镜探索与 Remotion 复刻

当现有已认可组件无法清楚表达当前语义，或用户明确认为当前组件“不合适”并要求重新生图时，按本流程执行。ChatGPT Pro 图片只负责探索构图、对象关系和连续状态；正式画面仍由真实素材、已认可组件和本期 Remotion 适配源码落地。

## 触发条件

- 用户明确要求使用 ChatGPT Pro / 创建图片；
- 用户对当前组件提出“换一个组件”“这个不适合”“重新设计”等意见，且现有库缺少能表达本句关系的候选；
- 同一对象关系需要先看“建立—变化—重点—交接”的空间方案，再写 Remotion。

如果准确组件已经能表达语义，直接走组件选型与关键帧流程，不为了生图而生图。真实录屏、原图、已有视频和 B-roll 继续按各自流程处理。

## Pro 生图提示词必须包含

1. 本段 stableId、时长、逐字稿和准确上屏词；
2. 观众必须看懂的对象关系，以及开始、重点、交接状态；
3. A 视觉参考（已认可组件的材质、字阶、留白）、B 逻辑参考（动作/关系）和 C 字形参考的职责；
4. 画幅、字幕安全区、品牌安全区和可由 React/CSS/SVG/Remotion 实现的边界；
5. 必须保留的事实、不得杜撰的软件界面/数字/价格/按钮，以及需要由真实录屏替换的区域；
6. 与前后场景的对象交接，避免把多格画成独立海报；已有录屏必须保留的操作、结果和源时钟；
7. 实际口播的语义落点与可用阅读时间。短段允许少量核心状态，长段说明信息如何逐步推进；图片数量不等于成片动作数量。

四状态不是固定配额；只有在连续关系难以说明时使用“建立—推进—重点—交接”四格。提示词应锁定事实与实现边界，把具体构图留给模型。

### 参考图必须成为实际输入

先从当前视觉库挑用途、对象关系和质感相近的准确截图/组合图，核对对应ID、来源视频或组件及hash。用户给的是多布局组合参考时，可同时用它和库内相近组合图：前者锁探索方向，后者锁已认可的材质、层级和构图关系。不能只在prompt里写“参考视觉库”、只传字形样本或拿无关单帧替代组合参考。拼图内的不同画面是参考，不默认要求全部进入本段。

发送前核对附件实际出现在本条消息；记录实际上传路径/hash与职责，不把本地已准备的文件当作已上传。A/B/C按需要分工，不强制三张重复参考。原图中的旧文案、作者标识和示例UI不成为本期事实。上传失败或浏览器被接管时保存状态，按已有工具规则交接；恢复后核对会话、待提交prompt和附件，不重复提交已在生成的任务。

## 执行与记录

- 使用 Ego Lite 的已有登录态，发送前冻结最终 prompt，通过 direction gate；确认界面实际为“创建图片”和 Pro 模式后再提交。
- 每个场景保存独立 `prompt.txt`、方向 receipt、生成原图、尺寸、SHA-256、会话 URL 和附件来源；不要按返回顺序猜图片身份。
- 生成结果只记录 `generated`。助手实际看过原图后再记录 `internal-reviewed`；Fred 明确认可准确图片/范围后才记录 `user-accepted`。静态分镜认可不等于动态认可、源码 API 认可或真实操作证据。
- 一个会话可以包含多个场景，但 Manifest 仍按 stableId 分项保存，避免把一个场景的认可范围扩散到其他场景。

用户要求多方案时，方案应在对象关系、载体、阅读路径或交接方式上有实质差别，不只换颜色/字形。数量遵从当次请求；每张保存稳定候选ID、准确图片和状态，放回同一逐段前端选择。采用最新真实选择：若用户提前选择附图，结束尚未需要的探索并冻结选图hash；不把未生成候选补记为完成，也不按图片排序猜A/B/E。选图后将旧动作计划一起替换，不能新图配旧版时序。

## 复刻顺序

1. 从生成图提取可复刻的核心构图、对象身份、相对位置、尺度变化和交接关系；不要直接把生成图当正式背景，也不要只复制颜色、字体或圆角。
2. 重新通过组件库交付门禁，绑定准确已认可源码、项目适配函数、真实媒体和字体。没有合适组件时报告缺口，除非 Fred 当次明确授权原创，不擅自把生成图改成原创 UI。
3. 用本期真实文字、录屏、图片或视频替换生成图里的示意内容；虚构软件、虚构数字、虚构价格和模型错误文字不得进入成片。
4. 在同一 Manifest 的 `componentPlan`、`referenceChoices`、`sceneGuide` 和 `callSite.callee` 中记录“Pro 探索 → 组件复刻”的对应关系。
5. 先出真实关键帧，再检查短动画中的对象连续性、内容就绪、字幕避让、前后交接和声音。关键帧静态通过后仍需内部动态检查和正式渲染门禁。

## 把九宫格变成按口播推进的动画

九宫格提供构图、对象关系和目标状态，不提供已成立的剪辑节奏。收到用户选图后先核对来源：实际 Pro 生成、其他生图工具生成、用户附件分别记录；不能把用户附图记成助手生成，也不能把一张多布局探索图记成多轮独立生成。保留用户选定的核心关系与质感，状态数量按口播取舍。

### 先取舍状态，再安排动作

1. 锁定当前最终音轨/SRT、段长、实际短语、前后场景，以及已成立的保护项。没有正式录音时用估时规划，音频到位后重新对齐。
2. 从每格提取具体对象与本格新增的意义，例如同一个任务、Key、文件或结果，而不是只列“第几页”。将其对应到口播里的建立、操作、变化、证明或结论。
3. 给每格记录 `selected / merged / dropped / replaced-by-media` 及理由：必要语义保留；相同含义的构图合并；重复解释、未在本段讲到、需要额外阅读但时间不足的状态删去；真实操作用现有录屏替换。按当前授权取舍，不能因删格顺手剪掉声音。
4. 计算每项从**完整可读**到离开焦点的窗口，另列动作完成、阅读和交接。不能把总段长除以九，不能只量文字开始淡入的时刻，也不能把大部分阅读时间耗在箭头缓慢生长上。
5. 用剩余状态写连续动作链，再落回同一 Manifest。可按[九宫格动作规划模板](../templates/pro-storyboard-motion-plan.md)填现有 `componentPlan/sceneGuide`；时码仍在 `motionEvents/readingPlan`，保护项仍在 `preserveObjects`，不另建可独立修改的时间线。

| 时间与内容问题 | 实际处理 |
| --- | --- |
| 短口播容不下全部格 | 保留核心语义，合并重复构图；有授权时删去非必要格。动作及时建立信息，留出看清文字的时间，不用密集翻页把九格塞完 |
| 长口播停在同一画面却已换了语义 | 让同一产品、窗口或文字承担下一步真实变化，如输入、转写、整理、保存、结果；不能靠持续脉冲、慢箭头或装饰漂移撑时间 |
| 口播正在精读原文或看结果 | 让对象停稳，保持必要上下文；稳定阅读有职责，不强制添加动画 |
| 图里的过程与口播不匹配 | 重新选适合的格或已认可组件，修正对象与关系；不要只给旧时序换新图，或为保住九格补造本期没有讲的步骤 |

### 用持续对象承接变化

先确定哪些对象跨状态仍是同一个，保持其身份与上下文，沿同一对象更新实际边界与锚点，再选缩放让位、局部聚焦、展开收束、同槽替换、连接或内容进入等合适动作。连接线只有在解释关系时使用；其落点、方向和出现顺序跟随当前对象，进度为零不能先露出端点。淡入淡出可以辅助局部显隐，不能替代“观众看到什么发生了变化”。

从“左侧说明”到“右侧结果”可让同一主体让位，再建立结果；从“Key”到“配置文件”可让同一 Key 进入同一文件。具体布局不是固定模板。相邻段延续对象时共用明确的动作/媒体时钟或等价的状态映射，后段从实际末态继续，不每段都清空重开。最终首尾帧相同只证明边界一致，仍需检查段内语义推进。

实现使用可编辑 React/CSS/SVG 与准确组件源码。不要用整页 `State` 挂载/卸载、按等长时间轮换九张构图，再叠上淡化或位移就声称完成连续复刻。确需整页换景时说明内容职责，并从原场景的对象或焦点建立新的关系；有意快切可以保留，不能将所有快速切换一概视为错误。

### 动作时间和阅读时间分开

参考已认可组件的**同职责动作区间**，核对行程、缓动、物体大小、文字就绪和落点。动作应及时到位，然后停读；长段不意味着把一次入场、开窗或连线均匀拉伸到整句结束。动作太快看不清，就减少同时变化的对象或删减状态；动作太慢，先缩短无信息行程并明确落点，不靠整体加速录音解决。具体秒数按本句与实际参考决定，不设跨期固定速度或每隔几秒必动一次。

阅读区间仍要检查口播是否进入了新对象、新操作或新结论。若已进入，应按语义推进画面；若仍在读同一内容，保持稳定。字体、载体、箭头和图标按当前可见组的视觉中心与对应基线检查，不能只看 CSS 外框中心。

### 真实媒体完成后才能补总结

录屏承担真实操作与结果证明。补充胶囊、流程收束或规则窗口，放在相关操作已经完整发生、结果已经可读的窗口；不提前结束录屏、不盖住关键控件、不丢掉原运镜与交接。总结词来自本句实际内容，必要时保持真实结果作为背景，再让短总结自然接到下一段。时间不够可以少用或不用，不强制把用户提供的所有组件塞入成片。

### 正常速度检查与局部返修

先核实际第一可读帧、最大运动包络、换词中段、线条初态及交接两侧；再带最终口播以 1× 看完整语义段，包含新增内容前后。静态九格齐全、首尾像素相同、低清无声诊断或变化阈值通过，都不能证明口播节奏、阅读和声音已经成立。

用户已授权直接正式云渲染并下载检查时，按该授权输出，不额外等待云端试片或用户动态样片确认；仍保留适用技术检查，并在下载后检查实际文件。发现问题先定位“状态过多、语义没推进、行程太慢、几何不齐、媒体被截断”等具体原因，只重做受影响动作及有依赖的邻段。按[渲染与返修](render-and-delivery.md)保护已成立画面、最终口播、字幕时码与完整声音；若动作落点改变，局部重绑音效，不重复处理整条音乐或人声。
