普通查询默认仍是已保留项；本句涉及上述用途时补一次新集合候选查询即可，不通读全部 21 条。不把 `status=exact` 解读为视觉已通过：在原复刻台它只表示选段范围被同范围输出覆盖。

新源码/成片/完整 public/字体/锁文件在项目 `skills/fred-remotion-output/assets/reference-code/library-remakes-20260916/`，两个源快照分别为 `faithful/` 和 `purple/`。隔离运行依赖位于 `skills/_runtime/remotion/library-remakes-20260916/`，Remotion **4.0.515**，React **19.2.4**。这与旧 B 集合的 4.0.473 不同；选定当前工程版本后适配，不混载或升级旧工程。浏览文件架见该集合根目录 `index.html`。本地运行依赖按 macOS 平台恢复；以后上 Linux 云端时复用源码/素材与锁文件，在云端安装对应平台依赖，不直接上传 macOS 的 node_modules。

准确源码复制到本期工程后再改，沿已有 `referenceChoices` 记录原符号、本期实现和实际调用位置；见[从内容到组件](content-to-component.md)。有 props 的直接传现有接口；没有 props 的先把本次真正要换的字段提出来，不从自然语言重写整个动效，也不为所有参考提前建立通用组件框架。

已有 props 指组件直接调用接口：原入口的 `scaleScene` 没有透传输入属性，适配时要直接调用 `ClipXXX` 或在本期入口显式透传，不能只给旧 Composition 填 `inputProps`。原入口还负责 `1280×720` 逻辑画布缩放及 `Media.tsx` 的 `FontGate` 字体就绪；直接调用时保留这两项初始化，或明确映射本期字体并等待加载。查询同时返回主 Clip 和 `FontGate` 的准确源码位置，完整入口也已保存。

换视频按各条实际媒体实现处理：

- R014/015/016/024/025/026/027/036/038 使用共享 `Media.tsx`，按 `.mp4` 后缀识别视频；BatchA 的 `type` 字段不参与判断。
- R028/033/041/042/044/045 使用 BatchB 内部的 Media，视频必须传 `type: 'video'`，仅传 `.mp4` 路径会被当图片。以上两组时长均从 `public/shared/videos.json` 读取，未登记时默认 5 秒循环。
- R051/052 使用 BatchC 的 LocalVideo，循环长度按文件名硬编码为 9.36 秒或 5.1 秒，不读取 `videos.json`；R053 则固定循环 306 帧。换源时同时改实际播放长度、入点和循环策略。R017 没有媒体，R048/049 只用图片。

媒体识别成功与播放区间正确分别检查，实操过程不应无意回到开头。

## 本批容易踩的四处边界

- **时间与尺寸分开改。** 原片混用 30/60fps，部分函数按固定帧数，R038 更是 30fps 测量轨迹表。改 4K 可以保留逻辑画布等比缩放；改 60fps 还需按秒重映射轨迹/事件/帧序列并保持原时长。逐句 cue 重新绑定本期口播，不只改 Composition 的 fps。
- **媒体替换有不同深度。** BatchA/B 多条已有 media 参数；报告/表格仍是截图，R051 卷页依赖预抽 JPG，R036 尾部含特定文字 mask。这些更换对应内容时要重做局部资源，直接替换一个 src 并不足够。可变接口以每条 `editableParameters` 为准，待改字段见 `adaptationNeeds`。
- **字体、配色和角标沿当前片要求。** 本批原样字体有 MiSans Regular/Heavy，7 条紫色是本批修订；它们不是新片固定字体或全局紫色模板。适配到 Mic Pro 已认可质感时沿本期字体和字阶，保护同组一致。FredTalk 横版角标仍在最终画布独立层按实际底色处理，不放进缩放设备/媒体组。
- **动作代码不自带可沿用的音轨。** 本批媒体组件 muted，源码没有 Audio 事件编排；成片中的示例声音不能直接当新片配音和音效。按实际出现、点击、输入、聚合、转场选择项目音效库并重绑 cue。文档滚动不使用数字滚动声，已增强 +8dB 的素材不重复增强。

本次保存与构建状态只证明各自范围。抽帧分析用于选型判断，不代表已完整动态审看或新内容通用 API 已验收。没有用到的旧文案、示例媒体和历史分支不随新片自动进入交付。
