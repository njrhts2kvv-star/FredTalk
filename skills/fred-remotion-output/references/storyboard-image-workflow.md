# 用分镜图探索表达，再用真实组件落地

适用于 Fred 希望先看多个方向、减少写完动画后才发现方向不合的情况。新一期先按[图文建议与关键帧](route-and-storyboard-review.md)由助手给整组建议，Fred调整并选定；本套只用于需要生成图探索的Remotion段，准确视觉库截图/短片足够时可直接选型。已有明确选图或本轮明确直做可直接实现，不能仅因助手觉得方向清楚就跳过用户选图；录屏/卡通段不强制进入本套。本方法复用用户认可的表达与视觉语言，不承诺生成结果或代码首次即被认可。

## 默认视觉与自由度

完整默认值以[DESIGN.md](../DESIGN.md)为准；参考图含旧细边、紫面或PPT页眉时，在本期提示词里明确覆盖，参考动作与质量关系继续保留。

- FredTalk解释型动画以黑白为主；纯白/纯黑背景，紫色只作少量关键词、细节强调，允许完全不用。灰色尽量少，主要服务阴影和必要弱化，自制胶囊/卡片不默认细描边，不默认大面积灰底或灰色卡片阵列。颜色面积不设机械百分比，按视觉重心判断。
- 黑底白字、白底黑字的胶囊/模块可用克制柔和阴影形成层次。手机、电脑、平板、桌面窗口是成熟载体，按内容选择，不要求每套都出现设备，也不把整片做成流程图。
- 同组字体统一，默认参照实际MiSans字体；生成图片只能示意字形，代码需加载项目真实字体。字号分层，避免把所有内容变成超粗大标题；强结论仍可用大字。
- 内容组织先于表面模仿：对象建立、当前职责聚焦、同一批内容变化、交接、收束。镜头可以靠近/让位/回到整体，保持对象身份；不把九格做成九张独立海报，不为变化机械切黑白。
- 二维文字、卡片、节点、设备外壳及移动/缩放/遮罩/归组优先；流程不默认画连接线或箭头。此类探索默认不加入人物、机器人、粒子、光晕或复杂3D；这是本路线默认边界，不是全局禁用人物/H3，明确需要时另选合适路线。
- 最新用户要求与当前已认可基线优先；不固定三栏、居中、镜头数量、设备型号或胶囊配额。

## 实际步骤

1. 核对本段用户指定的制作路线，再取当前逐字稿与时长，说明本句要让观众看见的变化及事实边界。只认可镜头逻辑时，不能写成用户已经认可外观。
2. 按语义从现有catalog选真实参考并实际看图/视频。区分A视觉参考（组件、字阶、表面与留白）、B逻辑参考（对象关系与镜头推进）、C字形参考（真实字体样张）。B按需，不能用生成图替代真实风格依据。
3. 从原视频确定性抽帧拼参考图，记录源ID、hash和时间；避免混入与当前方向冲突的人物、大面积紫色或3D。必要的历史差异在提示词里明确覆盖。拼图可用于这类探索参考，不继承Deck独立成图的上传限制。
4. 用[通用提示词](../templates/storyboard-image-prompt.md)填本期内容与附件职责。锁定风格、内容准确性和实现边界，把构图/表达留给模型。多方案应在表达关系上不同，不只是换颜色。
5. 保存本期prompt与方向合同，按[探索入口](exploration.md)已有direction gate检查发送文本。使用Ego Lite与用户指定的ChatGPT Pro，显式点击“创建图片”，核对附件和实际生成状态。模型菜单与生图功能分别确认，不冒称某个图像后端型号。
6. 用户授权多段并行时可用多个space，每段一组上下文；本次两个space各10张是成功用例，不是固定配额。遵循Ego所有权与当前平台限制，发送至少错开5秒；已受理不重复发送。上传/外部生成仍需当次授权或现有会话明确授权。
7. 下载独立原图，按实际图像身份去重并验证解码/hash，保存对话链接和安全的来源记录；做可点击原图的总览。标出过量强调色、灰色、小字、虚构数字、连续性问题。不能只凭缩略图或数量正确宣称视觉通过。
8. 按[选型前端合同](route-and-storyboard-review.md)交付全部候选、助手整组预选、理由与适配限制；用户建议/选择分别保存并绑定图像hash。用户可选整套或局部镜头，确认后实现。把选中表达映射回真实组件和源码，替换本期内容并按录音重排时序，检查真实关键状态及短动画。静态图认可不等于动画认可、公共组件API通过或真实操作证据；正式门禁沿用原流程，不增加新的固定审批轮次。

方案数和关键状态数按需求选：可以少量方向，也可以每段10套；九宫格是选型工具，不规定剪辑次数。有限返修保护未点名部分，已授权直出不重复索要确认。

## 本轮经验：先分清动画路线，不只加负面提示词

先由助手提出制作方式与表达建议，Fred调整选择。若选Remotion，再决定是否用二维标签/对象运动或合适的代码组件承载比喻；若选生成视频，则走对应工具流程，卡通外观按内容另定。图像不符合路线时标为“仅逻辑参考/需重做”或排除，不能因为交足10张就视为合格，更不能将助手勉强预选记成用户认可。

多段任务先做整片呈现规划，将本段职责和相邻段交接带入各space；避免各组只看同一参考拼图而都生成桌面窗口。差异来自信息对象与动作，不靠随机换皮。

发送时确认“创建图片”标签真实保留在已发送消息中（填充输入框可能覆盖此前选择），并检查图片生成状态。仅长篇思考、查字体或写代码且未出现图片任务时，停止错误模式，在原space纠正后发送；有已受理图片任务时不重复提交。
