# 横竖媒体、设备载体与毛玻璃前景

当场景使用`media-layout`、`device-frame`或`frosted-focus`时按对应小节读取。适用规则为F20、F06、F05；角标由`brand-corner`单独带入；录屏/实拍/生成视频作为主要观看内容播放时关闭新增右上角角标；Fred 人物 B-roll 全屏播放除外，保留角标（见 fred-remake `corner-branding.md` 108期补充）。全屏和窗口播放都适用，源素材自带标识保留。混合场景在原`brandCorner`记录显隐区间，解释动画沿用原有规范。

## 三层几何分开，动作相互关联

| 层 | 记录在本期已有计划中的决定 | 局部修改时保护什么 |
| --- | --- | --- |
| 原始内容 | 真实路径/hash、有效内容ROI、原生尺寸、入出点与帧率 | 内容身份、文字/产品细节、原比例、播放连续性 |
| 外框/设备 | 全屏/窗口/电脑/手机/iPad，真实屏幕bbox、内边距、圆角和缩放锚点 | 用户认可的载体、光学大小、动作与画面占比 |
| 前景与品牌 | 文字组、蒙版职责、角标独立层、字幕/关键UI安全区 | 字体/字重、层级、对齐、局部底色对比 |

新增记录写进原`visualPlan`与素材台账；这些是设计决定，不宣称已有自动适配API。只有源素材或画面职责改变时重新求几何，不因换一张图重做全部布局。

横版电脑/窗口通常更适合横向实操，竖版手机录屏可放手机或竖向内容框，iPad按实际画幅和内容职责选择。先验证真实素材比例；`contain`保全内容，`cover`只在允许且记录ROI的裁切时使用，不能拉伸或裁掉关键结果来填满设备。多对象比较按可见内容的光学大小与共同基线协调，不能只让透明PNG外框同宽。

入槽前先辨认源素材已经带有的设备边框或浏览器外壳，避免在黑框上再叠同样的黑框。需要嵌入真实设备时按有效屏幕框裁切内容，外壳与内容裁切同步；更换载体不改变真实UI的比例。

采用已有成片进入整片前，核对其内嵌字幕、角标、外框、旁白、BGM、源声/音效、原速度与尾部保持；在原素材/声音计划中明确每层保留还是由本期接管。不能把完成片当无声裸录屏，再重复叠字幕、角标或混音；需要完整源声时保留末句和尾音，声音处理沿[背景音乐](background-music.md)及当前音频职责执行，不默认去掉已有声音。

用户要求去边/全屏时，分开定位源素材内置边、外部容器留白和真实页面背景；网页白底不是排版白边。按有效内容等比作最小必要裁切，并在源页面滚动、缩放和关键结果阶段复查UI，不能仅验证一帧。用户指定设备或稳定播放时保留该选择，通过合理屏幕比例和薄框扩大内容，不强加持续推拉。

### 同类播放窗口的尺度

录屏/成片是当前主要观看内容时，先让实际内容占据足够大的可读区域，再安排外框和辅助文字。对照本期已满意的同职责播放段，统一稳定播放态的可见内容宽度、光学大小与重心；不能只统一PNG或DOM外框宽度，留下过厚设备边、页眉和黑色两侧空槽。多视频比较、缩略总览和讲解配图有各自职责，不强行使用主播放窗口尺寸。

媒体可以铺到字幕后方，字幕遮住无关背景或非关键底部可以成立；关键按钮、结果文字、人物表情和当前阅读区仍须可见。不要为字幕永久空出整条底部而把视频整体缩小。改尺寸时检查真实播放中的有效ROI、字幕出现窗口、载体入场/缩回和相邻出口；用户已保留的窗口表面、圆角和设备身份不随放大自动删除。2026-10-04 Fred进一步明确将108期v9大播放外壳作为后续全屏主视频默认：实际调用[FullscreenVideoWindow](fullscreen-video-window.md)，4K为3600×2027.11、圆角48、向下32/模糊50px黑色13.33%阴影，居中。多窗比较、设备内播放与解释动画仍按各自职责，不将此尺寸套到所有构图；当次明确要求优先。

窗口型品牌落版被选定时，画布底色、窗口表面、左上按钮、Logo与文字组分别记录；黑舞台＋白屏幕是可选对比，不是所有结尾的默认。保留官方Logo身份，必要时只处理透明边/白底，不重画标识；浅色承载面用清晰深字。整组以可见Logo轮廓与文字测视觉居中，去掉重复收尾小字，不能只把每行分别居中就认为组间关系成立。

## 播放速度独立于载体运动

先按口播划出连接/处理/结果等实际阶段，再安排每段入点、速度与停稳。内容浏览、流程总览可以加速；精读、证明操作和关键结果需要留可读时间。用户要求“完整播完”时映射目标首尾并包含最后内容，不能靠截断假装完成。

源帧率与时间单位明确；恒定速度可按`sourceTime = sourceIn + elapsed * rate`计算，分阶段速度连续衔接。帧范围半开/闭合遵循本期Manifest及渲染器约定；不得把秒数直接当帧号。镜头靠近、媒体在屏幕间交接、蒙版显隐都沿同一媒体时钟；放大后缩回仍是同一源文件、同一任务/弹窗与连续源时间，不能切到另一张近似界面。没有阅读或交接职责的推拉可直接去掉，让真实关闭/返回动作自然承接。画面加速不自动改变口播。

分别排查镜头变焦是否过慢、源操作是否被慢放、停帧是否有阅读目的；不能为凑段长统一拉慢或在无信息位置冻结。稳定阅读可以成立，要能指出此时在读什么、为何需要停留。优先调整素材入出点和操作分段，按本期口播检查实际速度；不规定统一倍率或最长静止秒数。

用户要求多个例片“都在播放”时，每个槽绑定实际视频和自己的源时间，不用poster、截图或固定首帧冒充播放。先比较源片与最终MP4同时间的实际状态，区分源片自带停顿/黑场、合成取帧异常和播放器卡顿。例片展示默认按自然速度选有内容推进的有效区间；循环只用于允许重复的展示素材，记录源首尾与接法并看回绕，不能把真实操作重复当作新的结果。四槽合成一个槽或跨场景交接时，媒体时钟独立于位置/尺寸插值，检查交接两侧源PTS；不因组件重新挂载把内容倒回开头。

真实操作与解释性聊天分清用途：示例聊天可采用熟悉的气泡、头像和消息顺序提高可信度，但不冒称实际客户记录。隐私遮挡沿用当前范围；用户撤销普通信息遮挡后核对相关层，真正凭据继续局部保护。播放映射或裁切改变后重查保护层覆盖，不用大面积遮罩掩盖内容。

“全屏”先结合现有画面解释：内容在认可载体内尽量填满，还是内容接管最终画布。用户已强调保留外框时直接保留；有实质歧义才问。屏幕接管全屏使用真实屏幕内容框过渡，见`skills/fred-remake/references/device-camera-rhythm.md`。

### 继承实际末态再交给前景

在既有 `boundaryContract.enter/exit` 记录实际源时间、滚动、相机与载体几何，沿 `sourceMapping` 声明源身份、全局锚点、源入点和速度。`scene.py` 带出邻段已声明映射和边界，不从相同截图推断连续播放。

`templates/components/component-adaptation.ts` 的 `mediaTimeAt` 用全局帧算源秒数，`continueMediaMapping` 在真实交接帧建立下一载体入点，支持继续、改速和显式rate=0保持；只解决恒速区间及分段改速的时间连续，不读取素材、不推断滚动/相机、不替代原生取帧与接缝审看。加蒙版不自动停帧或重启源时钟，有目的的保持仍可采用。


“在上面基础上”“上面加蒙版”“从画布提起再归位”先检查是否延续同一对象。若是，下一段承接实际输出末态：源文件与源时刻、页面/滚动位置、相机位置与透视、对象尺寸/层级，以及继续播放还是有目的的保持，写入现有handoff与媒体映射。不能只复制相同布局，重新挂载后把源视频或相机回到起点；新增前景负责接走观点，底层按当前语义继续或停稳。

画廊中提起的视频来自当时真实槽位与源时间；归位时对齐仍在推进的画廊状态，不返回过时截图。需要尾态截图时，从当前实际渲染状态取帧并核对，辅助composition的[时钟范围](render-and-delivery.md#辅助composition取帧的时钟范围)也须正确。接缝两侧比较真实UI、滚动位置和相机/对象几何；发现跳页或重置先修来源与时钟，再决定是否需要有职责的转场。

## 黑白毛玻璃负责从材料转向观点

1. 让观众认清当前材料；上游已建立的界面、照片或设备直接承接，无需重复重开。
2. 在前一帧同一媒体状态上减弱背景干扰，按实际对比选黑/白蒙版与适量模糊。黑蒙版可承载清晰白字，白蒙版可让黑模块/窗口接管；不固定全片底色。
3. 保持前景文字/Logo清晰；按本句出现、归组、停稳、替换或退出。同语义组字体一致，整体重心与底部留白协调。归组总结可按当前语义使用窗口型模块与分行文字，处境列举可使用逐项胶囊；X019/R053是可检索关系，不是固定组合。
4. 下一句仍依赖材料时恢复清晰；需要交接时沿现有设备/内容状态衔接，不突然重开一个无关背景。

蒙版不能把前景文字与角标一起糊掉；全屏遮罩覆盖最终画布，设备内遮罩与屏幕裁切共用几何。背景动作是否继续由语义决定：已要求“持续动着”时保持播放；需要固定底图时才冻结，不能把加蒙版默认等同于截图。查询T07可取失焦与前景接力的准确动作参考，不能把它当作已经参数化的通用滤镜。

多次使用毛玻璃可以成立；检查每次是否接走新的内容重点。不用固定透明度、固定出现秒数或次数上限替代实际可读性判断。

## 同一个输出里核对

检查最终视频中的原图/录屏身份、横竖比例、有效UI、源末尾、进入与退出、媒体时钟、外框连续、文字完整、角标局部对比和听得见的动作声音。优先看用户指出的真实时间窗口及相邻接缝；修改播放方式后复核保护层。交付分辨率与来源分辨率分开记录，放大的1080p不能标为原生4K。
