# 提示词聚焦与图片局部特写

用于完整提示词讲解、原图对比、单处或多处细节放大，以及“讲到哪里，镜头就带到哪里”的返修。核心是让当前口播对象可读、可定位，并保留它与上下文的关系。下列是可跨期使用的方法；不是整片模板，也不是已经发布的通用 React 组件。准确场景实现与已认可区间仍按本次合同执行。

## 1. 把口播映射到真实对象

在已有 Manifest / motionEvents 中记录以下关系，不另建一套时间轴：

| 对象 | 当前任务需确定的内容 |
|---|---|
| 原文 | 完整来源文字、显示语言、原文 hash；译文保留数量、限制、否定和条件 |
| 口播重点 | sourceBeatId、准确短语及对应出现位置、进入/可读/离开帧 |
| 图片细节 | sourceAssetId/hash、正确比较侧、归一化 ROI、口播含义和可见依据 |
| 画面状态 | 当前概览、目标焦点、需要保留的上下文、下一焦点和镜头交接 |
| 载体 | 当前组的明暗、形状、媒体框、玻璃底与标签的可见边界 |

时间以当前录音为准，SRT 帮助定位；多个并列名词通常分别绑定 cue，不能在第一个词开始时把后面所有词一起划完。引入或铺垫句先建立整体关系，讲到某模块时才提升它的权重，不让第一个模块从开头一直放大。

先看原图再确定 ROI。口播说到不同区域，就检查每个区域是否真的被呈现；不能用同一建筑代表建筑、河岸、植被等所有含义。缺少证据的区域标明缺口，不靠标签假装已展示。

## 2. 完整提示词作为上下文，当前短语成为阅读焦点

1. 保留完整提示词；需要中文时忠实翻译，不用几行摘要冒充完整原文。用户明确要求节选时标注节选范围。
2. 先让观众辨认这是完整原文，再按口播把镜头靠近重点。完整原文存在于同一内容层，不要求全景时每一个字都能同时读清。
3. 强调色在文字下方从左到右扫过；划线也可使用，但必须在最终观看尺寸上明显。颜色按当前合同选择，紫色或黄色是候选，不是所有任务的默认色。
4. 镜头落到当前短语或它所在的句群，留出必要上下文；下一句换焦点时直接移动到新区域。不能每次先退回全文，再重复放大。
5. 稳定可读时保持镜头坐标不变。需要扫读整段才安排有目的的滚动；全文本来能放下时不添加无意义滚动。

### 文字几何与高亮实现

- 字体加载完成后，用真实 DOM / Range 的 `getClientRects()` 测当前短语。测量树与显示树使用同样的字体、宽度、padding、行高和换行规则；先还原预览外层 scale，再换算到设计坐标。
- 以字符范围或稳定的出现序号定位重复词；查不到、匹配重叠或歧义未解决就报出具体文本位置。不要用 `indexOf()` 的首次匹配默默选错第二处。
- 高亮用背景、绝对定位底色或独立遮罩绘制，不改变字重、padding、行高或布局。跨行短语按多个实际行框揭示；不要为了测一个框而强制 `nowrap`，造成原文换行和载体溢出。
- 从目标字高及句框宽度决定 scale，不能全片固定同一倍率。以左上角为变换原点，目标焦点为 `(cx, cy)`、期望屏幕位置为 `(ax, ay)` 时，使用 `tx = ax - cx * scale`、`ty = ay - cy * scale`。
- 载体、文字、选区作为同一组接收镜头变换。黑色外壳与白色内页不能使用独立缩放，避免白底跑出黑底；阴影置于外层，正文在内层裁切。

## 3. 图片特写：先认识整体，再看证据

提示词退场后先建立左右原图或对比网格，并留足与当前口播相称的辨认时间。建立全貌时可按口播依次标注对象，不能两张图刚出现就立刻放大。概览停留不是完全没有反馈，也不靠持续漂浮填满时间。

根据当前问题选择构图：

| 口播责任 | 可选呈现 | 检查重点 |
|---|---|---|
| 解释一个很小的细节 | 原图选区＋连线/小圆点＋局部特写窗 | 能反查局部来自原图哪里；不用大白卡再次放完整图片 |
| 同一句需要看多个区域 | 主图＋多个局部窗，随语序依次建立 | 区域互不重复、连线不接错；数量以可读为限 |
| 直接比较同一个属性 | 两侧相同职责的 ROI 并排 | 采用可比的尺度、窗口几何及裁切依据，不靠不同倍率制造优劣 |
| 重点从左侧转到右侧 | 当前主图扩大，另一侧缩为上下文；随后交换主次 | 标签和原图身份连续，缩小后仍能认出是哪一侧 |
| 下一句讲同图的另一区域 | 保留当前近景，镜头或局部窗口平移至下一个 ROI | 不反复回到概览，不突然更换坐标原点 |

形状由细节轮廓决定：紧凑物体可用圆形，横向连续结构可用胶囊，建筑、文字、长直边可用矩形。默认同一轮承担相同职责的窗口同尺寸、同形状；不同轮次可换，具有不同职责的纵横细节可按内容说明例外。不要一侧用圆形、一侧用矩形无理由地比较同一属性。

### 裁切与连线实现

- ROI 绑定原始图片的归一化坐标，不绑定缩略图截图中的绝对坐标。记录图片宽高、当前显示框与 `contain/cover` 实际内容区，扣除留白或裁切偏移后再定位。
- 设原图像素 ROI 为 `(x, y, rw, rh)`，目标窗为 `(dw, dh)`，等比填充的初始比例可取 `s = max(dw / rw, dh / rh)`，平移以 ROI 中心对准窗口中心。边界 clamp 后重验关键内容；主体被裁掉时调整 ROI、窗口比例或留边，不继续放大掩盖问题。
- 源选区、小圆点、连线端点从当前主图的同一变换矩阵计算；主图缩小或镜头移动时同步更新，不能让线仍指向旧坐标。源选区对应完整 ROI，局部窗显示它的真实细节。
- 连线颜色按所在区域对比选择，白线适合深色媒体；白底上可用深线或克制的衬边。线条是来源关系，不是必须添加的装饰。
- 需要直接切入特写时，可用短遮罩或有目的的镜头切换带到已就位的局部，不必展示从小图拉大到位的全部过程。交接前后仍须能判断对象身份和来源。

## 4. 主次变化之后要停稳

将一个镜头明确分成进入、阅读、交接或退出。曲线只用于有意义的变化区间；阅读区间的相机状态精确保持，禁止由整段时间驱动的持续上移、微缩放或呼吸漂浮。

相邻镜头衔接时，从上一镜头真实结束状态计算下一镜头起点。连续局部讲解直接前往下一焦点；只有口播回到整体判断时才归回概览。返回阶段与结论强调共用连续的主次状态，避免一个缩放状态刚恢复，另一个权重立即接管导致跳一帧。

长口播不等于拉长运动：把时间留给清晰、稳定的结果。同类镜头可参考相近的收束力度，但移动距离、阅读量和语速决定各自的时长，不固定切镜频率。

## 5. 透明底负责承载，不抢主体

透明或磨砂表面贴合当前媒体范围，留出必要的边缘、轻阴影和标签空间。不要用远大于图片或视频的空白面板补面积。纯白画布按当前要求保持 `#FFFFFF`；玻璃的局部合成颜色不能把整片变成米黄底。

区分两种层：背景模糊/蒙版弱化上下文，清晰前景承载当前原文或细节。模糊不能施加到需要读的文字上。连续强调保留同一表面节点，随 cue 替换焦点，避免每句话都重新闪现蒙版。

多组内容保持统一字阶、对齐与材质质量，同时按职责在白色玻璃、黑色载体、真实屏幕/工作台、开放比较舞台中选择。当前用户要求交替时在其范围内安排；不按页码轮换、强行用齐样式，或把各组内容都塞进相同白胶囊。示意工作台不冒充真实操作证据。

## 6. 把检查放进现有样片与最终 QC

| 检查窗口 | 必须能确认的行为 |
|---|---|
| 全文建立 → 首个重点 | 完整原文没有被摘要替代；焦点跟随首个真实口播 cue |
| 最长短语、重复词与跨行强调 | 精确命中正确字符，高亮不挤动字形，放大后不被外壳裁切 |
| 两个连续焦点 | 下一对象承接前一状态，没有无因归位或全局漂移 |
| 全貌 → 首个局部 → 多处局部 | 观众先能认识原图；每个局部与口播、源选区、标签一致 |
| 最大放大、主次交换、返回末尾 | 同轮几何一致；标签完整；邻接帧没有卡顿式跳变或残留线条 |
| 稳定阅读窗口 | 检查相机矩阵与静态前景 ROI 是否保持；背景视频在播放不能误报成相机漂移 |
| 1080 样片与实际 4K 输出 | 字体、换行、焦点和裁切一致；高亮与边框在最终观看尺寸可见 |

先看布局静帧，再正常速度播放完整语义窗口；交接处按原生 fps 密采样。用稳定对象的屏幕 bbox、变换矩阵或 ROI 差分查漂移，不用全帧亮度证明局部稳定。4K 下毛玻璃或字体采样可能不同，应在实际输出中核对；不能因低分辨率样片正常就跳过。

这些检查并入已有修订表和代表镜头证据，仍使用 [生产门禁与交付](gates-and-delivery.md) 与 [全帧异常检查](render-failure-checks.md)，不新增批准步骤。通用表面/聚焦能力见 [内容与运动组件](content-motion-components.md)；设备接管全屏见 [设备镜头与内容接力](device-camera-rhythm.md)。
