# 动效差异与渲染异常排查

出现下列症状时按证据选检查项；这不是每个视频都要套用的动效配方。

## 动作方向对了，但过程不像

- 把外壳、内部胶囊/卡片、圆点、描边路径分别量测起点、中间态与终态 bbox。记录尺寸比、缩放中心、相对位移与时序，不能只给父容器加一个 scale 就认为场景实现完成。
- 白色弧形刷过要区分“静止内容被遮住”与“内容本身平移”。复制实际遮罩边缘、行进方向和加减速，不改成淡出或整屏滑走。
- 圆点绕圈与路径显现若属于同一动作，使用同一路径几何/长度进度；核对起点、方向、圆角转弯与完成时刻，避免点走圆形而描边走胶囊形。
- 副本收回要确认扩展的是卡片背板、卡片本体还是整个窗口。保持不应移动的工作台/标题稳定，不把局部动作扩大成全场变形。
- 同样的终帧不能证明过程一致；用户说缩小不明显时，先比较内部尺寸变化和持续时间，不先加弹跳、模糊或额外装饰。

## 线条未开始却出现圆点，或收回后留线头

先定位孤立点对应的实际节点。SVG 的圆头描边在 dash 绘制进度为零时可能仍显示端帽；对本应未出现的路径显式不绘制（例如 progress <= 0 返回 null），不要只把 dash 长度设为零。收回时同步连线及其依附对象的结束窗口，检查开始前、首个可见帧、结束前后和反向 seek。保留有语义的项目符号、光标及环绕标记；不能全局删除所有 circle。问题跨多个场景出现时检查共享 primitive，但仍保护未点名的有意义元素。

## 高亮时文字跳动或重叠

- 排查 border-width、padding、字体 fallback 与动态容器尺寸是否改变内容盒。高亮可用独立绝对定位描边、outline 或 inset shadow，或者预留固定透明边框。
- 方案由参考决定；不是全局禁止 border 动画。验收时比较高亮前、中、后的文字 bbox，并检查圆角与描边是否被裁掉。
- 独立检查最长标签、最大缩放、旧词退出和新词入场；终态无重叠不能证明交接时无叠字。

## 文档缩放的细字抖动与层级跳变

1. 先分类并定位帧范围：整张图片缺失/变白、交叠边缘突然换前后、细字与表格线明暗跳动，还是播放器缩放产生的观感。对实际出问题的 MP4 原生帧率密采样，结合正常速度播放；不要从一张稳定帧推断原因。
2. 记录生产帧状态：对象身份、位置、尺寸、图片布局尺寸、缩放、裁切、z-index 和显示区间。按焦点建立、保持、回落、下一焦点接管逐段检查；维持稳定 key 与素材来源。
3. 层级只在语义交接确实需要时切换。避免把连续强调进度直接取整为不断变化的 z-index；可在单个突出区间固定优先级。必须检查区间两端前后数帧，以及阴影、邻卡的实际相交区域；层级数值变化本身不等于可见闪帧。
4. 图片布局随容器每帧变化、百分比宽高配合 cover 时，检查是否出现重复重采样或裁切变化。可试固定图片布局尺寸，使用同一比例的 transform 缩放，由外层槽位裁切；布局尺寸从素材和最大显示需求推导，不固定成某期数值。不做非等比拉伸，也不保证此法能消除所有高频细线闪动。
5. 分别验证层级和采样假设，每次只改一个变量。回归测试调用实际组件/帧状态或测真实渲染帧，检查单个突出区间的层级稳定、图片比例、交接边界与末态。记录失败版本、通过版本和图像证据；不要把源码字符串断言当作画面连续性证明。
6. 同内容、同帧时刻、同显示尺度对比前后版本；低分辨率样片变稳不能证明 4K 播放也变稳。保留原图，不默认用模糊、光流或复制帧掩盖问题。若编码帧正常而仅特定播放器异常，记录播放器及显示缩放，换播放器或原尺寸复核。
7. 分开报告“实现风险已确认”“该项修复测试通过”“采样未见异常”“用户认可”。多个变量一起修复后获认可，只能说明该组合被接受，不能宣称某一因素已被独立证明为唯一根因。

## 预览正常，4K 首帧空白或出现碎块

1. 从出问题的最终 MP4 提取真实第 0 帧和首批连续帧；另取异常时间前后逐帧图。疏采样 contact sheet 可能跳过唯一坏帧。
2. 检查图片解码、字体就绪、组件重复挂载和缓存；Remotion Img 是必要的加载约束之一，不等于实际编码首帧一定正常。
3. 检查无必要的全屏 transform/clipPath 叠层。动作结束后可恢复 none，但先验证移除样式不会改变定位、层级或裁切语义。
4. 单独复现坏帧，再逐项比较并发数、浏览器版本或安装版本支持的渲染后端。记录每次结果；不要未经验证就把“GPU 问题”写成确定根因，或把某个后端写成通用必选项。
5. 优先从源实现修正并重渲染。只有坏帧属于明确的静止保持段、相邻正确帧与其意图完全相同，才可复制邻帧替换；运动段不能这样补帧。按原时间点重新渲染正确源状态属于另一条修复路线，条件见下文；不能剪掉时长或改变音轨。
6. 补帧后保留总帧数与时间映射，重新验证实际最终输出。不能用修补前的 PASS/hash 交付修补后的文件。

连续首帧示例（只用于抽样诊断，输出到本次过程目录）：

```bash
"$clip_ffmpeg" -v error -i "$clip_video" -vf 'select=lt(n\,8),scale=480:-2,tile=4x2' -frames:v 1 -update 1 -n "$clip_first_frames"
```

这些变量需事先绑定当前真实路径；图片不存在或命令没有输出帧就是失败，不能只看退出码。极短视频不足 8 帧时按实际帧数调整。

## 全帧异常检查与偶发白帧

### 交付前：不漏时间帧

- 对实际交付 MP4 的每一解码帧做异常空场与亮度突变检查，绑定文件 checksum、扫描帧数、零基帧号和真实 PTS。核对扫描覆盖完整帧数；不能加低频 `fps` 或跳帧 `select` 再声称全帧检查。空间降采样可用于整屏异常初筛，但不能证明细线、局部碎块或原分辨率画面无异常。
- 可统计近白/近黑像素占比、亮度范围、相邻帧差，以及“本帧突变、下一帧恢复”的孤立异常。按真实运动合同检查应该持续存在的主体/ROI；纯白背景不等于允许整个主体消失。单一全白阈值不覆盖黑底、彩底、局部缺失和所有闪帧。
- 候选必须提取原尺寸坏帧及前后至少两帧人工复核。设计允许的空场、闪光或正常切换按合同解释并记录，不能自动删掉；未解释候选保持待修，不能发成片。零候选仅代表该检测范围内未发现异常，不代表全片视觉通过。
- QC 分开记录：完整解码、全帧异常扫描、视觉观看、用户认可。合法编码的白帧也能完整解码；低分辨率样片正常不能替代最终高分辨率的扫描。

### 防止局部缺失漏检：对齐已认可样片

- 已有同内容、同时钟样片时，在修复编码前增加逐帧保留区域对比。先核对帧数、真实 PTS、映射时钟、画幅、颜色范围与统一采样尺度，再比较，不能只凭 fps 相同按帧号硬配。
- 全屏白帧、相邻帧差和孤立帧检测会漏掉“只有文档消失、外壳仍在”的局部异常，尤其发生在原本就快速运动的转场。结合持续主体 ROI、局部差异图与样片对照，不把整屏扫描零候选当作局部无缺失。
- 改动遮罩只排除明确授权修改的对象及其实际运动区间，并记录坐标、时间和理由。尽量不用整幅宽条或全时段遮罩；被遮掉的区域必须用新设计的帧状态/原尺寸证据另验，不能形成检查盲区。
- 分辨率、抗锯齿、色彩转换与重编码本身会有差异。阈值从正常片段校准，复核异常帧及前后至少两帧；不把某期阈值写成通用 PASS 标准，也不把“差异小”写成像素完全一致。
- 先汇总整屏扫描、ROI 与基线比较的全部候选，再统一修复和一次编码；避免每发现一帧就重编码整片。最终输出仍重跑全部检查。

### 出现异常：区分帧状态、截图与编码

1. 先确认错误已存在于最终文件的解码帧，而非仅某播放器；保存参考片段，不覆盖证据。对比同帧预览、实际生产状态和时间戳。静止保持段突然全白，不能归因于尚未开始的缩放曲线。
2. 冻结相同源码、素材、字体和配置，在坏帧索引做原尺寸诊断重渲染。单帧正常只证明该独立运行正常；它同时可能改变调度、输出格式等变量，不足以证明 GPU、并发或编码器是唯一原因。
3. 若确定性帧状态正常、异常只在批量出片偶发，保持已认可设计不变，优先采用“无损逐帧序列 → 编码前全帧检查 → 编码 → 最终 MP4 全帧复检”。这是一条用于隔离截图/合成与编码的修复验证路线，不是已证明能根治所有闪帧的通用配置。
4. 编码前帧就坏时查绘制就绪、字体/图片加载、截图与浏览器合成；中间帧正常但最终解码坏时再查编码、封装与解码。保留对应中间帧及编号映射，避免两层同时改导致无法归因。
5. 并发数、浏览器版本、渲染后端每次只改一项，记录复现次数、坏帧位置和输出 hash。不要反复整片重跑直到偶然通过并宣称根因消失，也不要修改已认可字体/动效来掩盖出片异常。
6. 不剪掉坏帧、不缩短时长、不默认光流补帧。复制邻帧仍受静止保持段限制；运动段按正确帧状态重渲染，满足下述条件后才可替换。修复、拼接或重编码后旧 QC/hash 失效，重新验收实际交付文件。

### 同一源状态的精确帧重渲染

- 仅在有确定性源实现、且修复在当前制作授权内时使用。冻结源码、Manifest、跨目录依赖、素材、字体和渲染配置，绑定每个异常帧的真实 PTS 与源时间映射；无源实现不能据邻帧猜造运动。
- 在原尺寸、原帧时刻重新渲染，核对主体完整性、字体/图片加载与前后运动连续性。非全白不代表正确；仍要比对应状态/ROI。单帧渲染成功不证明批量异常根因已解决。
- 替换的是该帧应有的源状态，不是邻帧、插值或延长停留。优先在无损帧序列/母版上替换后只编码一次；只有压缩 MP4 时评估额外代际损失，显式固定颜色范围、像素格式、时间基准并复核颜色漂移，不把 RGB 往返后整片重编码称为无损修复。
- 保留 rejected 文件、替换帧列表、原/新 checksum 和构建 hash。先在过程目录完成验证，再移入最终输出目录；失败候选不得以正式交付文件名暴露为已完成。
- 复核完整帧数及真实 PTS；只有验证恒定帧率与起点后才可使用 `frame/fps`。不改声音时保留音轨并核对包 hash/PCM；最后重跑解码、全帧扫描、局部对比和实际最终文件 QC。

仅诊断请求不自动授权修复或覆盖成片；可以输出隔离的测试帧与诊断报告。病例的具体时间点、文件和坏帧证据留在 episode，不写成后续项目的固定参数。

## 首尾提取和工具失败

- 极靠近文件末尾的 seek 可能成功退出却没有输出图片。优先使用已确认的实际最后帧索引/时间；nb_frames 不可靠时先计数或解码定位，不猜 duration 减一个固定小数。
- 每次抽帧验证文件存在、非空、能解码，并绑定源 hash，避免读到上次遗留图。
- 运行前验证 ffmpeg/ffprobe 的实际可执行路径；失效 wrapper、门禁参数错误与素材缺失分别处理。相同错误重复出现时先读脚本用法，不继续猜参数。

## 局部表面与内容持续可见

整屏亮度/解码检测不能判断白底上的白色承载是否有一帧消失。对要求持续存在的对象登记真实 ID、可见区间、位置变化和有意遮挡，分别检查表面、阴影与内部内容。测量应来自实际生产状态或真实帧，不能把预期坐标另抄到测试里自证。

定位后对整个相关区间密集抽帧/播放，检查边界附近和阴影 ROI；阈值用同背景正常帧校准，不把某一期亮度写成通用值。可用 `scripts/audit-surface-visibility.py` 对实际 MP4 的指定区间逐帧采样固定 ROI 并生成候选；运动对象应分段或由实际状态导出 ROI，不能用固定 ROI 自动断言移动对象消失。候选需要结合合成与遮挡解释，脚本不作审美 PASS。

局部修复后看完整上下场，再扫描最终编码文件；上游尾态/素材/source hash 改变使相关接缝和 QC 失效。

项目内可用的完整 FFmpeg 示例为 `skills/_runtime/FredTalkApp/node_modules/ffmpeg-static/ffmpeg`（运行前先检查 `-version`）；Remotion 内置裁剪版本可能没有 select/crop/rawvideo。实际使用：

```bash
python3 skills/fred-remake/scripts/audit-surface-visibility.py --input <actual.mp4> --output <process-qc/roi.json> --roi <x,y,w,h> --frames <start:end> --baseline <normal-start:normal-end> --ffmpeg <verified-ffmpeg>
```

坐标使用实际输出像素，帧号零基、右端不包含。`test-surface-visibility.py --ffmpeg <verified-ffmpeg>` 用真实编码 MP4 检验单帧局部消失：画面另一侧持续存在，整屏检测不报空场而局部 ROI 应报候选。


### 通用全帧候选扫描工具

`scan-frame-candidates.py` 将实际 MP4 每个解码帧与 probe PTS 对齐，支持分数帧率及 VFR；输出源 hash、完整元数据、逐帧统计和异常候选组。可调阈值与空间采样宽度，不做时间抽样，也不自动判定美观通过。

```bash
python3 skills/fred-remake/scripts/scan-frame-candidates.py \
  --input <actual.mp4> --out <process-qc/frame-candidates.json> \
  --ffmpeg <verified-ffmpeg> --ffprobe <verified-ffprobe> --contact-sheets
```

Python 环境需要 NumPy 和 Pillow，优先复用已验证的项目 runtime。联系图只是候选定位，逐个按前述规范提取原尺寸帧并解释；局部主体缺失另用 ROI 工具和基线对比。PTS缺失、不递增、帧数不匹配或解码失败均不得当扫描完成；零候选不等于用户认可。
