# 字体、逐帧与像素级场景实现

适用：用户要求接近 1:1 场景实现、认为“动作类似但质感差很多”，或指出字体大小、粗度、框形、镜头速度不一致。执行本文件时，疏采样只用来定位；变化区间以原生帧和实际输出为依据。目标是还原参考的构图与运动关系，不把重设计当场景实现。

## 1. 锁定依据与认可范围

- 读取最新选择和意见，保存参考、当前成片、源码及意见版本的 hash。意见对应用户实际看到的视频，不对应随后改过的活动源码。
- 先完整播放参考与当前成片，列出应有对象、缺失对象、动作顺序、首态、交接与尾态。文字、人物、胶囊、卡片、视频槽、鼠标、蒙版、笔触各自登记。
- 用户整体认可后，锁住当前视频与其源码快照；只修新点名的对象、属性和区间。未发布的实验实现单独保存，不因“更先进”自动覆盖获认可成片。
- 内容允许替换时明确边界：Fred 文案、人物和媒体可以替换，行数、对象数量、槽位比例、锚点与运动关系仍按参考测量。黑白关系按参考片段，强调色只替换原有强调，不把白字、笔触和连接线全部染色。
- 公共 Skill 保存方法，不带入某次项目的密码、素材、文案、成片或全量批准记录。

## 2. 字体不对，重新找字体

不要继续在错误字体上反复缩放，也不要全片套一个默认黑体。

1. 从清晰、未运动模糊、未被遮挡的源帧裁同字 ROI。覆盖代表性的横竖笔画、转角、开口、中文标点及拉丁字母；中文和 Latin 可以分别识别。
2. 检查字形特征：切角、笔端、内白、字面宽窄、中宫、重心与真实粗细。先从已有字体中筛选；不合适就搜索新的可本地保存且许可适用的字体。保存字体文件、来源、许可和真实字重，不以字体名字推断匹配。
3. 用相同文字、相同画布尺度、相同渲染器制作候选对照。先比较 family 和真实 weight，再调可见字高、自然字宽、基线、字号、字距和行距。CSS fontSize 不等于画面中的字高。
4. 去掉背景、阴影、边框和邻字后测墨迹 bbox、笔画宽度及字形边缘。IoU、笔画占比和像素差分只帮助筛选，不能作为“同一字体”或“整片还原度”的证明；检查不同阈值下的结果，并实际查看 ROI。
5. Fred 文案长度不同，先保持参考的信息块和显式换行，必要时在允许范围内调整措辞长度。不要随意压扁字形、极端挤字距或缩小整个标题凑宽。只有参考本身有字形变形时才实现相同变形。
6. 点阵字要核对点阵尺寸、点的大小与间距、点形和字面边界；空心字要核对内外轮廓和填充过程；手绘字不能直接换成普通无衬线字。
7. 冻结字体文件 hash，并等待 FontFace 加载完成后渲染。核对实际使用字体，排除 fallback 和浏览器合成粗体。确认未使用后再移除候选加载，避免每帧工作流带上无用依赖。

未找到原字体时明确记录候选、选择理由和剩余差异。字高合适不代表字形已一致；一次候选胜出不成为所有后续片段的默认字体。

## 3. 按实际帧拆解动作

1. 用 ffprobe 读取源尺寸、帧率、帧数及 PTS。首帧单独提取，检查非零首 PTS、可变帧率和选段起点。输出按时间映射到源帧；源 30fps 到输出 60fps 不凭空增加源动作。
2. 先定位事件，再对每个变化区间提取原生连续帧，包含变化前后的稳定状态。逐帧记录对象出现、消失、换词、遮挡、镜头、蒙版、字体与媒体内部状态；不能只看首中尾或缩略联系表。
3. 分开量舞台镜头、对象运动和媒体内部播放。例如外壳缩小、内部画面推近和文字变小是三个不同参数，不用一个 scale 代替。
4. 记录各对象 bbox、基线、圆角、边框/笔宽、留白、层级、缩放中心、旋转/透视及显隐区间。按实际运动拟合分段曲线，保留停顿、加减速和惯性，不给所有片段套相同 ease。
5. 跟踪器可能误认字幕、窗口边、阴影或相邻对象。对异常跳值检查遮罩和帧图，保存人工修正与低置信度区间；不把误检最大误差当作真实偏差。
6. 为同一对象保留连续节点和稳定锚点。参考通过位移退出就真正移出，不能用淡出或边缘遮罩掩盖时序/位置错误。
7. 多视频逐槽位登记，不用两段循环素材冒充九个窗口；外壳和内部视频时钟独立控制，替换媒体也保留槽位比例、对象数量和交接关系。

每段至少保存：`sourceFrame/PTS → outputFrame`、对象/属性、源测值、新测值、动作区间、依据与置信度。静止重复帧可合并登记；变化帧不能用一个终点代表。

## 4. 像素级对照与返修

- 把源画幅统一映射到输出坐标，使用相同显示比例与时间基准。并排看结构，半透明叠加看边界，闪烁看位移，局部差分看笔画、蒙版和接缝；字体与边缘在输出原尺寸查看，必要时放大 ROI。
- 对相同背景、容器、边框、描边和蒙版比较像素/边缘。替换过的文案与媒体区域按字形观感、字高、基线、对象边界、轨迹和构图比较，不用全画面相似度掩盖结构错误。
- “粗度不对”拆成字体笔画、描边、阴影三项；“框不对”拆成宽高、圆角、边框、内边距、内外层比例和缩放中心；“字大小不对”分别检查字高、字宽、基线及父级镜头倍率。
- 初始定位门槛可用：动作起止/交接误差不超过 1 个源原生帧；1080p 稳定边界/锚点不超过 4px；文字可见高度误差不超过 3%。其他分辨率按比例换算。这些是找问题的门槛，不是自动审美通过条件，也不能让可见错误因“数值达标”通过。
- 先查对象和动作漏项，再校几何和时点，再细调字体、笔触、阴影和边缘。参考片段没有的窗口标题栏、三色点、阴影或边框不要添加。
- 手绘笔触保留路径、笔宽起伏、粗糙边缘和绘制过程，不用一条光滑 SVG 线替代。人物替换保留明确姿态差异，用户停用人物生成后不擅自重启生成。
- 每次返修检查受影响区间及前后交接，再完整播放该条 1× 与慢速，关注速度、阅读停留、遮挡、裁字、基线跳动和末态。只看过几帧就只记这些帧，不能写“全帧通过”。

## 5. 批量出片与独立验收

批量任务采用“可运行实现 → 冻结整批 → 云端排队 → 下载到前端 → 集中对照 → 只重渲受影响条目”。用户明确要先看全部时，不把逐条校准完成作为每次云渲的前置条件。未完成校准的初稿照常产出，但清楚标记“初稿待返修”；这不授予最终视觉通过。阻止运行的编译错误先修，不上传半写入快照。

- 源码、依赖锁、字体和媒体形成隔离快照并 hash 验证。渲染与本地校准并行，复用已核实 runtime；按当前机器实测配置并发，不以降低尺寸、帧率或画质换速度。
- 技术检查、还原度检查、动态观看和用户认可分别保存，并绑定当前 MP4 hash。重新渲染后旧检查/意见保留历史，不自动继承为新文件通过或把用户原意见标成已解决。
- 前端提供原参考/旧版/新版、同步重播、逐帧、源帧与输出帧、慢放、叠加和原尺寸局部查看；新意见绑定用户看到的 hash，避免后台更新后误判验收对象。
- 保存完整 Remotion 源码、独立时间线、示例参数、必要素材、字体许可、锁文件和渲染命令。本地可运行目录与压缩包都保留；交付目录安装依赖、检查所有 composition 并试渲代表片。
- 未发布的实验代码与当前出片源码区分保存。当前活动工程并非每条成片的精确版本时，交付对应快照或逐条版本映射，不声称可重复生成同一文件。
- 下载后核对 hash、完整解码、尺寸/帧率/帧数/PTS/音频策略；这些不能替代视觉检查。云端无待执行任务、下载校验完成后按授权生命周期关机。

最终报告说清已产出数量、暂缓项、当前返修、验证范围和观看入口。即使用户整体认可，也不捏造自己未做过的逐帧或动态验收。
