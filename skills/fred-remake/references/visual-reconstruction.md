# 视觉拆解与接缝实施

## 记录什么

每个片段只维护一份事实源，至少记录：

- `implementationMode`、源文件路径/checksum、源尺寸/fps/duration、音轨与音量策略。
- `openingReference` 与 `finalReference`：路径、checksum、职责。用户上传名字叫“尾帧”的图也可能被明确指定为本片首帧，以用户职责说明为准。
- `preserve` / `change`：哪些画面、节奏、文字、音效已认可；允许变化的维度。
- `exactScreenWords`、字体 family/weight、实际字号、行高、letterSpacing、文字可见 bbox；无法确认字体时记录候选与视觉差异。
- `geometry`：设计画布、卡片 bbox、圆角、边框、图片槽位、可见 Logo bbox、z-index、遮罩范围。建议同时记像素与画布归一化值，换分辨率整体换算一次。
- `motionEvents`：语义责任、开始/结束帧、起止位置/尺寸、曲线、前后状态、定格区间；不用每句固定时长。
- `audioPolicy`、`sourceTimeMapping`、`frameRatePolicy`、`userAcceptance`；记录真实原音轨是否保留，不擅自加 BGM。

疏采样用于发现变化段；普通运动诊断可用关键区间 6–12fps 连续帧并播放检查。用户要求逐帧、接近 1:1 或像素级场景实现时，按 [pixel-motion-reconstruction.md](pixel-motion-reconstruction.md) 提取源原生连续帧、建立输出帧映射，不能把 6–12fps 采样当作全帧验收。特别关注 t=0、第一秒、用户点名区间、每次接替两侧、末尾 0.5 秒。

## 字体与排版

涉及字重不匹配、短强调遗漏或像素级差异反馈时，按 [fine-detail-repair.md](fine-detail-repair.md) 做局部证据对比；ROI 必须排除边框与邻字，笔画密度只作辅助指标。

1. 先对齐参考图与目标图的画幅、内容缩放和坐标系，再比字形。
2. 按字形→字重→可见高度→宽度→行高→字距调整。量测包含中文标点和中英混排，不用 CSS fontSize 当可见字高。
3. 冻结字体文件和字体加载；字体 fallback 或字体未加载会表现为布局跳动。
4. 给动态标题预留独立阅读区。卡片放大后，标题仍须避开相邻媒体，不能只检查 settled 初态。
5. 文字来源错误要改文字，不用截图遮罩把错字盖成不可编辑的一团。参考原字形就是要保留的位图时可沿用，但披露文字不是重新排版。

## 滚动、突出与回落

- 用户要“从左往右滚动再突出”时，整个轨道向右移动到目标位，再由当前卡片接管注意力；不要只放大一张又复位，其他全静止。
- 用共享位置进度确定所有卡片轨道；必要时叠加短延迟，距离焦点越远可轻微后退，避免刚性平移。保持视觉秩序，不引入无理由的摇摆、旋转或模糊。
- 延迟必须在下一次信息接替或合并前收敛。更换焦点时避免同时两个大标题争抢。
- 例如约 70ms 的最大跟随差、约 6% 的两侧缩小可以作为小样起点，不是默认必加参数。用户未要求更灵动时，先忠实场景实现原曲线。
- 边框过粗：减小描边/内边距，保持图片槽位与外壳圆角协调。透明外壳不等于真实文档内容也应透明。

## 文档表面与标题

- 用户嫌像手机外壳或明确要求无框白纸时，去掉容器描边，缩小圆角，以浅接触阴影和下方柔和投影区分白纸与纯白背景。不要只反复调细黑框，也不默认给所有参考换成这一风格。
- 用缩放、轻微抬升及同步扩散的阴影表达高度，不用无理由的透视倾斜、旋转或循环漂浮。投影不可形成深灰光圈，放大回落全程检查相邻纸面与阴影的遮挡。
- 把文档名称作为独立的大字标题，保留截图内部真实内容；不为增强识别性伪造或重排证据文字。标题大小按画幅及最长名称测量，不能把某期字号当统一默认值。
- 区分“容器无框”和“截图内部无框”：表格线、真实 UI 边界属于内容，除非用户要求，不随外壳一起清除。调整内边距、圆角或缩放后，检查截图宽高比、上下裁切和最大状态的标题间距。

## 混合修复接缝

### 分句连续性

- 首帧权威是用户当前指定成片的实际尾帧，不是旧版本组件、旧参考 PNG 或文件名中的“OK”。记录上游视频 checksum、实际尾帧索引/PTS、尾帧图片 checksum 和下游版本。
- 源组件可复用时，把其终态与当前成片尾帧对照再引用。组件相同不保证字体、素材或导出版本相同。
- 上游更新后，旧接缝 PASS 失效。只修下游声明的承接区间；不连带改变后段字体、音轨或结尾。
- 使用位图尾帧承接时披露原分辨率与放大方式，不冒称重新生成的原生 4K。源路径消失时只允许用 checksum 相同的已验证文件接替；找不到同内容来源就暂停，不用“名字相似”猜测。

### 接入规范

适用于局部开头坏、后面好的源视频，不代表全片 Remotion 重建。

1. 定位最后污染帧、原动画第一个可用稳定帧及其真实时间。若没有干净接缝，扩大重建区间或说明必须重建更多内容，不能用闪白掩盖。
2. 黑卡保持阶段从 t=0 就正确显示，独立白底与干净裁切，不出现旧键盘、输入框、刻度或散点。用户只要求去外围噪点时，不侵入文字/Logo 内部。
3. 新内容承接原动作方向和视觉中心。黑卡退出、白卡入场可以重叠，但文字阅读区不能打架；不要出现无语义的整屏闪白或瞬时空场。
4. 静帧作为接入目标时必须提取该时间点的实际源帧。接入前和接入后图形 bbox、缩放、位置、亮度和裁切连续，不只检查“时间对了”。
5. 记录输出时间到源时间的映射。例如时长不变的开头替换，`sourceTime = outputTime`；若裁切或增加停留，写出新的分段映射并同步音轨。
6. Remotion 的 Sequence、trimBefore 和不同视频组件的时间语义，以安装版本文档为准。不要同时全局 seek 和局部 trim 导致双重偏移。
7. 尽量保持一条连续音轨，视频层静音后单独挂音频，防止双音轨、重音、缝隙和不同步。保留来源时不能宣称已做配音或母版增强。
8. 检查接缝前后至少 5 帧，必要时逐帧播放。源 24fps 进入 60fps 输出时明确是重复采样；不要承诺后段原生 60fps 动态。

### 参考片段后段不动的可验证做法

- 若采用码流复制，在参考片段真实可独立解码的关键帧处分段；重建区间可以延长到该点，但视觉修改边界单独记录。不要把任意小数秒裁切当作可无损接缝。
- 拼接前核对编码参数、尺寸、time base、帧数与时间戳。拼接后完整解码并密采样接缝，确认无缺帧、重复帧、瞬移或音画时钟变化；参数不兼容时改用明确披露的重编码方案。
- 声称“保留区间完全一致”时对相同帧范围、相同像素格式的解码数据做 hash 比较；保留音轨则单独比较音频 payload。整文件 hash 会因重封装改变，不能据此判断画面被改。
- SSIM 只辅助比较，不能替代上述一致性证据，也不能证明运动质量。只抽样检查时，报告必须写“采样帧未见异常”，不能写“全片无频闪”。

## 不把指标当审美结论

同时间截帧比较可检查字号和坐标；不同采样时刻、编码误差、抗锯齿差异会改变像素，不用单一差分阈值宣称像素级相同。已批准区间要求不动时，优先保留源实现/源帧，并验证未受本次改动影响。

字体正确、尺寸正确、解码成功只是技术条件。仍需看完整视频判断运动方向、停留时长、接管力度、连续性以及终态是否有意义。

## 表面、内容裁切与动态参考

载体几何、表面填充/阴影、内部内容揭示分别建模。去描边保留需要的白表面；阴影的 spread 也可能模拟描边。文字 reveal 通常只裁内部，不能让父级 clipPath 意外抹掉整块表面与阴影；有意的整块遮挡仍可保留。逐个检查入场、最大变化、交接和退场。

H3 来源与跨片对象状态按 [动态交接](h3-handoff.md) 登记。同终态不等于同过程，必须比较中间层级、内部运动、速度变化和焦点接力；下一场复用的冻结状态与真实当前尾帧一起验证。
