# 设备镜头、内容接力与统一质感

用于设备或页面过于静态、放大后失衡、模块提前出完、相邻动作忽快忽慢，或用户要求参考已认可产品讲解质感的任务。它是可选的构思和验收方法，不是新增已批准组件，也不是每期必用的电脑开头。准确场景实现或有限返修仍以本次 preserve/change 为准。

## 1. 设备是阅读空间，不只是装饰外壳

- 需要交代操作环境时，先建立可辨认的设备全貌，再随口播推进到承担信息的屏幕区域；允许机身、底座或屏幕边缘自然出画。不要为了始终完整露出设备而把核心文字缩小，也不机械规定每段必须从全景开始。
- 同一设备内把三件事分开：舞台镜头的平移/缩放、设备外壳与屏幕槽位、屏幕内部的内容变化。相机推进不等于内容滚动，内容新增也不必带动整个电脑漂移。它们共用输出时钟，但分别对应语义 cue。
- 一个清楚的可选关系是“认出环境 → 靠近当前内容 → 内容内部展开或主次交换 → 结果留下”。口播没有的步骤不强加；从上一场已经建立的近景接入时，不退回全景重复介绍。
- 推进要改变观众能读到的内容或信息主次，而不是给整张静图加持续微缩放。页面特写可以通过定向平移、裁切和局部强调呈现不同内容，不必换更多截图。

## 2. 缩放围绕明确锚点，检查最终可见几何

### 设备屏幕连续接管全屏

当下一句话开始讲屏幕内部操作或结果时，可以从设备全貌推进到屏幕承担整个画面。推进过程中允许机身、支架自然出画；内部内容、外壳和屏幕裁切共用同一几何变换，不先隐藏电脑再硬切成一份无关的全屏录屏。

- 以屏幕的真实内容框作为目标，不能用含机身/底座的外框求倍率。同画幅时，屏幕局部框 `(sx, sy, sw, sh)` 到目标画布 `(W, H)` 可用 `s = W / sw = H / sh`，`tx = W/2 - (sx + sw/2)*s`，`ty = H/2 - (sy + sh/2)*s`；不同画幅先明确保留边缘或允许裁切的内容，不能拉伸填满。
- 从当前实际设备状态连续插值到目标状态；屏幕圆角、外壳露出与内容裁切协调变化。达到全屏后不留黑缝、残余支架或被截掉的功能标签；按用户要求保留有意义的窗口边缘。
- 尽量让同一内容节点完成交接。必须更换节点或使用保留视频时，绑定同一个媒体源时钟与裁切：交接两侧的源帧按输出时钟连续衔接，不能回到开头或跳到无关播放位置。设备推进与页面滚动分别绑定口播，不互相代替。
- 全屏建立后，让真实操作继续承担信息，不再无目的地放大整屏。返回设备全貌只在内容需要重新交代环境时使用；也可直接把屏幕结果接给下一模块。
- 验收设备全貌、推进中段、屏幕接近画幅边界、全屏首帧及紧接的操作，检查上下文、屏幕像素位置与音画时钟连续。使用混合保留片段时追溯实际源视频，不能把未被调用的同名函数当作入片证据。

### 焦点锚点与相对对齐

明确使用舞台中心、当前内容焦点或相邻对象基线中的哪一个锚点。中心推进应在全部中间帧保持该中心；偏轴推进只有在内容焦点需要时使用，不能因为新增模块就无理由侧偏。

以 top-left 为 transform origin 时，可由目标屏幕位置反推定位：

```text
x(t) = targetAnchorX(t) - localAnchorX * scale(t)
y(t) = targetAnchorY(t) - localAnchorY * scale(t)
bottomAlignedY(t) = targetBottom(t) - outerHeight * scale(t)
```

这是单层等比变换的几何关系，不是固定坐标模板。outerWidth/outerHeight 包含真实 border-box；嵌套 transform 应累计换算到屏幕坐标。最终 4K 缩放只换算一次。

- 手机与旁边卡片的视觉分量、底边或中心分别核对；不能只提高 scale 而留下错误的 top。放大后同时检查标题、内部留白、字幕安全区及角标遮挡。
- 比较文字与 Logo 组合的可见宽度、同排模块的阅读基线，而非透明图片外框；不是每个标题都必须强制同宽。
- 外层承载阴影，内层裁切内容；屏幕裁切不能吞掉设备表面，设备放大不能使内文挤变形。字体、字重、圆角、边框和阴影按同一材质角色保持连续，允许设备壳、白纸和黑卡有不同材质。

## 3. 用口播决定内容接力，用运动包络决定速度

在已有 motionEvents 中写清“哪句话触发哪个对象、何时可读、稳定到何时、接下来谁接管”。SRT 定位、录音校准；不另建第二套时间表。

- 枚举几个对象时，通常逐个进入或逐个从上下文中接管焦点；不要先全部亮出再空等口播。若讲的是整体概览或对比，可以同时建立，但后续应有清楚的注意力顺序。
- 先建立当前要读的文字，再按语义叠加白/暗蒙版或结论；不能一开始遮住正文，也不能一边朗读一边把阅读区移走。
- 区分“动作完成后的阅读停留”和“动作本身一直慢慢滑”。同类换卡保持相近的移动时长、距离感和收束力度；空余口播时间用于结果可读，不把最后一次移动拉长填满。
- 快节奏来自去掉空等、及时换焦点和有信息的镜头变化，不是全片倍速、持续缩放或强行固定切镜频率。开头尽早建立相关反应，必要的阅读停留保留。
- 一个语义时刻优先一个主动作，辅助动作让位。新内容入场、旧对象缩小、镜头推进都存在时，安排先后或共享有因果的进度，避免互相抵消。

## 4. 绕行、合并和收回都要完成空间让位

环绕类参考不能只复制最终外框。源动作要求“主体先缩小，再绕行”时，缩小外壳及内部内容为同一组，围绕同一中心让出空间，再开始外圈动作。路径和跟随标记共用几何与进度；检查一整圈的轨迹、文字/胶囊边界及阴影间隙，不只看起点和终点。

合并或收回时，连线与对象共用明确的结束窗口。线条不晚于其所连接对象消失而悬空拖尾；进度为零的圆头描边不能留下孤立点。具体边界实现和逐帧检查见 [渲染异常](render-failure-checks.md)。有语义的项目符号、光标或运动标记不因“去黑点”全局删除。

## 5. 统一质感，不统一成一种效果

- 统一字体角色、对齐逻辑、对比和材质连续性；通过全景/特写、内部内容变化、开放文字、材料展开、主次交换和黑白对比增加表现。不是用同一胶囊、白卡或同一进场复制整片。
- 真实截图负责产品身份、操作或结果证据；关系和职责解释可以用准确文字与原生模块。品牌要求“提到产品有对应画面”不等于全程悬挂 Logo，也不等于每句话必须塞截图。示意模块不能冒充真实完成的操作。
- 图片按内容需要选择，数量不追求用齐。真实内容过密时取有来源的可读片段、推进至相关区域；避免用空灰线代替观众需要读到的记录，也不把整份密集原文全塞在小设备里。
- 毛玻璃用于保留上下文的重点强调，不是默认转场或万能结尾。中短篇连续讲解可先把它作为 1–2 个关键时刻的稀疏候选，再按当前片长和用户要求判断；不是硬配额，更不要求每片必须使用。持续同一蒙版下的内容接力是一段强调，不按句数反复开关。
- 正式品牌角标与产品内容层分开。启用规则和深浅底资产继续按 [角标规范](corner-branding.md)；不随设备镜头一起放大，也不因中央黑卡就误判右上区域为黑底。

## 6. 怎样检查这套方法是否真的成立

提示词短语与图片 ROI 的焦点测量、连续特写、稳定阅读和返回检查见 [提示词聚焦与图片局部特写](prompt-and-detail-camera.md)。这些检查和下面的设备状态共用现有代表镜头记录，不另建时间轴。

已有代表镜头预检中加入设备全貌、推进中段、最大特写、内容接管及退出；同时看相邻完整口播窗口。检查实际输出中的焦点位置、可见字高、设备比例、最长内容和运动包络。静帧证明布局，连续帧与正常速度播放证明节奏；两者不能互相替代。

用户认可整片后，将具体版本、hash、认可原话、有效组件调用与可参考时间窗留在本期记录。公共 Skill 只保留这些判断方法；单期源码提取为通用组件后须单独验证，不把源片认可自动转成适配组件或后续新片的认可。
