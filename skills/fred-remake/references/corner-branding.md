# 用户认可的横版视频角标

## 何时使用

机器参数见 [corner-branding.json](corner-branding.json)。正式素材从项目 skills/ 读取，不依赖历史 episode、临时 PNG 或全局缓存。

## 背景和呈现

- 白色、浅色底：fredtalk-ai-corner.png，深紫色 FredTalk 字。
- 黑色、深色底：fredtalk-ai-dark-transparent.png，白色 FredTalk 字。
- 保留各资产原有 AI 标识、黄色点缀和透明轮廓，不自行描边、改色或加底板。
- 按 Logo 所在区域的实际底色选择版本，切换跟随场景；不要只按整帧平均亮度切换，避免频闪。黑白转场中逐帧检查可读性。
- Logo 固定在最终画布右上角的独立层，不随正文缩放、摄像机或卡片运动；有复杂媒体背景或遮挡时按当前画面处理，不能默默移动批准位置。

## 精确几何与缩放

以下值来自用户认可的效果，单位是输出画布像素；不是浏览器 CSS 像素或设备像素比。

| 版本 | 4K 目标框 x,y,w,h | 1080p 目标框 x,y,w,h |
|---|---|---|
| 白底深色字，完整原图 | 3099,72,691,170 | 1549.5,36,345.5,85 |
| 黑底浅色字，先裁透明边 | 3109,82,670,150 | 1554.5,41,335,75 |

黑底资产先在原图坐标裁切 x=295,y=184,w=1528,h=341，再放进目标框。裁切坐标不随输出分辨率缩放。白底完整原图包含透明边距，因此两版图片框不同，但可见字形对齐：4K 可见宽约 670、高约 150、顶部约 82、右侧约 61。不要把图片外框误当成可见轮廓。

16:9 输出统一取 s=目标宽/3840=目标高/2160，对目标框仅乘一次 s。Remotion 若已在 1080p 逻辑舞台整体放大到 4K，就使用表中 1080p 值，不能再给角标乘 2。DOM 可保留小数，栅格工具仅在最终定位时取整。不要重新使用 GSAP case-brand 的 top40/right40/height52 来替代本批准值，也不要取此前测试尺寸的平均数。其他画幅没有继承本横版的几何认可，需根据当前画幅另行校对。

## 使用与验收

1. 从 JSON 读取目标框及资产 hash，核对素材来源；替换素材时重新测 alpha 可见边界，不能直接复用 PNG 外框。
2. 制作合同记录本规范 id、输出尺寸、缩放发生在哪一层、各场景的背景版本及实际隐藏区间。源视频播放时确认新增角标层确实关闭；已有 Logo 不再重复叠加。
3. 检查浅底、深底、切换帧和运动包络；确认 Logo 不裁切、不压住关键内容，两版大小位置没有跳动。
4. 批准的是角标规范，不能据此声称新一期全片已获认可；现有生产/QC 门禁照常执行。用户只要 3 秒测试时只交测试，不扩展为全片修改。

单期视频、抽帧和批准原话仍留在 episode 制作目录；公共 Skill 仅保存通用规范及既有公共资产引用。
