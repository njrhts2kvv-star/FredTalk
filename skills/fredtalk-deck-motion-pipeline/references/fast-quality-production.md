# 快速达到稳定质量的讲解视频制作

目标是减少重做，不是减少必要验收。先解决观众“现在看什么、发生了什么、与前一句有什么关系”，再选择载体和动作。本文是执行检查入口；细则仍由相应参考负责，不创建第二套页序、素材或批准事实源。

## 1. 开工先消除四种歧义

在已有 Manifest / motion brief 中明确：

- **交付类型**：Deck 接入、独立横版/竖版视频或局部替换；标题、角标、字幕、声音分别按本次要求设置。无烧录字幕不等于没有字幕安全区；按用户后续剪辑需要记录。
- **当前基线**：最新录音/SRT、用户实际看过的版本、当前反馈范围。新指令覆盖旧计划；历史合同/receipt 不改写，当前入口指向最新范围与批准证据。
- **保留与变化**：将意见绑定段内时间、全局帧、语义事件和对象。说“右边太空”先检查载体宽度与内容分量；说“没居中”先确认是文字组、同排模块或设备之间的相对对齐，不能全片改成居中。
- **每次变化的原因**：原状态 → 哪个对象怎样变化 → 什么保留 → 下一句接什么。没有内容责任的灰条、装饰线、空卡、循环动作不进入实现。

用已有修订清单登记 `sourceVersion / segmentLocalTime / globalFrameRange / object / preserve / change / reviewWindow`；同类问题在本次影响范围一起排查，保护已认可区间。

## 2. 选择素材，按缺口调用 H3

| 需要解决的问题 | 优先来源 | 使用边界 |
|---|---|---|
| 已提供片头或认可转场 | 原视频或准确源实现 | 保留指定动作；核对音轨、帧率与回接，不擅自重做 |
| 操作入口、软件状态、真实网页内容 | 当前录屏/截图 | 是证据；裁掉无关区域、删减浏览过程，关键操作保持可读 |
| 精确条款、输入、数字与改文案 | Remotion＋真实文字 | 可编辑、可测量，避免生成文字承担事实证明 |
| 尚无可靠实现的空间转变、因果动作 | 少量 H3 动态参考 | 先生成高风险动作，检查中间状态，再决定保留媒体或代码重建 |
| 已有合适设备、分支、网格、聚焦等动作 | 认可库实际视频＋准确源码 | 按语义提取，不继承旧文案、空白停顿和整片布局 |
| 判断、制止、指向或收束 | 已授权人物动作 | 从有效动作开始合成，按可见轮廓安排大小与文字关系 |

H3 数量由动作缺口决定，不设每期配额、不强制每句生成。UI准确、但运动不确定时用 H3 探索动作；只有字号/对齐/裁切问题时优先局部代码修复。模型文本能力可以用于简短信息设计，但结果中的文案与产品证据仍需核验。

在已有素材清单区分 `direct-footage / real-evidence / motion-reference / appearance-reference / repair-evidence`，同一文件可以有多个明确角色。记录源文件/hash、派生文件/hash、入出点、crop、速度、停帧和输出尺寸。只有实际提交记录里的引用才算送入 H3；本地看过截图不等于模型收到截图。任务成功、下载成功、用于参考、直接入片和用户认可分开记录。

录屏容器围绕有效内容建立：白底可配白表面与柔影，黑底可配暗色载体，允许直接全幅。不要强行全片统一白卡；低分辨率素材须在实际输出中读得清，不为精致而缩成装饰。联系人、仓库或操作对象等真实信息不得由灰线假UI替代。

## 3. 批量铺开前看这些代表状态

先内部诊断本次实际存在的高风险画面，通常选开头一段，再加中后段不同载体的短窗口；不要只用开头样片证明后续全部形式成立。已有完整认可基线的局部返修将设计诊断与方向复核限定在受影响窗口及邻接状态，不重新发起整期方向讨论；最终交付仍做适用的全帧检查、保护范围回归和接缝检查。

| 检查 | 要看到什么 | 不可用什么代替 |
|---|---|---|
| 字体与层级 | 同一信息模块默认主/辅两档字号；关键标签、胶囊和结论真实加载 Semibold 600；密集原文可用 Medium 500；同职责同字重 | 只检查CSS出现600，或一张小卡继承400再塞四档字号 |
| 空间与对齐 | 在最终缩放比例下检查最长文字、内边距、同排中心/基线及视觉分量；可以大字靠左 | “所有地方必须居中”、补空卡、无意义横线 |
| 文档滚动 | 明确完整扫描后解释，或边滚边讲；测内容真实高度，完整扫描时最后一条进入视口且顺序不漏 | 用固定偏移猜已滚完，或解释中突然跳回文档 |
| 毛玻璃强调 | 在已成立的原场景上叠加结论时，背景位置/尺度保持，白或暗色半透明层＋真实模糊，前景清晰；多个结论共用同一蒙版节点 | 实心白幕、每句话卸载蒙版、为加前景擅自移动电脑 |
| 主次交换 | 主、次载体在讲解责任变化时共用连续进度（如主任务缩小、侧边任务放大），尺寸/位置连续，文字可读 | 多段短曲线重置、压字、无职责的左右漂移 |
| 人物 | 入场即进入有意义动作；手势对准口播，结尾保持/退出合理 | 从素材frame1机械播放、低头等待、缩得很小再补几行字 |
| 接缝 | 上段尾态 → 下段首态 → 下一动作都有因果；统一帧/音频时钟 | 只看末帧和首帧相似，不看接下来半秒 |
| 完整提示词 | 原文完整；口播枚举分别高亮；真实字符框驱动近景；载体与内文共用变换 | 用关键词摘要代替全文、只划一条看不清的线、同时强调尚未说到的词 |
| 图片特写 | 原图先可辨认；ROI 对应口播及正确一侧；同轮几何统一；连线随主图位置变化 | 整图重复放进大白卡、标签代替证据、静态阅读区间持续上漂 |
| 屏幕接管全屏 | 屏幕内容框连续对齐画布，圆角/外壳/播放时钟共同交接 | 设备突然消失、切换节点从第零帧重新播放、模型或功能名称被裁掉 |

“两档”限制的是一个信息模块的层级，不是整片只许两个字号。数字、长原文或必要的第三角色可按内容说明例外。节奏随口播的信息变化建立，不把“约两秒有一次变化”硬编码为切镜频率；适当阅读停留和已认可系列同构保留。

毛玻璃、表面与内容组件见 [内容与运动组件](../../fred-remake/references/content-motion-components.md)，人物见 [动作规划](../../fred-remake/references/character-motion-planning.md)。用实际渲染/DOM结果核对字重、可见尺寸与bbox；合同里重复一段宽泛字号描述不构成执行证据。

涉及设备全貌到屏幕特写、内容逐项接管或相邻镜头速度失衡时，使用 [设备镜头与内容接力](../../fred-remake/references/device-camera-rhythm.md)。将这些状态纳入已有代表镜头预检；复用锚点、层次和节奏判断，不把单期设备布局或特效数量固化为模板。

提示词字符测量、单处/多处特写、主次交换和镜头停稳的细则统一见 [提示词聚焦与图片局部特写](../../fred-remake/references/prompt-and-detail-camera.md)。检查完整语义窗口及实际输出尺寸，不能用静帧整齐或整屏解码代替焦点与节奏检查。

## 4. 让每轮检查有明确成本

1. 在动效实现前完成现有 direction/motion 门禁；已有码工程先核对真实版本与授权，不用事后PASS追认早先动作。
2. 先typecheck/构建与关键状态图，再以原生输出帧率渲染短窗口，覆盖进入、主动作、交接和退出。静态截图只判断排版，不能证明动态顺畅。
3. 批量实现后看完整1080样片的内容覆盖和节奏。全片认可后，有限返修且明确直出使用 [正式返修分支](preflight-stage-gates.md)，不再次机械索要用户确认。
4. 冻结源码、合同、字体及媒体依赖，再一次性渲染受影响交付段。源快照隔离时，已完成且不受影响的段可保留；共用构建仍运行时先停或等它完成，不能边改边渲染。
5. 从同一全局时间轴按整数帧切段；旁白按对应采样范围处理。先校验文件完整封装，再检查全帧候选、音画时机、保留区域和两侧接缝。重新封装后更新hash与相应QC。
6. 渲染重试只记录观察到的错误与恢复证据；降低并发或增大timeout后成功不证明OOM/GPU根因，也不是跨期固定最优参数。主动管理browser/bundle资源生命周期，避免完成后残留进程。

通用容器审计沿用 `fred-remake/scripts/media-audit.mjs`；全帧候选审看按 [渲染异常规范](../../fred-remake/references/render-failure-checks.md)。结构门禁、技术检测、实际视觉自检和用户认可各自有证据；字段齐全不能代替观看质量。

## 5. 只沉淀跨期成立的内容

单期全文、最终构图、时间码、H3结果、用户截图、过程复盘和当前批准留在episode。公共Skill保存：素材选择方法、组件职责、可参数化适配实现、检验工具与准确批准语义。新适配组件通过状态/构建测试不等于用户视觉认可；原版媒体及源码不被覆盖。
