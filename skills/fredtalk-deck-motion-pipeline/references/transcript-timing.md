# 逐字稿与时间轴

时间事实源：正式录音的 forced alignment/ASR word timestamps → 人工修正 → 逐字稿估算。未录音时按语义单元、标点和 Fred 历史语速估算，并标记 `timingSource: estimated`。

标记主语首次出现、关键词、连接词、停顿和结论。`还要` 是追加，`然后` 是顺序，`但` 是转折，`所以` 是结果，`不是/而是` 是纠正，`最后` 是收束。默认顺序出现，只有口播明确“同时”才并行。

Cue 示例：`{"beatId":"b12","text":"先自己判断","startMs":820,"endMs":1830,"event":"establish","screenTarget":"judgment"}`。动作起点贴近词语被说到的时刻，可为认知预备提前 2–4 帧，但不能提前泄露结论。普通入场可从锚点后 0.28–0.50 秒完成起步校准；末帧停留按阅读、录音及下一场承接确定，不统一套固定秒数。

前 4–5 秒空白通常因为只绑定句中关键词。若首个正式锚点晚于 0.8 秒，从逐字稿已经说出的主语、对象或问题建立前置载体，再在后续锚点变化；不要新增无依据文案或机械增加无责任页面。

## 关键含义覆盖与解释推进

时间对齐不能代替内容覆盖。逐个检查核心判断、因果关系、限制条件及观众收益，在已有 beat 记录中标明由哪句上屏文字或哪次可见变化承担；支撑说明可仅保留口播，无需逐句抄字幕。概括必须保留主语、关系及影响结论的限定，不能用较好排版的次要短句替代主要观点。

当口播从术语走向解释、从前提走向结论，检查画面是否也推进了理解。可保持同一主题对象，通过问题、通俗定义、选中、展开或例子逐步补充含义；仅在对应语义已出现时触发，不机械按固定秒数换字。阅读、思考、真实操作或已有参考需要稳定画面时允许停留，不把“没有运动”直接判为失败。
