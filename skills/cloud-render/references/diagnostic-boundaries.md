# 渲染故障：先定位层，再修实际链路

只在对应症状出现或维护渲染器时读；沿用本期日志和QC，不增加一套交付流程。

| 症状 | 核对方法与边界 |
| --- | --- |
| 配了多个浏览器却未按预期复用 | `openBrowser`返回值通过准确的`puppeteerInstance`传给`selectComposition`与各worker的`renderMedia`；核对实际浏览器主进程和页数，不能用job数字证明拓扑。`pupeteerInstance`拼写错误会使该传参失效，但不能据此认定所有白帧同一根因 |
| `EPIPE`、取帧失败或偶发白帧 | 先保留最小复现及源时间，区分源解码、媒体时钟、截图合成与编码层；一次改一个变量。换编码、线程或并发后仍失败就记录反证，不反复猜GPU。分段速度可使用固定源起点与明确局部时钟验证，是否解决以当前真实素材为准 |
| 动态检查不通过 | 先看采样能力、有效区间和阈值；N个样本最多N−1次相邻差异。小区域变化用cue/ROI与正常速度播放补查；采样通过不保证美观，配置失败不证明静止画面不合适 |
| 有音轨却缺尾部 | 对比完整混音与最终MP4，检查封装命令、起点和尾部波形。本链路用完整外置音轨一次合成及明确目标时长，避免最终封装的`-frames:v`提前结束音频；不只检查stream存在 |
| 快照/素材hash报错 | 核对实际运行入口和依赖闭包，排除清单自身及已停用文件；真正缺失资源仍需补齐。源在运行中变化就另建快照，不能修改hash冒用旧QC |
| 配置、依赖预检或共享实例状态不符 | job、launcher、renderer和实际日志一起核对，保留当前已验证后端，允许1×1诊断。无关可选模型缺失如实记录，不能把全库警告当成本片阻塞；关机前按最新要求核对任务归属及远端活动进程 |

已有参数/源码测试：`node skills/cloud-render/scripts/test-render-options.mjs`与`node skills/cloud-render/scripts/test-render-browser-binding.mjs`。后者用严格API替身执行实际launcher，验证实例绑定、分块覆盖、清理及音频参数；它不启动真实浏览器，不证明当前云环境或画面已经通过。

真实媒体复验使用本期获授权素材：选择能重现问题的短区间、最长文字/模糊及受影响接缝，完成后保留环境版本、命令、输出hash和实际观察。只扩查尚未解决的风险，不把单期倍速、并发、gap帧数或失败猜测变成默认限制。

## 长任务工作集与恢复

Chrome提示memory/disk不等于已经证实系统OOM或磁盘耗尽。分别核对实际错误、guard的stopReason/exitCode、可用内存变化、磁盘/临时目录容量和远端进程；护栏终止与内核OOM也分别记录，不能从同一句报错推断唯一根因。

视频密集长片的短试通过不能证明全片工作集稳定。出现持续增长或护栏触发时，在保住帧率、分辨率、JPEG/编码质量和时钟的前提下，评估较短批次、每批结束释放浏览器/媒体缓存、限制实际支持的缓存及避免重叠编码。先核对版本与参数支持，记录真实峰值/护栏结果；本期批长、缓存数值和4×2只是已用配置，不升级成全局最优。

恢复采用唯一冻结快照与完成分块清单，先证实旧块完整性与依赖相容再复用，失败/不完整块重出，最后仍校验完整文件。浏览器进程释放不代表云实例已关机；下载校验完成后按最新电源授权及活动任务核对平台状态。
