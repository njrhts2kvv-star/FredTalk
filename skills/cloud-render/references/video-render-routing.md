# 含视频场景：选处理路径与控制缓存

在含录屏/视频的任务开始渲染前读取。先保持当前画面和真实音频时钟，再选择成本合适的执行路径；不要为了使用某工具改分镜。以下由实际对照形成执行偏好，不是所有视频的固定模板或自动路由功能。

## 按片段选择

| 当前片段 | 优先做法 | 何时换路径 |
| --- | --- | --- |
| 全屏录屏、固定裁切、停留、固定角标，或可准确表达的聚焦蒙版 | 优先评估 FFmpeg 直接解码、滤镜合成和编码 | 不能保持运动、文字清晰度、透明/模糊或时序时继续 Remotion |
| 设备进场、复杂镜头、文字/多对象关系动画 | 沿用当前已验证的 Remotion 方案 | 测量显示视频取帧是瓶颈时再试局部源帧缓存 |
| 短视频反复定位/冻结、同素材反复返修且取帧昂贵 | 可按实际使用的源帧预解码，并在 Remotion 按时间映射读取 | 准备成本或容量不划算时，改为直接解码或更小片段 |
| 长录屏或混合场景 | 按实际使用区间拆分；简单部分 FFmpeg，复杂部分 Remotion | 保持全局时钟与接缝，不把复杂动画简化成普通播放来报提速 |

FFmpeg 路线仍走本期相同素材/分镜合同和适用交付检查。已有稳定实现、只做有限修改时不为小幅收益重写整段。首次出现实质不同的媒体/效果组合时，用覆盖当前风险的短区间对照；已验证且输入条件相同不每次重跑全部组合。记录路径、范围、选择原因及证据到已有任务记录，不新增审批。

## FFmpeg 执行要点

- 冻结源媒体 hash、输出帧范围、源时间映射和音轨起点。输出帧率、trim、变速、冻结与源PTS逐项对应；VFR按时间戳取帧，不直接套用恒定帧率帧号。静止阅读是有目的停留，不自动补无意义动作。
- 静态蒙版/Logo可只解码一次再循环使用；这与把整个源视频展开为图片不同。动态蒙版、透明度、圆角、层叠顺序、角标位置和裁切保留原效果。FFmpeg整数裁切与CSS小数几何可能不同，检查细字和边缘，不宣称逐像素相同。
- 使用 `-nostdin`。编码器、preset、CRF、像素格式、fps和尺寸与对照一致；硬件编码、缩放或色彩链路改变时单列并重新验证，不能把它们混入单变量提速结论。
- 含音频的最终封装采用明确时长，并验证实际视频帧数和音频尾部；不要依赖 `-frames:v` 结束整个复用音视频管线，它可能提前截断音轨。可以先输出精确帧数的纯视频，再一次性合成完整混音；将两步耗时都计入。
- 混合输出只在流参数兼容时copy拼接；按每块准确帧数与fps确定时长，检查边界PTS和连续播放，完整音轨最后合成一次。已有口播、音乐、SFX不能遗漏。

## 源帧缓存有容量上限

源帧磁盘缓存、解码器内存缓存与操作系统页缓存分别记录，不能用磁盘PNG体积当作内存占用。FFmpeg直接处理仍有解码/滤镜缓冲，不承诺零内存或任意长片恒定资源。

1. 先从时间映射求实际用到的源区间/独立帧，冻结帧只存一次；只加解码定位/过渡所需的余量，不把整条源素材默认全部抽帧。
2. 取少量代表源帧测平均大小，估算 `独立源帧数 × 平均字节数`，再计临时文件、分块输出、最终视频和安全余量。记录当前磁盘/内存、缓存预算及同时在用的片段数。旧样本的每分钟容量不是通用常数。
3. 长片按预算分批预取、渲染和复用，避免整片展开。只清理当前任务明确标记为可重建、已不被活动任务引用的临时缓存；无法满足预算时改直接处理或缩小工作集，不默默降低质量。
4. 缓存绑定源hash、源帧号/PTS、提取工具版本、像素/色彩格式、裁切和缩放参数；映射、素材或提取参数改变时相应失效。可共享不可变实体，不为4个浏览器复制4份磁盘缓存。
5. 把首次抽帧准备时间计入冷启动总耗时；热缓存返修单列。缓存复用与失效细则见[缓存与局部重渲](cache-reuse.md)。

## 并发与组件选择

4×2、8×2指独立浏览器×每浏览器页面数，不适用于FFmpeg线程数。沿用本工程已验证配置；未验证的媒体密集场景可从4×2起步，按实际资源和同区间试样判断是否值得8×2。纯动画可沿用已验证8×2。两者都不是固定最优值，正常返修不必重复压测。

不要只因为较新的视频组件短测更快就替换生产组件。升级/切换在隔离环境按准确版本测试，覆盖挂载切换、Freeze、Sequence边界、源时间跳变和尾帧；检查最终MP4每帧技术异常及关键媒体ROI。出现空白媒体，即使文件解码、帧数和音轨都通过也不得采用该方案。历史单版本异常不是永久禁用整个组件，也不能臆定内部根因。

## 判断一次优化是否成立

- 同内容、同范围、同质量、同机器，基准任务依次运行，避免竞争资源；报告真实后端。GPU型号不证明解码/滤镜/编码用了GPU。
- 分列上传、依赖准备、抽帧、渲染与编码、合并音频、校验、下载；冷/热缓存分开，单次与复测分开。不要将并行worker时间相加，也不要把5秒局部外推成整段或长片实测。
- 对最终文件检查hash、准确帧数/尺寸/fps/时长、全解码、PTS、音频起止/尾部及与master对应；检查媒体空白候选、切换与冻结边界、蒙版中间态、细字、角标和接缝。
- SSIM用于找差异与最差帧，不等于美术评分；技术通过、内部画面检查和用户认可分别报告。失败版保留证据，修复后重验，修复耗时纳入可交付结果。

## 执行能力边界

当前公共 `render.mjs` 不会自动选择FFmpeg或生成源帧缓存。Agent按上述逻辑在本期隔离目录编排并验证；不得添加未实现的job字段冒充自动功能。单期命令、媒体、准确数据和失败日志留在本期，历史对照入口见[实测记录](benchmarks.md)。不把测试CRF或服务器地址变为正式默认值。
