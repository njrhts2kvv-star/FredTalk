# 减少重复渲染与缓存复用

在保持原始画质、帧率、布局、动作、时序和音频的前提下，优先减少重复工作。首次制作主要受出帧成本影响；同一期返修和重复出片更可能受益。记录实际耗时，不预设加速倍数。

## 执行状态

当前 `scripts/render.mjs` 每次 bundle 一次并重渲所选范围内全部分块，尚无自动分块缓存、缓存键或失效检测。以下是后续执行与实现的规则，不代表自动功能已经落地。不得只向 `render-job.json` 添加脚本不识别的字段就声称启用缓存。局部渲染与复用需要在本期隔离任务中明确编排；没有实现并验证复用路径时，继续正常渲染并报告未命中原因。

含视频时先按[视频处理选型与容量控制](video-render-routing.md)决定是否需要源帧缓存；不要把环境/分块复用等同于整片抽帧。

## 1. 局部修改只重渲受影响分块

- 先对比上一份通过内部校验的快照与当前快照，记录改动文件、素材、props、全局帧区间和影响判断，保存在本期已有任务记录中。内部校验通过与 Fred 看过认可分别记录。
- 保留基线的准确分块边界与全局帧坐标，重渲所有与受影响区间相交的完整分块；跨场景过渡、上游尾帧、下游首态、运动包络和前后依赖都计入影响范围。不能按口播句子或文件名直接判定范围。
- 复用证据至少包含：composition ID、绝对起止帧、全片时长/fps/尺寸、解析后的 props、该块完整传递依赖的源码/素材/字体 hash、锁文件及实际运行版本、Chrome/启动器/GL 与驱动环境、编码和图像参数，以及旧分块文件 SHA256 和校验结果。
- 整体快照 hash 变化后，仅在能证明某块完整依赖与上述配置未变时才复用该块；无法建立完整依赖范围就保守重渲，不能凭 mtime、同名文件或存在旧 MP4 命中。
- 共享组件、全局 CSS、字体、布局参数、依赖版本或渲染环境变化时重新判断所有使用者；无法定位使用者则全片失效。fps/尺寸/全局时间基准变化通常使全片失效；插删时长至少使位移后的分块失效。不得通过重置帧号或挪用旧片掩盖时序变化。
- 仅外置音轨变化、画面及其音频驱动数据均未变时，可以复用全部视频分块并重新合成完整音轨；波形、字幕或节拍依赖音频时，对应画面也必须失效。
- 只复用通过 SHA256 核验且与新块流参数兼容的视频流分块。在新的唯一输出目录合并，保留原任务不覆盖；仍先去分块音轨，再无损拼接，最后一次性合成完整音频。
- 新最终文件仍执行完整帧数、PTS、解码、音频校验；视觉检查覆盖修改区间、新旧接缝及保留范围。缓存不跳过现有 direction/motion/render/formal 门禁，也不赋予新版本用户认可身份。

## 2. 复用匹配的依赖、浏览器、字体和素材

- 先核对已授权云端环境，匹配时复用现有安装，避免每个任务都下载浏览器或重装依赖。环境缓存是可重建副本，canonical source 仍为项目实体依赖。
- 依赖缓存绑定 package.json、锁文件 hash、安装选项、包管理器版本、Node 版本、OS/架构和实际包版本。只共享安装完成并验证的不可变环境，不在活动任务使用的 node_modules 内执行安装；不匹配时新建隔离环境，按锁文件安装。
- 浏览器绑定匹配 Remotion 的实际 Chrome 版本/二进制 hash、OS/架构及启动配置；字体绑定文件 hash、实际字重与字体配置。首次复用环境仍验证字体加载和实际后端；只有选用GPU才验证硬件路径，已验证的软件后端同样可复用。
- 素材按内容 hash 复用已上传实体文件，上传缺失或变化部分，组装每次唯一完整快照并验证清单；不因复用省略当前快照的完整性核验。新上传目的地仍遵循现有授权。
- 缓存写入先落临时目录，完整核验后发布；活动任务只读。不原地修改共享缓存或冻结硬链接，不清理其他任务正在使用的环境。
- bundle 只在完整构建输入、配置和工具链均相同时复用；一旦源码变化重新 bundle，不能只凭锁文件相同复用旧 bundle。

## 3. 缓存不随帧变化的昂贵计算

- 先测量具体耗时。优先预计算确定性的数据解析、几何数据、路径采样、静态布局输入和素材元数据；随帧变化的动画值仍按当前全局帧计算。
- 可用模块级只读数据或依赖完整的 useMemo，明确其缓存仅限当前进程/页面/组件生命周期；多个浏览器之间不会自动共享，也不能假定跨次渲染保留。
- 跨任务预计算产物绑定输入、算法源码、参数和工具版本 hash，在快照中作为可追溯输入；涉及尺寸、props、字体或音频的数据必须包含相应依赖。缺失、变化或无法验证就重算。
- 字体相关测量必须等待实际字体加载，不缓存回退字体结果。避免共享可变对象、未固定的随机数、当前时间或跨帧累积状态，以保持分块渲染确定性。
- 静态资源提前准备不等于批量转 WebP、降低分辨率或把动态模糊改成静态图片；任何表示方式改变都必须证明当前效果和运动包络保真，不能为了提速改掉已确认画面。

## 记录与验收

在已有任务结果或本期修订记录中列出：命中的环境/素材/计算缓存、复用与重渲的全局帧区间、对应 hash、失效原因和实际执行路径。分列上传、安装、bundle、浏览器准备、出帧及编码、合成、下载、校验耗时；冷启动与缓存命中运行分开统计。只有同内容同质量的实际对照才能报告节省时间，未测时写“预计减少重复工作，收益待测”。
